# Changelog

What changed between one tag and the next, not what changed between commits.
This file holds the release that has not been tagged yet;
[the releases page](https://github.com/nevindra/nilo/releases) holds the ones
that have, one page each. What was measured and what was got wrong on the way is
in [`docs/history.md`](./docs/history.md); what is coming is in
[`docs/todo.md`](./docs/todo.md), and what was refused or answered is in
[`docs/decided.md`](./docs/decided.md).

## Unreleased

### Breaking

- **The 400 or 422 for a body, a form or a query argument that did not fit gains a `fields` array**, one entry for each field that failed (`field`, `code`, `message`, `expected`), and a plain `Form(T)`, JSON body or `Query(T)` now reports every failed field in it and in `error` (`"3 fields did not fit: …"`), where it stopped at the first. A client or a test that compares those bodies byte for byte, or matches the whole `error` sentence of a request with several mistakes, changes; one that reads `error` and `status` is unaffected, and one field wrong is the sentence it was. A key the endpoint does not take is now one entry among the others, and a body with several of them names all. 404s, 500s, 401 challenges, a fail function's sentence and the answers before routing are byte-identical. An app that named its own shape with `app.failures` is not handed the list ([ADR 024](docs/adr/024-every-failure-answers-as-json.md), [ADR 034](docs/adr/034-a-binding-hands-its-failures-to-the-handler.md)).
- **`.min` and `.max` over an enum that sets `nilo_column` (a Postgres `ENUM`) are a compile error on the SQLite dialect**, because SQLite orders the column by the label's spelling and Postgres by the enum's declaration, so the same grouped Row named a different label on each with no error. Drop `nilo_column` from the enum so both store text, or read the first row with `.order` and `.limit = 1` ([ADR 181](docs/adr/181-the-marker-has-two-kinds-of-word.md)).
- **A `sql.Date` field refuses a column that does not arrive as `date` on a raw read inside a transaction and on a composed statement**, where an `int4` was read as a count of days since 2000. A domain over `date` still reads. Cast the column to `date` in the statement ([ADR 233](docs/adr/233-a-raw-statement-is-held-against-its-row-the-first-time-it-runs.md)).
- **`nilo_jwt` verifies ES384 (`EC` keys on `P-384`) and EdDSA (`OKP` keys on `Ed25519`, RFC 8037) beside RS256 and ES256**, and the key and its curve still pick the algorithm, never the token's `alg`. `Key.Material` has a third case, `.okp = .{ .crv, .x }`, so an exhaustive `switch` over `key.material` needs one more arm; an `OKP` key that used to be skipped is now read; `key.algorithm()` follows the curve and is `""` for one with no branch (P-521, Ed448), and a token whose key is on such a curve is `error.CurveNotSupported`. `jwt.curves` is `P-256`, `P-384` and `Ed25519` ([ADR 111](docs/adr/111-nilo-verifies-a-token-and-does-not-fetch-one.md)).

- **`config.Reason` has a fifth tag, `too_many`, and `config.Failure` gains `entry`, `capacity` and `group`**, for a list setting that names more entries than it has room for. A `switch` over `Reason` with no `else` needs an arm for it ([ADR 289](docs/adr/289-a-setting-can-be-a-list-and-a-group-can-be-switched-on-by-presence.md)).

- **`fail.InFlight.read_request` is now `request_ops`**, one pointer to a read function and an allocate function, so a long `fail` message can be kept in the request arena. Only code that sets it by hand, such as a test fake, changes ([ADR 286](docs/adr/286-a-handler-may-answer-in-several-typed-statuses.md)).

- **`c.bodyStream()` decodes a gzip request body instead of answering 415**, counting the decoded bytes against `max_bytes` (a body that inflates past it is a 413, one that does not decode is a 400, as for `c.body()`). The decoder's window, about 73 KB, comes from the request arena and only for a gzipped body. A route that read the compressed bytes itself names `"gzip"` in `nilo.bodyEncodings` to keep getting them raw. `nilo.Body`'s read errors gain `BadEncodedBody`, so a `switch` over them with no `else` needs that arm ([ADR 089](docs/adr/089-a-body-under-an-encoding-other-than-gzip-is-refused.md)).
- **`nilo.spawn` under a `testing.Client` or `testing.Wired` runs the work** on a runner the clients lend, where it answered `error.NoServer`. A test that expected `NoServer` from a handler's `spawn` while a client was alive now sees the work run; `client.settle()` waits for it, and the last client's `deinit` cuts off what has not returned. With no server and no client it is still `error.NoServer`, and `spawnLocal` is unchanged ([ADR 028](docs/adr/028-a-spawned-fiber-belongs-to-the-server.md)).
- **`nilo_fetch` adds to two exhaustive sets**: `Client.Error` has `InvalidUpload` and `BodyEncodingInvalid`, and `Exchange.Body` has `upload` (set only by `beginUpload`; `begin` refuses it). A `switch` over either with no `else` needs the arms ([ADR 292](docs/adr/292-a-fetch-build-can-read-a-gzip-answer.md), [ADR 293](docs/adr/293-a-request-body-can-be-sent-gzipped.md)).
- **A `build.zig` that copied the `dev` step from the guide puts `dev.addPassthruArgs()` after `dev.addDirectoryArg2(...)`**, as the guide now does: in the old order `zig build dev -- … -- <server args>` handed `nilo-dev` the binary as a server argument and it never started ([ADR 190](docs/adr/190-a-restart-on-save-watches-the-binary-not-the-sources.md)).

- **`compress.negotiate` takes a `have_zstd` argument between `have_br` and `have_gzip`, and `compress.Coding` has a `zstd` member**, so a call to the first and a `switch` over the second with no `else` change. In a `-Dzstd` build a `.zst` beside a compressible file is a sibling and a 404 under its own name, and a static tree holds a second compressed copy of each file; `.precompressed = false` and `compress_zstd = false` undo each ([ADR 273](docs/adr/273-a-file-a-build-compressed-is-served-as-the-coding-of-the-file-beside-it.md), [ADR 295](docs/adr/295-zstd-is-a-module-whose-contexts-are-the-callers-memory.md)).

### Added

- **`app.failures(T)` hands a shape of your own the fields that failed**: `nilo_failure(status, message, fields: []const nilo.FieldFailure)`, or `[]const E` where `E` declares `pub fn nilo_field(f: nilo.FieldFailure) E` to rename or drop keys, mapped once in the request arena; the two-parameter `nilo_failure` is unchanged, and a third parameter of another type, an `E` without `nilo_field`, or a `nilo_field` that can fail is a compile error ([ADR 024](docs/adr/024-every-failure-answers-as-json.md)).

- **`app.errors(.{ .{ error.EmailTaken, 409 }, .{ error.NoSuchOrder, 404, "no such order" } })` gives errors from code that does not know about HTTP a status once, for the whole App.** A handler that `try`s a service returning `error.EmailTaken` answers 409 with no `fail` call and no `catch`; the access log carries the same status; a 5xx never sends the error's name; the API document lists the statuses on routes whose inferred error set holds the error. A status outside 400 to 599 and an error listed twice are compile errors. An App that never calls it behaves as before, and a connection costs nothing more ([ADR 004](docs/adr/004-http-errors-via-fail-functions.md)).

- **A tagged union is a handler's body argument**: `fn create(condition: Condition)`, where `Condition` is a `union(enum)` carrying `nilo_json = .{ .tag = "signal" }` and its `jsonParse`, is read as the body (leaving the `jsonParse` line off, on the body or on a union inside one, is a compile error naming the line to add, not a 400 on the first request), answers the same named 400s as a union inside a struct, and is described as `oneOf` with a `discriminator`, so a handler no longer takes a `*Ctx` and calls `c.json` to keep the body in the API document. A union with no `.tag` is a compile error naming the type and the line to add. `Form`, `Query` and `Bound` still read a struct only, and say so. Nothing to change; no allocation is added to a route that does not take one ([ADR 016](docs/adr/016-the-api-description-comes-from-the-signatures.md)).

- **`/metrics` publishes the watchdog's catches, the tracer's drops and the process series**: `nilo_watchdog_caught_total`, `nilo_trace_spans_dropped_total` (only with `app.trace`), and on Linux `process_resident_memory_bytes`, `process_virtual_memory_bytes`, `process_open_fds`, `process_max_fds`, `process_start_time_seconds` and `process_cpu_seconds_total`, read from `/proc/self` when the page is scraped. Nothing on a request changes and nothing to change in a program ([ADR 079](docs/adr/079-the-route-table-is-the-registry.md)).

- **`nilo.Counter(L)`, `nilo.Gauge(L)` and `nilo.Histogram(L, opts)` are metrics of your own, declared as fields of a service and printed on `/metrics` once the service is provided**, with a label that is `void`, an exhaustive enum or a struct of them (`orders_total.inc(.paid)`), every series printing from the first scrape and `service="<type name>"` on each sample. Recording takes no lock and allocates nothing. `pub const nilo_metrics = .{ .{ "name_total", .counter, "Help.", reader } }` is the same for a module that cannot import `nilo_http`, and `cache.Store` (`nilo_cache_hits_total`, `_misses_`, `_evictions_`, `_expired_`) and `jwt.Keyring` (its memo's hits and misses) declare one. `listen()` now refuses (`error.MetricsRefused`) one name that is two different families, two services whose type names end alike sharing a name, and more than 1,024 series. `cache.Store.stats` takes `*const Store`. Nothing to change ([ADR 079](docs/adr/079-the-route-table-is-the-registry.md)).

- **`nilo.FieldCode` and `nilo.FieldFailure`**: the `code` of an entry in `fields` (`missing`, `not_that_type`, `not_one_of`, `too_many`, `unknown_field`, `rule`; the tag names are public API) and the entry itself, which `fail.current().?.fields()` reads inside a request. The OpenAPI `Failure` schema lists `fields` as optional, with `code` as that enum ([ADR 024](docs/adr/024-every-failure-answers-as-json.md)).

- **`/metrics` publishes `nilo_session_rejected_total`**: session cookies and Bearer tokens that were sent and failed to open, so a wrong `session_secret` after a deploy shows as a climb rather than as a quiet hour. An expired one and a request that sent none are not counted, and the series appears once the first is seen. Nothing to change ([ADR 033](docs/adr/033-a-session-is-sealed-into-the-cookie.md)).

- **A handler may return a `union(enum)` whose arms are each a `nilo.Status(code, T)`**: each arm answers with its own status and body type, and the API document lists one response per arm, so a 400 carrying `{"error":"…","offset":12}` beside a 200 list stays a typed return. Two arms with one status, an arm that is not a `Status`, and `?` around the union are compile errors ([ADR 286](docs/adr/286-a-handler-may-answer-in-several-typed-statuses.md)).

- **`cors.deciding(decide, options)` asks a function of yours whether an origin is allowed, on each request that carries one**, for an allowlist that changes while the server runs (per-project allowed domains kept in a database). `decide` takes up to two services and the origin, and returns `bool`; an `Origin` that is not a well-formed origin is treated as none and never reaches it; a service it names that is not provided is refused at `listen()` ([ADR 088](docs/adr/088-an-origin-is-a-fact-about-the-deployment.md)).

- **`nilo_config` reads a list and a group switched on by presence.** `config.List(T, max)` is one variable with commas in it (`ALLOWED_ORIGINS=a,b`), with room for `max` entries fixed while compiling and no allocation, and a `?Struct` field is a group of `<FIELD>_*` variables that is null until one of them is set to something, after which its required fields are required (`SMTP_HOST` set makes `SMTP_PORT` required) and a blank variable inside it reads as not set. Two settings that would read the same variable (a plain `smtp_host` beside the group `smtp`) are a compile error naming both ([ADR 289](docs/adr/289-a-setting-can-be-a-list-and-a-group-can-be-switched-on-by-presence.md)).

- **`.tls = .unverified` on one `nilo_fetch` call (`Call` or `Begin`) skips the certificate check**, for a health or uptime check of an endpoint on a self-signed or expired certificate. It is a field of the call only, never of a `Target` or `Settings`; its connection is pooled apart from verified ones, a redirect to another origin is verified again, no server name is sent, and an IPv6 literal is `error.UnverifiedNeedsHostName` ([ADR 290](docs/adr/290-a-call-can-skip-the-certificate-check-and-only-that-call.md)).

- **`Body.buffered(buffer)` is the request body as a buffered `std.Io.Reader` over a buffer you own**, for `std.json.Reader` and line-at-a-time parsers such as NDJSON; a zero-length buffer is `error.EmptyBuffer`, so size it from the parser, never from the request. `Body.explain(err)` is public: it turns that reader's `ReadFailed` back into `BodyTooLarge`, `BodyTruncated` or `BadChunk` and passes any other error (`StreamTooLong`, `EndOfStream`) through. `Body.reader` stays unbuffered.

- **A handler can ask whether its client is still there**: `c.presence()` answers `.here`, `.half_closed` or `.gone` (`nilo.Presence`), `c.gone()` is the yes/no, `c.sleepUnlessGone(ms)` is `nilo.sleep` that returns early with `.gone`, `events.sleep(ms)` does the same inside an event stream, and `nilo.gone()` answers it from code with no Ctx (a blocking worker). A FIN after a keep-alive request is `.gone`; a FIN after `Connection: close` or HTTP/1.0 is `.half_closed` (the client may still be waiting for its response); for Events a FIN is always `.gone`. On HTTP/2 and gRPC a RST_STREAM or a connection reset is `.gone`, and a GOAWAY is not. The route is not cancelled: a handler that never asks runs as before, and `error.ClientGone` (answer: none written, logged as 499) is there to return. Nothing to change ([ADR 287](docs/adr/287-a-handler-can-ask-whether-its-client-is-still-there.md)).

- **`Stream.abort()` and `Events.abort()` break a response off** so the client sees a failed transfer, never a short body that looks whole: HTTP/1.1 closes without the terminating chunk (or short of its `Content-Length`), HTTP/2 resets the stream with `INTERNAL_ERROR`. `return out.abort();` is the call site; it returns `error.StreamAborted`, which App does not log as a failure ([ADR 019](docs/adr/019-a-request-that-lasts-is-still-one-request.md)).
- **`nilo_fetch` reads a gzip answer in a build that asks for it**: `.fetch_gzip = true` on the dependency (or `nilo.app`, `-Dfetch_gzip` here). Every call then sends `Accept-Encoding: gzip, identity` and decodes an answer under `Content-Encoding: gzip` whatever was advertised, so a server that gzips regardless of `identity` no longer fails every call; `max_body` counts the decoded bytes, the footer's CRC-32 and length are checked, and a body that does not decode is `error.BodyEncodingInvalid`. A build without the flag links no flate (+16 bytes) and still answers `error.HttpContentEncodingUnsupported`. An `Exchange` begun by hand decodes only with `Begin.decode`. `fetch.testing.Canned.replyGzip` serves a gzipped answer ([ADR 292](docs/adr/292-a-fetch-build-can-read-a-gzip-answer.md)).
- **`nilo_fetch` sends a request body gzipped, and writes a chunked one.** `Call.encoding = fetch.gzip` (or `fetch.gzip.with(.{ .level = .fastest, .min_bytes = 512 })`) compresses a slice body, sends the compressed `Content-Length` and `Content-Encoding: gzip`, and sends it once more plain to a server that answers 415 without the coding in its `Accept-Encoding`; `Response.sent_encoding` says what went out. `Exchange.beginUpload` is a chunked body the caller writes a `flush` at a time, gzipped with a sync flush at each when asked; `Body.stream` keeps its mandatory length. A program that never names `fetch.gzip` links no compressor. `Canned` gains `requestEncoding()`, `requestBodyDecoded(gpa)` and `serveUpload()`, and `nilo_core` gains `core.deflate`, the in-place gzip start `http/compress.zig` had as `reset` ([ADR 293](docs/adr/293-a-request-body-can-be-sent-gzipped.md)).
- **The test client speaks gzip**: `nilo.testing.gzip(arena, bytes)` for a body sent under `Content-Encoding: gzip`, `answer.decoded(arena)` for an answer that came gzipped, and `answer.json` inflates one first; `bytes` and `text` still give the wire bytes.

- **`nilo_zstd`, the thirteenth module, and zstd across the server behind `.zstd = true` (`-Dzstd`).** libzstd 1.5.7 compiled `ReleaseFast` with no libc, every context in memory the caller gives it, one-shot and streaming in both directions, and `CompressorPool` and `DecompressorPool` for a context per thread. A build without the flag fetches and links nothing; one that asks pays +122,976 bytes to decode and +409,696 to encode, stripped `ReleaseFast` ([ADR 295](docs/adr/295-zstd-is-a-module-whose-contexts-are-the-callers-memory.md)). In that build:
  - **`app.compress` answers zstd to a client that asks**: the highest `q` wins and zstd wins a tie, so a browser's `gzip, deflate, br, zstd` gets it; `zstd;q=0` never does, and a zstd that cannot answer falls to gzip. One zstd compressor a thread beside gzip's, 1.3 MB mapped at the default `max_bytes`; `compress.Options.zstd = false` keeps gzip alone.
  - **`app.static` serves `app.js.zst` beside `app.js`** (br, then zstd, then gzip on a tie), decoded and compared with the file at load, and makes a level 12 copy of its own (`compress_zstd`, on by default), its window held to a megabyte so the load needs a context of at most 13 MB.
  - **A request body under `Content-Encoding: zstd` is decoded** for `c.body()`, `c.json`, a typed body, `Form(T)`, `c.bodyStream()` (counted against `max_bytes`; `bodyStreamWith(.{ .zstd_window_log_max })` caps the window, 23 by default) and a gRPC message under `grpc-encoding: zstd`. An announced size is checked against `max_body` before anything is allocated, a frame that announces none is decoded into at most `max_body + 1` bytes, and a checksum the frame carries is verified. The 415 names `zstd` in `Accept-Encoding` only in that build.
  - **`nilo_fetch` reads a zstd answer with `.fetch_zstd = true`** (or `nilo.app`, `-Dfetch_zstd` here; it implies `.zstd = true` and is independent of `.fetch_gzip`). Calls send `Accept-Encoding: zstd, gzip, identity` as the build allows (`fetch.accepted_encodings`) and decode an answer under `Content-Encoding: zstd` whatever was advertised, `max_body` counted on the decoded bytes; a bad, truncated or failed-checksum frame, or one asking for a window over 8 MB, is `error.BodyEncodingInvalid`. The decoder's context is on the heap, sized at the first read from the frame's header (112 KB for a small frame, at most 8.9 MB), and freed by `end`; the flag costs +92,128 bytes and a build without it is unchanged.
  - **`Call.encoding = fetch.zstd` sends a body in zstd**, and `Exchange.beginUpload(…, fetch.zstd)` flushes a block at each `flush`. Naming the constant is what links the encoder (+455,904 bytes). A coding's `Level` is `.fastest`, `.default`, `.best` or `.{ .exact = n }`. A server that answers 415 without `zstd` in its `Accept-Encoding` is sent the body once more plain. `fetch.testing.Canned.replyZstd` serves a zstd answer, and `requestBodyDecoded` undoes zstd as it does gzip.
  - **The test client speaks it**: `nilo.testing.zstd(arena, bytes)` for a body sent under `Content-Encoding: zstd` (a compile error naming the flag in a build without it), and `answer.decoded` and `answer.json` read a zstd answer.

### Changed

- **`nilo_fetch` sets `TCP_NODELAY` on every TCP connection it dials** (plain, TLS and through a proxy; not a unix socket), so a POST whose body is larger than the write buffer no longer waits 41 ms for the peer's delayed ACK on a pooled connection. Nothing for a user to change.

- **`cors.Origins.set` and `setSplit` refuse an origin with a space or a control byte in it** (`error.OriginNotAnOrigin`), which matched no browser's `Origin` and, echoed back, could not be written as a header. `setSplit` still trims the spaces around each entry ([ADR 088](docs/adr/088-an-origin-is-a-fact-about-the-deployment.md)).

- **A `nilo_s3` request waiting on a credential refresh stops at its route's deadline**, with `error.TimedOut`, or signs with the key it already holds if that is still good, while the refresh runs on to its own `fetch_timeout_ms` and is kept for the requests after it. Before, it waited out the whole fetch. Nothing to change ([ADR 105](docs/adr/105-a-route-can-say-how-long-it-has.md)).
- **CI runs `nilo_core`, `nilo_pw`, `nilo_jwt` and `nilo_proto`'s tests on Windows**, and Windows is now on record as supported for those four only; `config.Env`, `id.v7Now` and `nilo_cache`'s clock refuse it while compiling, and a server there runs under WSL2 ([`decided.md`](docs/decided.md)).
- **The `db.raw` first-run check says an outer-join column "may be NULL"**, and also flags a column read through an anti join (`LEFT JOIN … WHERE o.id IS NULL`), which is NULL on every row, including the `Right Anti` Postgres 16 and later write for it. A field it refuses over a `NOT NULL` key is fixed as before, with an optional field or a `coalesce` ([ADR 233](docs/adr/233-a-raw-statement-is-held-against-its-row-the-first-time-it-runs.md)).
- **A SQLite migration step that times out on a lock names `busy_timeout_ms`**, the setting that applied, where it named `.lock_timeout_ms` and 5000 ms ([ADR 240](docs/adr/240-a-migration-waits-five-seconds-for-a-table.md)).
- **`id.v7Now` keys made one after another on one thread sort in the order they were made, inside a millisecond too**: the 12 bits after the version hold a counter (RFC 9562 §6.2, method 1), so rows inserted in a loop and read back by id come out in insertion order. A burst that uses up the counter runs the key's timestamp a millisecond ahead rather than breaking the order. A `v7Now` key carries 12 fewer random bits, the order is per thread, and `id.v7(entropy, ms)` is unchanged. Nothing to change ([ADR 143](docs/adr/143-a-key-that-can-be-printed-and-a-key-that-can-be-made.md)).
- **`nilo_cache`'s shard lock spins on a read and yields its thread after 256 looks**, where it swapped on every look, and a write the shard refuses no longer takes the lock. Nothing to change ([ADR 109](docs/adr/109-a-cache-holds-its-bytes-under-a-lock-it-can-spin-on.md)).
- **A JSON string is checked for UTF-8 a 32-byte block at a time whatever it holds**, where the check went a byte at a time after the first byte over `0x7f`, so a response in Japanese, Chinese, Arabic or Russian no longer pays for it. Which byte strings count as text is unchanged, and a differential test against `std.unicode.utf8ValidateSlice` holds it. Nothing to change ([ADR 096](docs/adr/096-a-byte-that-is-not-text-is-not-a-string.md)).

- **A `fail` message longer than 240 bytes is kept whole inside a request**, in the request arena up to 16 KiB, so a 400 that lists every problem reaches the client whole. Outside a request (work registered with `app.before`) it is still cut at 240 bytes, and a gRPC call is told the first KiB, since `grpc-message` is a header ([ADR 286](docs/adr/286-a-handler-may-answer-in-several-typed-statuses.md)).

- **`db.exec` and `tx.exec` read `$n` on SQLite the way `raw` does**: `$2` written before `$1` binds each value to the placeholder it names, where it bound by first appearance and could change no rows without an error. Every placeholder is written as `$1`, `$2`, … (or `?1`, `?2`, …) with none skipped, or every one as a bare `?`; a statement that mixes the two or skips a number, a `:name` placeholder, a `$3` given two values, or a value no placeholder names is `error.QueryFailed` with the reason in the Problem ([ADR 204](docs/adr/204-a-raw-placeholder-is-spelled-for-the-dialect.md)).

- **A followed `nilo_fetch` redirect goes up to ten hops, where it stopped at three**, the default of Go's `net/http` and reqwest. The `.follow` buffer now bounds one URL and one Location rather than the whole chain, so ten redirects of ordinary length fit the 2 KiB `Client.get` uses. A longer chain or a loop is still `error.TooManyHttpRedirects` ([ADR 183](docs/adr/183-a-redirect-is-a-decision-with-a-name.md)).

- **Every non-2xx answer to a `nilo_s3` call leaves one `warn` line** naming the bucket, the method, the path and the status, and the `Code` when the body has one, including a bare 413 or 502 from a proxy, which failed with nothing in the log.

- **`testing.Live.start` returns once the App's boot work is over** (services started, `before` run, checks passed), not once the port is bound, so a test that seeds through a service right after it no longer races the boot ([ADR 244](docs/adr/244-a-handler-is-given-the-loop-it-runs-on.md)).

- **`Events.live()` also reads what `events.sleep` found**, so a loop that sleeps through `events.sleep` ends the moment the client closes, not on its next write. Nothing to change.

- **`zig build dev` boots the server once, not twice.** With `-fincremental`, the default, `nilo-dev` no longer runs a build-once pass before the watch: Zig 0.17's incremental compiler recompiles and rewrites the binary in every new process, so that pass was followed by a second full compile and a restart (14 s on a program with a C library). `nilo-dev` also skips the restart when a rewritten binary has the same bytes as the one it started, and the `building with …` line is gone from its output ([ADR 190](docs/adr/190-a-restart-on-save-watches-the-binary-not-the-sources.md)).

### Fixed

- **A test whose handler or writer runs on the `std.Io` a `Wired` test or a `testing.Client` lends (`nilo.loopIo()` with no server) is no longer killed with "signal IO" when the call is cancelled.** That `Io` is one `std.Io.Threaded` for the whole process, which cancels a blocked call with `SIGIO`, and any other `Threaded` the process started before it and ended after put the default action back on `deinit`, so the next cancel ended the test binary. The handler is put back whenever that `Io` is handed out.
- **A static directory that follows the disk no longer serves a file that was written in place while it was being read.** The follower waited for the directory to hold still and then read it, and a write that began between the two (`cp`, an editor's save: truncate, then fill) put the file into the new generation empty or half written, where every request read it until the next change. It now looks again after reading, and a generation that moved under its read is thrown away and read again; a directory that never holds still is read as it is after a second, as before ([ADR 277](docs/adr/277-a-static-directory-can-follow-the-disk-and-a-response-finishes-on-the-tree-it-began-on.md)).
- **A `nilo_fetch` POST, PUT or PATCH to an `https://` origin with a body under about a kilobyte reaches the server**, where the body stayed in the socket writer's buffer after the TLS writer was flushed and the call ended in `error.TimedOut` while the server waited for it. A larger body filled the buffer and went out, so only small ones (a webhook, a JSON command) were lost; plain `http://` was unaffected.
- **Reading the empty body of a `nilo_fetch` answer that has none (a 204, a 304, a HEAD's) no longer segfaults on aarch64.** The body was std's `Reader.ending`, which at 0.17.0 sits in read-only memory while a read writes its position; an `Exchange` now carries an empty reader of its own. Nothing to change ([ADR 176](docs/adr/176-an-answer-with-no-body-ends-at-its-head.md)).
- **`db generate` raises a Problem when the key moves onto a new column and the old key column is dropped in the same change**, where it added the new column as a plain one and left the table with no primary key. Write the key move as a step of its own ([ADR 123](docs/adr/123-a-migration-is-a-diff-against-a-snapshot.md)).
- **A `nilo_fetch` call under a route deadline stops queueing for a permit when the route's time runs out**, failing with `error.TimedOut` without dialling, where it waited for the permit and only then saw the deadline had passed. Nothing to change ([ADR 105](docs/adr/105-a-route-can-say-how-long-it-has.md)).
- **On HTTP/2, trailers a client sent for a stream the server had already answered and forgotten no longer end the connection**, which took every other call on it down with a gRPC client stream answered early. The block is decoded and ignored, as it already was for a reset stream, within the time a call's header block gets; a HEADERS on such a stream that does not end it is still a connection error. Nothing to change ([ADR 260](docs/adr/260-a-request-on-http2-runs-from-its-headers.md)).

- **A `nilo_fetch` body streamed from a `std.Io.File.Reader`, and so `putStream` from a file, no longer aborts in std's `Writer.defaultRebase`**: the framed body writer had no buffer, and a file reader whose `sendFile` answers `Unimplemented` asks its writer for room. A file now uploads 64 KiB at a time, 16 KiB at a time under a `stall_ms`, whose clock moves as each step reaches the socket; a copying reader written as a workaround can go.

- **A gzip request body whose bytes disagree with its CRC-32 is a 400**, through `c.body()`, `c.bodyStream()`, a typed body and a gRPC message alike. std's decoder reads the trailer and compares nothing, so a flipped byte inside a literal decoded to a wrong body of the right length.
- **`testing.Client` no longer rebuilds the middleware chains on every send**, which freed the chains a second thread driving the same App was reading. They are resolved again only when something was registered since (`App.resolveChainsIfChanged`).
- **`zig build dev -- … -- <server args>` starts the server**: `nilo.app`'s `dev` step and the `dev-<example>` steps pass the binary to `nilo-dev` before the passthrough arguments, and a configure-time check refuses the old order.

- **A body of no bytes under `Content-Encoding: gzip` is an empty body to `c.body()`**, as it already was to `c.bodyStream()`, where it was a 400.
