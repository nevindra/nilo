# Changelog

What changed between one tag and the next, not what changed between commits.
This file holds the release that has not been tagged yet;
[the releases page](https://github.com/nevindra/nilo/releases) holds the ones
that have, one page each. What was measured and what was got wrong on the way is
in [`docs/history.md`](./docs/history.md); what is coming is in
[`docs/todo.md`](./docs/todo.md), and what was refused or answered is in
[`docs/decided.md`](./docs/decided.md).

## Unreleased

### Breaking

- **`app.static` and `app.embedded` serve a `X.br` or `X.gz` beside a compressible `X` as a form of `X`, and the sibling is no longer a file: `/app.js.br` and `/app.js.gz` answer 404 where they answered the bytes.** A tree that publishes `notes.txt.gz` to download beside `notes.txt` passes `.precompressed = false`. A sibling older than its file, not smaller than it, or a `.gz` that is not a gzip of it is ignored with a warning ([ADR 273](docs/adr/273-a-file-a-build-compressed-is-served-as-the-coding-of-the-file-beside-it.md)).
- **A connection is now ended by the server after about 1,000 requests** (`max_requests_per_connection`, 900 to 1,000 per connection, `0` for never): the last answer carries `Connection: close`. It counts HTTP/1.1 only; `max_requests_per_h2_connection` sends an HTTP/2 connection a GOAWAY naming the last call it will answer, and is off by default because h2load does not reopen after one. A client that reconnects on `Connection: close` (every browser, curl, net/http, requests) notices nothing; one that pipelines resends what was behind the last answer, and one that cannot reconnect sets `0`. Connections were never ended before, so a client stayed on the instance and the executor it was dealt to for as long as it lived ([ADR 275](docs/adr/275-a-connection-is-ended-after-a-number-of-requests.md)).
- **`Plan.isEmpty()` is false while a Problem stands, and `db generate` and `db check` now report it.** A plan with a Problem and no step used to read "Nothing to do" and "Up to date"; `check` now exits 1 and prints the Problem and the `--accept` command. If your CI ran `db check` over a standing Problem, it goes red until the step is written and accepted.
- **The migration advisory lock is asked for and polled** (`pg_try_advisory_xact_lock`, again after a 200 ms `pg_sleep`) where it was waited for, because a waiting statement deadlocks with an index build. A caller that held the lock by `Dialect.advisoryLock(key)` as a blocking statement reads its answer (`true` when granted) and asks again; a replica that waited sees the release up to 200 ms late.

- **nilo needs Zig 0.17.0. v0.7.0 and every tag before it build on Zig 0.16.0**, and stay there. The pins moved with it: zio to a commit on its `main`, because its tags are still the 0.16 line, and tls.zig and pg.zig to forks carrying the 0.17 port until upstream takes it (`build.zig.zon` names the pull requests). A project upgrading nilo upgrades Zig in the same change, and meets 0.17's own changes in its code.
- **A hook declared without `pub` is now skipped without a word, where 0.16 refused it with "not marked pub".** That is a `nilo_start`, `nilo_stop`, `nilo_ready` or `nilo_check` on a Service, a `nilo_table` marker, or any other `nilo_*` declaration: Zig 0.17's `@hasDecl` sees only `pub` ones. Mark it `pub`.
- **`nilo-dev` builds incrementally by default**, on the self-hosted backend: a save is served by the new server 0.56–0.70 s later where a full rebuild takes 3.6–4.5 s, on two cores, for 189 MB of resident compiler ([ADR 190](docs/adr/190-a-restart-on-save-watches-the-binary-not-the-sources.md)). `zig build dev -- --no-incremental` is the old loop. `--incremental` still parses and changes nothing, and `exe.use_llvm = true`, which 0.16 needed beside it, can go.
- **The `dev` step in your `build.zig` is written differently**: Zig 0.17 removed `b.args` and `b.getInstallPath`, which its four lines used. The new lines are in [Restarting on every save](docs/guide/getting-started.md#restarting-on-every-save).

- **The build flag `grpc` is `http2`: pass `.http2 = true` to `b.dependency("nilo", …)` where you passed `.grpc = true`** (`-Dhttp2` for `-Dgrpc` on a command line). HTTP/2 will serve every request and gRPC rides it, so the flag is named for what it builds ([ADR 259](docs/adr/259-http2-is-a-framing-of-every-request.md)). The old name is refused by the build in one line saying so.
- **The listener option `.grpc` is gone, from `listen()` and from an `also` entry: delete the line** (`.also = &.{.{ .port = 4317, .grpc = true }}` is `.{ .port = 4317 }`). On a plain listener it already did nothing, and on a TLS one it made the handshake offer `h2` alone, which a TLS listener now offers beside `http/1.1` without being asked, so a client that offered only `http/1.1` is served where it failed the handshake. The compiler refuses a program that still sets it with its own "no field named `grpc`" ([ADR 259](docs/adr/259-http2-is-a-framing-of-every-request.md)).
- **`nilo.Stream.init` and `initClosing` take the request's `Framing` where they took the connection's `*std.Io.Writer`.** Both are what `Ctx.stream` builds, and nothing in the reference shows them; a test that built a `Stream` by hand against a buffer builds a `Framing` around that buffer first (`.{ .http1 = .{ .in = &reader, .out = &writer, .minor_version = 1 } }`). Every answer now leaves through the framing that carried its request, which is the first stage of HTTP/2 for more than gRPC ([ADR 253](docs/adr/253-an-answer-is-handed-to-the-framing-that-carried-its-request.md)).
- **A header set after the answer's head was written is refused with an error**, where it used to be dropped without a word. A middleware that set a header after `try next.run(c)` and saw it reach the client never did; it calls `next.hold(c)` instead, or sets the header before `next`, or with `defer c.setHeader(...) catch {};` for one that must cover failures too ([ADR 008](docs/adr/008-middleware-is-an-onion-of-ctx-functions.md)).
- **`c.setHeader("grpc-status", …)` and `c.setHeader("grpc-message", …)` are refused.** Set them with `c.setTrailer`, which works the same on HTTP/2 and HTTP/1.1 ([ADR 254](docs/adr/254-an-answer-can-carry-trailers.md)).
- **A gRPC call that fails with `error.AlreadyExists` answers `ALREADY_EXISTS` (6), and one that fails with `error.RolledBack` answers `ABORTED` (10)**, where they answered `ABORTED` and `UNAVAILABLE` from their HTTP status. A client that retried on those codes sees the right ones now.
- **`App.grpcHost` is a compile error in a build without `-Dhttp2`**, where it compiled and was undefined behaviour in ReleaseFast if reached.
- **The idempotency and cache record encoders take the answer's trailers** beside its headers. A record written before reads the same.
- **`c.connection()` is removed.** It named an HTTP/1.1 `Connection` line, which HTTP/2 does not have. `c.keepAlive()` says whether the connection will carry another request, and is the same on both.
- **On HTTP/2, a request with a `content-type` that is not gRPC is served as HTTP**, where it was a 415. A build with `-Dhttp2` now answers every method but `CONNECT` (a 501) on a plain listener to a client that opens with the HTTP/2 preface.
- **`nilo_jwt`: `issuer` and `audience` have no default.** Both are a `jwt.Expect`, in `jwt.Options` and in `jwt.Keyring.Options`: `.{ .is = "…" }` to insist on a value, `.unchecked` to skip the check. A call or a ring that leaves one out no longer compiles (`missing struct field: audience`), where before it quietly accepted a token minted for any other application the same keys sign. What you change: `.issuer = "x"` becomes `.issuer = .{ .is = "x" }`, `.audience = id` becomes `.audience = .{ .is = id }`, and a field you had left out becomes a value or `.unchecked`. `.unchecked` on `audience` is for access tokens that carry no `aud` (Amazon Cognito's, Clerk's, Keycloak's for a user with no client role): compare the claim that names your application (`client_id`, `azp`) in your own `Claims` ([ADR 111](docs/adr/111-nilo-verifies-a-token-and-does-not-fetch-one.md)).
- **A `?T` field with no default is optional in a JSON body, as it already was in a query and a form**: leaving it out reads as null, nested objects and lists included, where it was a 400 `missing "x"`. The API document no longer lists such a field as required, and the sentence naming what an endpoint takes marks it `(optional)`. A body that must tell "not sent" from "sent as null" still uses `Patch(T)`; if you relied on the 400, give the field a type that is not optional ([ADR 011](docs/adr/011-the-query-string-is-a-struct-of-your-own.md)).
- **`sql.Ordering(…).by(terms)` takes its terms while compiling**, and none, or more than the ordering has keys, is a compile error where it was a panic in Debug and ReleaseSafe and a read out of bounds in ReleaseFast. Terms known only at run time go through `.fromTerms(terms)`, which is null for those two cases ([ADR 165](docs/adr/165-an-order-chosen-at-run-time-from-a-closed-set.md)).
- **`.x = null` and `.x = .{ .ne = null }` on a field that is not optional are compile errors**: the `IS NULL` they wrote could never match a `NOT NULL` column. Make the field `?T` if the column may be null ([ADR 040](docs/adr/040-a-condition-holds-a-value-not-a-maybe.md)).
- **`.now` on a `sql.AsText("timestamp")` column is a compile error.** It wrote `now()`, a `timestamptz` Postgres converts to the session's zone, so a session in Asia/Jakarta stored and compared seven hours off. Use `timestamptz`.
- **`job.every(ms)` takes its period while compiling, and refuses `0` and anything over a hundred years (`job.max_every_ms`); an exponential `backoff` with `.from_ms = 0` is refused too.** `every(0)` made a worker busy-loop, a huge period overflowed the clock arithmetic, and doubling a `from_ms` of zero stayed at zero, so every wait was none. A period that was a runtime value (`job.every(settings.minutes * 60_000)`) no longer compiles: a schedule is a `pub const` on the job, so write the number there. A backoff that really means no wait is `.{ .fixed_ms = 0 }`.
- **`nilo_s3`: a bucket that does not exist is `error.Rejected`, where it was `error.NotFound`.** It is the program's configuration that is wrong, like credentials, and answering it as a missing key hid a misspelt bucket name behind a 404. A missing key is still `NotFound`, and the log now names the bucket. A handler that matched `NotFound` to mean "no such bucket" matches `Rejected`.
- **`nilo_s3`: `presign`, `presignPut` and `presignPost` with `seconds = 0` are `error.Rejected`**, where they returned a URL that was already dead.
- **`nilo_s3`: `getRange` with `from > to` is `error.Rejected`; a ranged read answered with anything but a 206, and a `get`, `stream` or `head` answered with no `content-length`, are `error.Failed`.** Each used to be taken as the object, or as an empty one.
- **The API description is stricter in two places, and a client generated from it changes.** Every integer states both ends of its type (`{"type":"integer","minimum":0,"maximum":255}` for a `u8`, `-128` to `127` for an `i8`), where an unsigned one stated only `minimum: 0` and a signed one nothing; a `u128` states no `maximum`. And a field of a returned struct is `required` whatever its default, and so is a `?T`, which the writer sends as `null` when empty, so a generated client stops null-checking them; the request schema keeps its rule. A type that is both read from a body and written as an answer, and whose two halves differ, is now two components, `T` for the answer and `TInput` for the body, each referred to where it is used (one component, as before, when the halves agree) ([ADR 167](docs/adr/167-a-whole-number-inside-a-range-is-a-type.md), [ADR 016](docs/adr/016-the-api-description-comes-from-the-signatures.md)).

- **A route with two or more path params reads them by name, through `nilo.Path(struct { org: u32, id: u32 })`.** Bare arguments were matched by position, so `fn member(id: u32, org: u32)` on `/orgs/:org/members/:id` compiled and ran its query with the two ids swapped; it is now a compile error that writes the struct to use. Take one `nilo.Path(struct { … })` whose fields are the pattern's `:names` (a trailing `*` is the field `@"*"`) and read `p.value.org`. A route with one path param is unchanged, and a resolver may take a `Path(T)` too ([ADR 002](docs/adr/002-typed-handlers-are-a-thin-layer-over-ctx.md), [ADR 015](docs/adr/015-resolved-values-are-declared-by-their-type.md)).
- **A struct whose `nilo_json` renames its fields is a request body, read by the names it is written under.** It was a compile error. A client that posted the Zig field names to such a struct (`full_name` to a `rename_all = .camelCase` struct) now gets a 400 naming the unknown key: send the names the response already uses. Every 400 and `Bound` sentence about a body field, and an enum's choices in one, quote that spelling ([ADR 148](docs/adr/148-a-field-name-is-a-spelling-too.md)).
- **`logger.with` has no `.format`: the format and the level of every line are `listen()`'s, `.log = .{ .format = .json, .level = .info }`**, so a deployment sets them from its environment. `nilo.std_options` now carries `nilo.logFn`, so a program that uses it writes lines with the time first and no colours (`2026-10-09T12:00:00.123Z info message request=…`), and a JSON line is one object with the access line's fields at its top level. A root that sets its own `logFn` keeps it, and `listen()` warns when the format is JSON and that `logFn` is not nilo's ([ADR 262](docs/adr/262-a-log-line-has-one-sink.md)).
- **A single `Upload` field that receives several files is a 400 naming the field**, where it kept the first and dropped the rest. Declare it `[]const nilo.Upload` to take them all ([ADR 132](docs/adr/132-a-query-parameter-or-a-form-field-that-is-a-list.md)).
- **A route's `nilo.deadline(ms)` bounds the `nilo_fetch`, `nilo_s3` and `nilo_sql` calls it makes with its `*Ctx`.** Each takes the shorter of its own bound and the time the route has left, and a call made after the time is up is `error.TimedOut` without being sent. A handler that passed `c.timeLeftMs()` by hand can stop; one whose call has to outlive the route passes a `nilo.Run`. Postgres is sent no cancel: the client gives up and the connection is closed and dialled again, so a write the deadline cut off may still have committed, and a request that is retried needs an idempotency key ([ADR 105](docs/adr/105-a-route-can-say-how-long-it-has.md)).
- **`allowance.with`, `allowance.keyed`, `secure.api` and `secure.pages` read their options as a literal, and `Limited.Limit` is `nilo.Late(usize)`.** An option that does not exist is a compile error naming it. Options built as a value first pass `.per_window = .{ .value = n }` and `.csp = .{ .value = "…" }`, and `Limited.Limit`'s `.bytes` is `.value`. An allowance's `.name` is at most 24 characters with no `"` or `\`, because it names the `RateLimit` policy ([ADR 264](docs/adr/264-a-deployment-fact-is-a-late-value.md)).
- **`Within(…).Int` is `Within(…).Number`**, an integer for whole bounds and an `f64` for real ones. Only code that names the declaration changes.
- **`Date.days_from_epoch_to_y2k` is `sql.types.date_days_from_epoch_to_y2k`**, because `Timestamp` and `Date` moved to `nilo_core` (below).
- **`examples/orders` answers an empty order or a zero quantity with a 400 from its types**, where its handler answered a 422.
- **`db.checking` called a second time on one `Db` makes the boot fail with `error.CheckedTwice`**, where the second list replaced the first without a word and the check covered less than the program thought. A program whose tables are owned by several files joins them into one `sql.Schema` (`.tables = a.tables ++ b.tables`) and calls `checking` once ([ADR 192](docs/adr/192-a-db-with-no-schema-check-says-so-or-is-told.md)).

### Added

- **`db.poolStats()` says how full a Postgres pool is**: connections open, idle and lent out, how many times a statement found none, and how many connections were thrown away ([`sql` reference](docs/reference/sql.md#dbpoolstats), ADR 279). It costs nothing until called, and returns null on SQLite and before `listen()`.
- **`staticWith(.{ .follow = true })` keeps a directory in memory and in step with the disk.** Replace a file, its `.br` or `.gz`, add one or remove one, and the next response after the change is noticed carries it: tens of milliseconds on Linux (`inotify`), `follow_poll_ms` (default 1,000) where there is no event. A response already being written finishes on the tree it began on, a tree that cannot be read keeps the last good one, and nothing is allocated for a request. It costs one thread per followed directory and 25.4 KB of binary, and is off by default because ADR 009's fixed set of URLs is what a deploy can reason about. On the HttpArena static-h2 profile it is 22.8 to 23.4 µs a request against `.reload`'s 44.3 to 52.6 ([ADR 277](docs/adr/277-a-static-directory-can-follow-the-disk-and-a-response-finishes-on-the-tree-it-began-on.md), [Static files](docs/guide/static-files.md#following-the-disk)). A reload reads the whole tree again, so a tree of tens of megabytes wants `follow_poll_ms` raised.
- **A call over HTTP/2 to a route that never waits runs on its connection's own fiber**, with no fiber of its own: baseline-h2c went from 2.45 to 1.25 µs of server CPU a request, TLS h2 from 3.0 to 1.5, a unary gRPC call from 5.7 to 2.4. nilo sees it from the signature (every argument request data, or a service declaring `pub const nilo_never_waits = true;`, which a `cache.Space` does), and a handler taking a `*Ctx` says it with `app.post("/echo", nilo.neverWaits(echo))`. A route with middleware keeps its fiber. A promise that is wrong stalls that connection once, is named in the log, and the route gets a fiber from then on. Nothing to change in a program that does not use it. An HTTP/2 stream's arena now keeps 32 KiB between calls where it kept 4 KiB, which took a JSON answer from 10.1 to 8.0 µs.
- **`nilo_fetch` opens a WebSocket: `ws.open(&client, c, "wss://feed.example.com/prices", .{})`, then `receive`, `send` and `close`.** It is the client's own call upgraded, so its TLS, roots, deadline, request id and `unix_socket` apply as they do to a GET, and the permit goes back at the `101`. A message is limited in decoded bytes (`max_message`, 1 MiB; over it closes with 1009), a ping is answered without you, every frame you send is masked with fresh random bytes, and `close` waits at most five seconds for the other side's. `idle_ms` ends a silent socket with `error.Stalled` and is off by default. No permessage-deflate. The frame code moved to `nilo_core.ws_frame` so the server and the client read and write one copy of it; nothing the server's users call changed ([ADR 281](docs/adr/281-nilo-fetch-opens-a-websocket-and-the-framing-is-core.md), [guide](docs/guide/fetch.md#consuming-a-feed-websocket)).
- **`nilo_fetch` calls a service on a unix socket: `Call.unix_socket = "/var/run/docker.sock"`, or `unix_socket` in a Target's `open`.** The URL stays the request (its host is the `Host`, its path the request line), connections are pooled by the path, `Settings.proxy` does not apply, `https://` is `error.TlsOverSocket`, and a redirect that leaves the origin is `error.RedirectLeavesSocket`. `fetch.testing.Canned.openUnix` serves a canned answer on a socket. A program that sets no socket changes by 736 bytes of binary and nothing else ([ADR 272](docs/adr/272-a-call-names-the-socket-it-goes-over.md)).
- **A file your build already compressed is served.** `app.js.br` and `app.js.gz` beside `app.js` answer a client that prefers them (the highest `q`, brotli on a tie, never one at `q=0`), each under its own ETag, with `Vary: Accept-Encoding` on every answer for the file, the plain one and the 304 included; a `.gz` replaces the gzip copy nilo would make, a spilled file takes its siblings from the disk, and `.precompressed = false` turns it off ([ADR 273](docs/adr/273-a-file-a-build-compressed-is-served-as-the-coding-of-the-file-beside-it.md), [Static files](docs/guide/static-files.md#files-your-build-already-compressed)).
- **A dependent can bring its own tls.zig.** Pass `.tls_own = true` beside `.tls = true` (or `.tls_module = …` to `nilo.app`) and write `nilo.module("nilo_http").addImport("tls", your_module)`: nilo's pin is not fetched, and forgetting the line fails with a message that names it. The surface your module needs is under [A TLS library of your own](docs/reference/app.md#a-tls-library-of-your-own). Nothing changes for a build that does not set it ([ADR 274](docs/adr/274-a-dependent-can-bring-its-own-tls-library.md)).
- **`sql.Replays(Db, .{ .name = "orders", … })`: `nilo.Idempotent` answers once per key across every instance that shares the database.** The store is a table in the database you already have (`Replays.Row` goes into `createMissing` or a migration beside your own rows, and into `db.checking`), `Replays.open(&db)` is provided as a service, and the handler does not change: `nilo.Idempotent(Replays, …)` takes it where it took a `cache.Space`. Two instances receiving one key at once run the handler once (the claim is atomic in the database, and a test claims one key sixteen times at once from two pools), and a retry the balancer sends to the other instance is answered from the table. `sweep(scope)` deletes keys that ran out and nothing calls it: run it from a scheduled job. It costs two commits on a fresh request (about 2.6 to 3.3 ms on Postgres at defaults, tens of microseconds with `synchronous_commit = off`) and about 100 µs on a replay, on the routes that ask and nowhere else. A database that cannot be asked at the claim is a **503** and the handler does not run; a store of your own that can fail declares `pub const takes_scope = true` and is called with the Scope first ([ADR 268](docs/adr/268-an-answer-kept-for-a-retry-is-a-row-when-instances-share-a-database.md)). A `Cached` over a store that takes a scope is a compile error.
- **`db generate --concurrently <index>,…` builds an index on a table that has rows without stopping its writes** (Postgres). The named `CREATE INDEX` steps are written as a version of their own after the rest, marked `.transactional = false`, with `CONCURRENTLY IF NOT EXISTS`; the ledger row is written after the last step, a build that failed halfway leaves an invalid index that is dropped before the next attempt, and the generated `why` of every ordinary index step says how to ask. On one million rows, 622 to 1,106 inserts got through the build where the blocking one let through 0 to 7. The build runs without `lock_timeout`, since waiting for older transactions blocks no one; bound it with `statement_timeout`. A `Version` of your own may say `.transactional = false`, and its steps must then be safe to run twice. `wire.Begin` gets `transaction: bool = true` ([ADR 269](docs/adr/269-an-index-on-a-big-table-is-built-outside-a-transaction.md)).
- **`db generate --accept <name>,…` records a Problem as handled by a step you wrote**, so the snapshot moves past it and the diff stops raising it; `generate` prints each Problem's name (`orders.customer_id@1a2b3c4d`) and the command that accepts them, and nothing is accepted that was not named ([ADR 270](docs/adr/270-a-problem-is-accepted-by-name.md)).
- **`nilo_s3`: a streamed object can be read from an offset, and the total size comes back.** Set `.range` on the `Reading` before `stream` (`var r: Files.Reading = .{ .range = .{ .from = 5_000_000, .to = 5_999_999 } };`) and the slice is served whatever the bucket's `max_bytes` is; `Reading.total` and the new `Object.total` (from `getRange`) are the whole object's size from `content-range`, which is what a handler needs to answer a browser's own `Range` with a `Content-Range`. `len` stays the bytes the call moves.
- **`nilo_s3`: a failure says what it was.** `head` logs the status and `x-amz-bucket-region` of a refusal (a wrong region or a skewed clock was silent), a missing bucket is named, and a session token or access key id too long to sign with is no longer logged as "could not be reached".
- **`nilo_fetch` writes a form body: `client.postForm(c, url, fields, .{})`, `putForm`, `sendForm`, and the same three on a `Target`**, with `fetch.formBody(c, fields)` for the bytes alone. `fields` is a struct under `withQuery`'s rules and Refusals; the body is `application/x-www-form-urlencoded` with a space as `+`, one allocation sized exactly, and the `content-type` is said for you. **`fetch.basicAuth(c, id, secret)` builds the `client_secret_basic` header the OAuth way**, form-encoding the id and the secret before joining and base64-encoding them (RFC 6749 §2.3.1), so a secret with a `+` or a `:` in it is not refused only by the provider ([ADR 061](docs/adr/061-a-fitting-borrows-the-loop.md)).
- **`c.setTrailer(name, value)`**, a field sent after the body: a HEADERS frame on HTTP/2, a trailer section on a chunked HTTP/1.1 stream, and on a whole HTTP/1.1 answer when the client sent `TE: trailers`. With it `c.trailers()`, `c.clientReadsTrailers()`, `Ctx.checkTrailer`, and `.trailers` on `nilo.Response(T)` and `nilo.Status(code)`. A route that sets none pays nothing ([ADR 254](docs/adr/254-an-answer-can-carry-trailers.md)).
- **`next.hold(c)`**, which hands a middleware the answer below it unwritten as a `nilo.Answer` (`status`, `body`, `setHeader`, `setTrailer`, `replace`), written when the chain has unwound. A body sent with `c.send` under a hold is copied into the arena, free under 16 KiB and costly above it; **`c.sendKept`** sends one that already outlives the chain without the copy ([ADR 008](docs/adr/008-middleware-is-an-onion-of-ctx-functions.md)).
- **A protobuf message is a handler's argument and its answer**: a struct with a `wire` table is read as JSON or protobuf by the request's `Content-Type` and answered in the same, so one function is a JSON route, a protobuf route and a gRPC method, with no `proto.decode` in it. Any other format is read by the type itself with `nilo_content_type` and `nilo_decode`, the mirror of `nilo_write`. The document files a message under both content types ([ADR 256](docs/adr/256-a-body-is-read-as-what-its-type-says.md)).
- **A Connect client is told a failure as the code it reads**: a request carrying `Connect-Protocol-Version: 1` that fails is answered `{"code":"not_found","message":"…"}`, the code from the error first and the status otherwise, the table a gRPC call's code comes from. Every other request keeps nilo's shape or the one `app.failures` named, and a program with no message route links none of it ([ADR 257](docs/adr/257-a-connect-client-is-told-its-failure-in-connect-words.md)).
- **`app.rpc(T)` serves a struct as an RPC service**: `pub const nilo_service = "helloworld.Greeter"` names it, and each `pub fn` is a method at `POST /helloworld.Greeter/SayHello`, its first letter upper-cased, reachable by gRPC, Connect and plain JSON. A `pub fn` that speaks no message, or two that become one method, is a compile error ([ADR 258](docs/adr/258-a-struct-of-typed-functions-is-an-rpc-service.md)).
- **In a `-Dhttp2` build, every plain listener answers HTTP/1.1 and HTTP/2 on the same port**, told apart by the client's first bytes: the 24-byte HTTP/2 preface is HTTP/2 with prior knowledge (what every gRPC client and `curl --http2-prior-knowledge` send), anything else is HTTP/1.1, decided at the first byte that differs, so a short request is never waited on. A gRPC service no longer needs a port of its own, and a client that reached a gRPC listener with HTTP/1.1, which got a 505, is now served.  `Upgrade: h2c` is ignored and the request served as HTTP/1.1. An HTTP/1.1 connection costs what it did (5,197 bytes idle at 10,000 connections, the routed `GET` at 942k requests a second either side), and a build without the flag is byte-identical ([ADR 259](docs/adr/259-http2-is-a-framing-of-every-request.md)). Only gRPC calls are answered on HTTP/2 for now.
- **In a `-Dhttp2` build, HTTP/2 serves any request** (stage 5.3 of [the framing page](docs/design/framing.md)): the router, middleware and handler run as on HTTP/1.1, on a fiber a stream, held to RFC 9113 §8 (pseudo-headers, connection-specific fields, `te`, `content-length` against the `DATA`, `cookie` joined), answered with `:status`, `content-type`, `content-length`, `date`, the route's headers, `DATA` under both windows and trailers, and `HEAD` without `DATA`. `100 Continue` is sent when the handler first reads a body that has not arrived. What still waits is refused by name with a 500 that says so: `c.upgrade` (a WebSocket is HTTP/1.1); the stream, the event stream, the file and `c.eventsFrom` arrive in the entries below. An HTTP/2 request costs 963 to 971 ns in process against 413 for the same `GET` on HTTP/1.1, allocates the same from the second on a connection, and an idle HTTP/2 connection is 9,355 bytes at 10,000 ([`bench/result/http.md`](bench/result/http.md#what-any-request-on-http2-costs)).
- **In a `-Dhttp2` build, a request on HTTP/2 runs when its headers are in, and its body is read through a pipe** (stage 6.1): a handler starts as it does on HTTP/1.1, `c.body()` waits for the whole of it and hands it over where it arrived with no copy and no allocation, **`c.bodyStream()` works on HTTP/2** under its own `max_bytes`, and the client is told it may send more as the handler reads, so an upload faster than its handler holds the connection to one window (68 KB while stalled, 99 KB at the peak of 8 MiB) instead of the connection collecting it. `Expect: 100-continue` is answered when the handler first reads a body that has not arrived, and not when it already has. A gRPC message is read and inflated on the call's own fiber and a gzip one waits for room in the connection's budget there. A `content-length` the DATA does not add up to resets the stream with PROTOCOL_ERROR and fails the read that waits, a client that stops sending is held to the bound a chunked HTTP/1.1 body is, and a reset stream, a GOAWAY or a dead connection wakes a waiting handler with the error a closed socket gives. After a complete answer to a client that is still sending, the connection says RST_STREAM with NO_ERROR (RFC 9113 §8.1). **A handler that never reads its body now runs, and may answer, before the client has finished sending it** (the connection says RST_STREAM with NO_ERROR when it has answered first). Cost: a unary gRPC call is 62 ns and a small JSON `POST` 85 ns slower in process (7 and 10%), and an idle HTTP/2 connection weighs 70 to 139 bytes more; a build without the flag is byte-identical, a `-Dhttp2` one is 14.6 KB larger, and through `h2load` the pipe's wait is inside the spread of the collected one ([`bench/result/http.md`](bench/result/http.md#what-a-request-on-http2-costs-when-its-body-is-a-pipe)).
- **In a `-Dhttp2` build, `c.stream()`, `c.events()` and `c.sendFile` work on HTTP/2** (stage 6.2): a handler writes its answer in pieces as it does on HTTP/1.1, through a pipe the connection empties into `DATA` frames as the client's windows allow, trailers included, `HEAD` as a head with no `DATA`, and a file read into frames a buffer at a time, a range request too (there is no `sendfile` between frames). A piece allocates nothing: the connection writes the frames out of the buffer the call lent. A client that stops reading is reset with `CANCEL` at the write deadline and the call's next write fails, as on a dead HTTP/1.1 socket, and a reset stream, a GOAWAY or a closed connection wakes a call that waits to write; one connection takes turns between its streams, 64 KiB each and in rotation, so a small answer is not held behind a large one and no stream takes every window update, and a file's buffers are held to 1 MiB a connection. `c.upgrade` stays refused by name on HTTP/2. Cost: pieces at about half HTTP/1.1's rate (15.7 against 30 million a second) and a file at 3.2 against `sendfile`'s 6.7 to 7.3 GB/s, an idle HTTP/2 connection unchanged to the byte, and a `-Dhttp2` build 11 KB larger; a build without the flag is byte-identical, and HTTP/1.1, its `sendfile` path and the rows of `zig build profile` are unchanged ([`bench/result/http.md`](bench/result/http.md#what-a-request-on-http2-costs-when-its-answer-is-a-pipe)).
- **In a `-Dhttp2` build, `c.eventsFrom` works on HTTP/2** (stage 6.3): the stream is handed to the connection as on HTTP/1.1. The Rooms ring the connection's bell, the connection writes what was posted as `DATA` under both windows in turn with its other streams, and the handler's fiber has ended, so the stream holds no handler and a connection of event streams only gives its pages back when it is quiet. History, `Last-Event-ID`, `.retry_ms` and `.keepalive_ms` are as on HTTP/1.1; a client that stops reading is held to the Room's backlog and reset with `CANCEL` at the write limit; a reset, a GOAWAY, a closed connection and a stopping server each end the stream and give its seats back; a handed-over stream counts against `max_concurrent_streams`. **`c.upgrade` is still refused by name on HTTP/2** (the sentence now says "is HTTP/1.1 only"). A server that stops ends each handed-over stream with its last frame and a GOAWAY, written under a cancellation shield (`bulkhead.beginShield` and `endShield` are new in the Bulkhead contract), and a client that gives its window back a byte at a time is a flood and never makes an event be formatted again. Cost: a handed-over stream weighs 6.2 KB at 10,000 opened a thousand at a time (12 KB opened at once, which is not explained yet) and 4.9 KB on top of its connection when it is the only one on it, against 19.6 KB for one parked in its handler; HTTP/1.1's 5,192 bytes and an idle HTTP/2 connection's 9,423 are unchanged to the byte; a build without the flag is byte-identical, a `-Dhttp2` one 5.1 KB larger and 9.8 KB more for a program that calls `eventsFrom`, which pays nothing on HTTP/1.1; 100 subscribers are written 15 to 17 million events a second over HTTP/2 against 18 million over HTTP/1.1 ([`bench/result/http.md`](bench/result/http.md#what-an-event-stream-handed-to-the-http2-connection-costs)).
- **A unary gRPC call is about 30% faster in process, makes one allocation fewer, and a `-Dhttp2` build is 30 KB smaller**: the call reaches the App as what was read and its answer is collected by the framing, where both used to be written as HTTP/1.1 and parsed back ([ADR 253](docs/adr/253-an-answer-is-handed-to-the-framing-that-carried-its-request.md)), and its headers' Huffman is decoded two symbols a lookup, which halved the HPACK share of a call (767 to 773 ns a call, from 1,083 to 1,118). Its metadata is held to the same rules an HTTP/1.1 head is, as it was.
- **In a `-Dtls -Dhttp2` build, a TLS listener offers `h2` and `http/1.1` by ALPN and serves what was chosen** (stage 7 of [the framing page](docs/design/framing.md)): a browser gets HTTP/2 from nilo itself, every route working on it, and a client that sends no ALPN is served HTTP/1.1; one that offers ALPN with neither `h2` nor `http/1.1` in it gets RFC 7301's `no_application_protocol`. A WebSocket stays HTTP/1.1, on a connection of its own. gRPC over TLS is an ordinary TLS listener. An HTTP/1.1 connection over TLS costs what it did (9,370 bytes idle at 10,000 connections against 9,364), an HTTP/2 one 9,564 to 9,581 after a `GET`, so a browser holds about 9.6 KB where six HTTP/1.1 connections held 56 KB; a page of nineteen subresources loads in 77 to 80 ms against 117 to 121 with 20 ms added to every request, and equally on loopback. A build without `-Dhttp2` offers `http/1.1` alone, as it did ([ADR 259](docs/adr/259-http2-is-a-framing-of-every-request.md), [ADR 027](docs/adr/027-tls-is-terminated-in-front.md)). `bench/page_server.zig` and `bench/page_load.mjs` are the page and the Chromium driver, and `bench/mem.py --tls --h2` the idle figure.
- **`bucket.copy` and `bucket.compose`**: copy an object to another key, and join objects into one (a multipart upload whose parts are copies), inside the store, with no byte passing through the caller. A copy keeps its source's type; a join takes `.content_type` the way `putMultipart` does. Both read the answer for a 200 that carries an error ([ADR 058](./docs/adr/058-most-of-an-s3-client-is-not-s3.md)).
- **`sweepDead(c, before)` on `job.Table` and `job.Memory`**, which deletes the dead rows that died before a moment. `Table.sweep` takes `done` rows only and still does, since a dead row is the record of a failure; but nothing else removed one, so a `Table` kept its dead rows for good and a `Memory` full of them answered `QueueFull` to a push with nothing wrong. `Memory` now stamps a dead row with the time it died, as `Table` always did.

- **A middleware takes what it needs after `Next`**: `fn requireKey(c: *Ctx, next: Next, keys: *KeyStore, user: CurrentUser) !void`, registered with `use`, `useOn`, `with` or `without` like any other. A pointer is a service, a type with `nilo_resolve` is a resolved value worked out once and shared with the handler, `nilo.Path(T)` reads the path params, and `std.mem.Allocator` and `std.Io` are the arena and the loop. A service nobody provided stops `listen()` naming the middleware, where `c.service(T) orelse return next.run(c)` let every request through; a `Path(T)` is held at `listen()` against every route the middleware covers, and a request no route matched gets its 404 or 405 without running it. One that reads path params is refused at `listen()` over a static mount under its prefix, which would be served unguarded, and over a route only the real path decides (`useOn("/api", …)` beside `/:version/list`) ([ADR 008](docs/adr/008-middleware-is-an-onion-of-ctx-functions.md)).
- **`nilo.Timestamp` and `nilo.Date` work in a build with no `-Dsql`**: a JSON body or response field (RFC 3339 and `YYYY-MM-DD`), a query or form field, a path param, and `format: date-time` / `date` in the document. They live in `nilo_core`, and `sql.Timestamp` and `sql.Date` are the same types ([ADR 057](docs/adr/057-percent-is-needed-by-two-layers.md)).
- **`nilo.Bearer(T)` signs a client in that has no cookie jar, a mobile application most often.** `Bearer(T).issue(c, value, .{ .max_age = 3600 })` seals a token under the session secret; a handler takes `Bearer(T)` and reads `get()`, or `require()` for a 401 with `WWW-Authenticate: Bearer`. Fallback secrets open it, a token and a session cookie never open as each other, and the route is described with a `bearerAuth` scheme. Nothing to sign by hand, and no JWT ([ADR 265](docs/adr/265-a-bearer-token-is-a-session-sealed-for-a-header.md)).
- **`@import("nilo").app(b, .{ .name = "hello", .root = b.path("src/main.zig") })` writes a dependent's whole build**: the executable, its install and the `run`, `dev` and `test` steps, with `.sql`, `.tls`, `.http2` and `.libdeflate` passed through. `template/` ships in the package as a project to start from, and the getting-started page fetches it in one line. A `build.zig` written by hand keeps working ([ADR 263](docs/adr/263-a-first-project-is-one-call-from-its-build-file.md)).
- **A form field typed `[]const nilo.Upload` takes every file sent under its name**, in order (`<input type="file" multiple>`), bounded by `max_parts` and `max_body`, and described as an array of binary strings. `Fields.fileCount` and `Fields.filesNamed` read the same without binding.
- **`nilo_json` takes `.skip = &.{"password_hash"}`**: the named fields are never written in a response, never read from a body, and left out of the document. One read from a body needs a default or a `?T`.
- **`nilo.Many(Item, .{ .min = 1, .max = 5 })` bounds a list's length** in a JSON body or a form (`"tags" has to be a list of 1 to 5 items, not a list of 7`), collected by `Bound` and written as `minItems`/`maxItems`; **`Within(0.0, 1.0)` is a real range**, refusing `nan` and `inf`. The requests guide teaches the checking types on a JSON body, and `examples/rest` and `examples/orders` use them where they checked by hand ([ADR 167](docs/adr/167-a-whole-number-inside-a-range-is-a-type.md), [ADR 266](docs/adr/266-a-list-with-a-length-is-a-type.md)).
- **A rate limit and a CSP can come from the environment**: `.per_window = &settings.rate` or `.csp = &settings.csp`, the address of a value filled before `listen()` (`nilo.Late(T)`). The counts are `u32`, so `allowance.keyed` takes a million an hour. Every answer through an allowance carries `RateLimit-Policy` and `RateLimit`; `.headers = false` turns them off ([ADR 264](docs/adr/264-a-deployment-fact-is-a-late-value.md)).
- **A line a handler logs names its request** (`request=…`, or `"request"` in JSON), and `logger.with(.{ .skip = &.{"/healthz"} })` leaves paths out of the access log. A JSON line stays JSON whatever bytes it was given ([ADR 262](docs/adr/262-a-log-line-has-one-sink.md)).
- **`listen()` warns once when the root has no `pub const panic = nilo.panic;`**, which names the request a panic came from, and once when it listens on loopback inside a container, where nothing outside can reach it ([ADR 007](docs/adr/007-no-recover-middleware.md), [ADR 103](docs/adr/103-a-path-is-an-address-to-listen-on.md)). A second `provide` of one type names the type and the wrapper struct that holds two. The deploying guide shows a static build in a `FROM scratch` image and which platforms are tested.
- **`nilo_fetch` can go out through an egress proxy and trust a private certificate authority: `Settings.proxy` and `Settings.roots`.** `.proxy = .{ .url = "http://user:secret@proxy.corp:3128", .bypass = &.{"corp.example"} }` sends every `http://` call to a forward proxy (the user and password become `Proxy-Authorization` and go to the proxy alone, and no redirect carries them), and a host in `bypass`, with every host under it, is dialled directly. It is never read from `HTTP_PROXY` or `NO_PROXY`, and nothing is skipped that is not listed, loopback included. **An `https://` call goes through it in a `CONNECT` tunnel `nilo_fetch` opens itself**, with TLS run inside it and the certificate checked against the name in the URL and never the proxy's (std 0.17 cannot do this: its tunnel sends the request in the clear). A proxy that answers the `CONNECT` with anything but a 2xx is `error.TunnelRefused` before a byte of the call is sent, and a proxy that is itself an `https://` URL is `error.TlsThroughProxy`. A bad URL is `error.InvalidProxy` from `nilo_start`. `.roots = &bundle` is a `std.crypto.Certificate.Bundle` you loaded (the system's plus your authority is `rescan` and `addCertsFromFilePathAbsolute`), shared by both of the client's std clients and never freed by it. Nothing changes for a client that sets neither; a program that dials out is 2,144 bytes larger for the proxy and 4,704 more for the tunnel ([ADR 267](docs/adr/267-a-call-can-go-through-a-proxy-and-trust-a-private-authority.md), [ADR 276](docs/adr/276-an-https-call-goes-through-a-proxy-in-a-tunnel-nilo-opens.md)).
- **A `fetch.Target` can retry: `.retry = .{ .times = 3, .mint_key = "Idempotency-Key" }` on the type.** The numbers are yours (`times`, a `backoff` with `.jitter`, the `statuses` that mean "later", a cap on `Retry-After`, a `budget`), and the mechanism is nilo's: only a GET, HEAD, PUT, DELETE or OPTIONS is sent again, a POST or PATCH only with an `Idempotency-Key` header of yours or on a type that names `mint_key` (one key per call, on every try), a budget allows retries up to 20% of recent calls plus a floor and cannot be switched off, `Retry-After` is a capped floor on the wait, and the route's deadline ends the whole sequence with no permit held across a wait. A target with no `.retry` makes one try as before and pays +48 bytes of binary. The loop the guide used to teach (a `nilo.sleep` and a `switch`) retried a POST and had no jitter and no budget: replace it with `.retry` ([ADR 271](docs/adr/271-a-retry-is-the-callers-numbers-and-nilos-mechanism.md), [the guide](docs/guide/fetch.md#retrying)).
- **`nilo_s3` retries `Throttled` and `Unavailable` when the Store says `.retry`**, for `get`, `getRange`, `getIf`, `put`, `head`, `list`, `delete` and `copy`, each try signed afresh under one budget for the Store. The default is none, so nothing changes until you ask. `stream`, `putStream` and the multipart upload are never retried. `Store.open` is `error.BadRetry` for numbers that cannot work.
- **`Backoff` has a jitter: `.{ .exponential = .{ .from_ms = 1_000, .to_ms = 3_600_000, .jitter = .full } }`** (`.none`, the default, `.full` or `.equal`), so a hundred rows a downstream outage failed together do not all retry at the same instant. `Backoff` is `nilo_core`'s now and `job.Backoff` is the same type, so no kind changes a line; `job.Retry.delayMs` still answers the un-jittered ceiling.
- **`fetch.testing.Canned.serveScript(script, count)`** answers a script of `fetch.testing.Reply` values, one connection each, and records when each request arrived and its head, for a test of your own about retrying.
- **An answer can leave a field out: `pub const nilo_json = .{ .omit_null = true, .omit_empty = &.{"root_attributes"} }`** leaves out every optional of the struct that is null, and the named lists and text that are empty (Go's `omitempty`, serde's `skip_serializing_if`). The generated writer applies it, so the type keeps the fast path where a hand-written `jsonStringify` lost it, and `rename_all` works beside it. The API document no longer lists such a field as `required` in the answer, and a body read into the type is unaffected. A type without the entries is written by the same code as before. On a type that would go to `std.json` (a tuple, an array of bytes, an untagged union, its own `jsonStringify`) either entry is a compile error, as `rename_all` already is ([ADR 282](docs/adr/282-an-answer-can-leave-a-field-out.md)).
- **`testing.Client` and `testing.Wired` have `put`, `patch` and `delete`** beside `get` and `post`; `request` still sends any method with a body.
- **`nilo.bodyEncodings(.{"snappy"})`: a route reads a `Content-Encoding` nilo does not decode itself**, which is what a Prometheus remote-write receiver needs. Under `app.with(nilo.bodyEncodings(.{"snappy"}))` a body under a named coding reaches `c.body()` and `c.bodyStream()` as it arrived, with the coding in `c.header("content-encoding")`, and `max_body` or `maxBody` holds the bytes that arrived; decoding, and bounding what it decodes to, is the handler's. A coding the route did not name is a 415 carrying `Accept-Encoding`, and every other route answers the 415 it always did. Naming `"gzip"` passes gzip through undecoded. `c.json`, `c.form` and a typed body answer 415 for such a body, and a `nilo_decode` type is handed the bytes. The same holds on HTTP/2 ([ADR 283](docs/adr/283-a-route-can-read-a-content-encoding-itself.md)).

### Changed

- **Gzip stays on one compressor a thread: `Pool.gzip` starts its scan at the calling executor's own slot, and each slot's free flag has a cache line to itself** (`Pool.gzipAt` takes the index for a caller that starts its own threads). Nothing to change. libdeflate builds spend about 2% less CPU a `json-comp` request on 8 threads, more where cores do not share a cache ([ADR 211](docs/adr/211-a-response-is-compressed-on-a-compressor-borrowed-from-a-pool.md)).
- **A JSON answer is written into a buffer the thread keeps and copied into the request arena once, at its length, and a scalar field is one copy** where `sendJson` and a typed handler's answer grew an `Allocating` writer by doubling and wrote a field in several calls. The bytes are the same; nothing to change. On the arena's `json-h2c` profile, 3.7 KB of JSON a request, server CPU went from 10.4 to 7.7 to 8.5 us a request, and the writer alone from 1,450 to 586 ns ([ADR 278](docs/adr/278-a-json-answer-is-written-in-one-buffer-and-copied-once.md)).
- **`Exchange.take`, and so every whole-body call on `nilo_fetch`, reads a body that announced its `content-length` into exactly that many bytes**, where it grew a buffer by doubling. A call now holds 2,042 bytes less on each idle connection that made it (8,852 to 6,810 at 10,000 connections), and a body that ends short of its announced length is `error.BodyTooShort`. Nothing to change in your code; a program that dials out through `nilo_fetch` is 1,888 bytes larger.

### Fixed

- **An HTTP/2 request body with no `content-length` under a `Content-Encoding` nilo does not decode is a 415**, as it is on HTTP/1.1; it reached `c.body()` still compressed ([ADR 089](docs/adr/089-a-body-under-an-encoding-other-than-gzip-is-refused.md)).
- **`db generate` refuses a snapshot that is ahead of the newest version file**, where it wrote that number again: a version file deleted or lost in a merge left `snapshot.zon` saying a version the directory no longer had, and `db check` reported it while `generate` did not. It now stops with a sentence naming the snapshot and the newest file (`migrations.Error.SnapshotAhead`); put the file back or restore the snapshot ([ADR 123](docs/adr/123-a-migration-is-a-diff-against-a-snapshot.md)).
- **`sql.violated` and `sql.problem` can no longer lose the Problem of a failed statement to another request's statement while its result set is given back.** The statement is told after the drain, which can suspend. Nothing to change ([ADR 117](docs/adr/117-a-statement-that-failed-says-what-the-database-said.md)).
- **A number inside an externally tagged union is read by the rule every other number in a body is**: `{"a":"1_0"}` into a union with an `a: u32` arm was 10, and is a 400 now, as are `"+7"`, `"nan"` and `1e999` ([ADR 084](docs/adr/084-a-number-in-a-request-is-not-a-zig-literal.md)).
- **`listen()` stops as soon as `app.shutdown()` or a stop signal asks it to**, where it waited for its next look at the flag, up to a fifth of a second later. Nothing to change ([ADR 200](docs/adr/200-every-executor-accepts.md)).
- **A call that was redirected to another origin no longer sends it the credentials it was written with.** `get`, `postJson` and the other whole-body calls, and an `Exchange` begun with `.redirects = .follow`, re-sent a `Target`'s `authorization` and a call's own `Authorization`, `Cookie` and `Proxy-Authorization` lines to wherever a 3xx pointed, `https` to `http` included. `nilo_fetch` now walks the redirect itself: past a change of scheme, host or port those lines, the `www-authenticate` line and every standing header of a `Target` are not sent, and a hop from `https` to `http` fails with the new `error.InsecureRedirect` (a service that really redirects to plain `http` is called at that address on purpose). A redirect inside one origin keeps everything, as before. A call that relied on a Target's `x-api-key` or tenant header reaching a second host does not get it any more; make the second call yourself with the line you mean to send. The whole-body calls also have a new `Response.redirected`, the URL the call ended at or null ([ADR 183](docs/adr/183-a-redirect-is-a-decision-with-a-name.md)).
- **A file input left empty in a browser is no file: `?Upload` is null and a required `Upload` is the "missing the file" 400.** A browser sends an unchosen file input as a part with `filename=""` and no bytes, which `Form(T)` handed over as an `Upload` of 0 bytes, so `?Upload = null` was never null from a browser and an edit form that kept the old file replaced it with nothing. The part is dropped now (it is not an empty text value either). A chosen file with no bytes (a non-empty filename) and a part with an empty filename but bytes in it are still files. Present in 0.7.0; a handler that relied on receiving the empty `Upload` now gets null or a 400, and a handler that wrote `if (incoming.value.avatar) |a| …` needs no change.
- **A `nilo_job` run that returns `error.Canceled` of its own no longer stops every worker.** A `run` that raced two calls, cancelled the loser and `try`d it returned `error.Canceled`, which the worker read as the server going: the row was put back and every worker left its loop, so the queue stayed stopped until the process restarted. The worker now knows the shutdown from `serveOn` being cancelled, or from a cancellation a statement left pending, and an `error.Canceled` from anything else is a failed attempt of that run, retried or dead by its kind's `retry` ([ADR 243](docs/adr/243-a-run-cut-off-by-a-shutdown-goes-back-whatever-the-statement-said.md)).
- **`db generate` writes a new column's foreign key instead of stopping on it.** Adding a field with a `.references` of one column to a table that exists was a Problem on both dialects, `generate` wrote nothing, and the step it suggested never moved the snapshot, so the same Problem came back until `snapshot.zon` was edited by hand. It is now one `add_column` step with the `REFERENCES` in it (`ALTER TABLE "posts" ADD COLUMN "org_id" int8 REFERENCES "orgs" ("id")`), on SQLite too. SQLite takes that only for a column that defaults to NULL, so a `.default` beside a key on a new column is a Problem there. A key added to a column the table already had is still refused. `addMissingColumns` writes the same statement.
- **A value SQLite refuses before binding (an integer past an `i64`, a NaN) no longer takes its Problem's text from the connection's previous statement.** A probe could not make the old code carry it, but the path read `errmsg` for an error that never reached SQLite; it now says the error's name, so `sql.violated` cannot answer true for a unique the last statement hit.
- **`nilo-dev --no-incremental` no longer deletes the cache entry of the same program built for another target or mode.** It deleted every `.zig-cache/o/` directory holding a binary of the served name, and the next build of that other configuration failed `install` with `FileNotFound` on every run until the cache was rebuilt. It now deletes only the directory of the build each restart replaced ([ADR 190](docs/adr/190-a-restart-on-save-watches-the-binary-not-the-sources.md)). Present in 0.7.0; a cache already broken by it is fixed by deleting `.zig-cache` once.
- **A body such as `{"steps":[{"signal":"queued"},}]}` no longer aborts the process.** A stray `}` or `]` where an internally tagged union (`nilo_json = .{ .tag = … }`) should start reached `unreachable` in `std.json`'s `skipValue`, which is undefined behaviour in ReleaseFast; it is a 400 now. Present in 0.7.0 for a union with a `nilo.jsonParseFor` reader.
- **A tagged union with the tag first is read in one pass, and a body with two mistakes may name the other one first.** The same bodies are refused and a body with one mistake gets the same message; with two, the first in field order is named, so a client can read a different 400 sentence (`MissingField` for `UnknownField`, for one).
- **A number inside a `std.json.ArrayHashMap` or a tuple in a JSON body is read by the rule every other number is** ([ADR 084](docs/adr/084-a-number-in-a-request-is-not-a-zig-literal.md)): `{"a":"1_0"}`, `"+7"` and `"nan"` into a map of integers or floats are a 400, where they were 10, 7 and a NaN. A map value that is a struct is now read by nilo's reader too, so `unknown_fields = .ignore`, `Str` and `Patch` inside map values apply. A client that sent a number as a quoted string of digits (`"10"`) is unaffected.
- **An idle connection costs 512 bytes less: 4,678 at 10,000 connections on the benchmark server, where v0.3.0 read 5,188.** A connection's task carried a copy of the listener's sizes, which put it in the next size class of zio's allocator. Nothing to change; `zig build park-check` is new in `zig build test` on Linux x86-64 and fails if an idle connection takes a second page of stack.
- **A connection over TLS no longer waits on a socket that has nothing for a record it already holds.** The record layer takes whatever the socket has and decrypts one record a call, so a client that sent a second frame right behind its first (HTTP/2's `HEADERS` behind its `SETTINGS`, one connection in a thousand) left the server parked for bytes it had read; the wait now answers from the record layer first. A WebSocket over TLS parked in the same wait.
- **A spawned fiber whose `nilo.sleep` follows a swallowed cancel no longer keeps the server up.** The first wait it reached spent the stop's one cancel, its next `nilo.sleep` slept on, and `listen()` waited for it forever. `nilo.sleep` in spawned work now answers `error.Canceled` for as long as the server is cancelling it. Other waits are not covered: work that swallows a cancel puts it back with `nilo.io().recancel()` ([ADR 028](./docs/adr/028-a-spawned-fiber-belongs-to-the-server.md#a-swallowed-cancel-does-not-keep-the-server)).
- **Two replicas migrating at once no longer fail to boot under a role whose default isolation is REPEATABLE READ.** The second took its snapshot before it waited for the lock, did not see the first's ledger row, and ran the version again into `42P07`. Migrations now begin `READ COMMITTED` by name.
- **`expect` boots under a role that may only read and write rows.** It reads the catalog first and touches nothing when the ledger is there, where `CREATE TABLE IF NOT EXISTS` was refused for want of the schema's CREATE privilege; a boot is one query where it was four round trips.
- **A migration that changes the type of a column a trigger names in `UPDATE OF` or `WHEN` runs on Postgres**: the trigger is dropped before the change and made again after it, where Postgres refused the change with `0A000`.
- **`sql.violated` names the primary key of a table whose name leaves no room for `_pkey`**, truncated at 63 bytes the way Postgres truncates it.
- **A table with no schema is introspected down the whole `search_path`**, as a query resolves it, where only `current_schema()` was read and a table further down the path was found with no columns.
- **`insertMany` returns its rows in the order they went in, by statement**: `WITH ORDINALITY … ORDER BY`, where it rested on an order Postgres does not promise. `EXPLAIN ANALYZE` over a thousand rows shows no sort.
- **`Store.open` answers `error.ShardTooLarge` when one shard's ring would pass 4 GiB**, where it answered `error.TooSmall` for a budget that was too big. A caller that matched `TooSmall` for this adds the new name; the fix is more `shards` or fewer `bytes`. `Store.registerSpace`, and so `Space.open`, is safe to call from several threads at once, and the cache's size-ceiling messages say eight ways to a bucket, not four.
- **`nilo_fetch`: a call with a body, sent on a pooled connection the server had closed while it idled, is dialled again instead of failing with `WriteFailed`.** A `putForm`, `postJson`, `put` or any call carrying a body as the first one after a quiet spell (a load balancer or nginx reaping the idle socket) failed every time against a server that closes after each answer; a `get` never did. The one retry that already covered a bodiless call now covers a write that failed with the peer gone (a reset or a broken pipe) on a connection taken from the pool, under the same bounds: a body that can be sent twice, the call's deadline, at most the pool's size in attempts, and never on a connection the call dialled itself. A `.stream` body still goes on a connection of its own ([ADR 058](docs/adr/058-most-of-an-s3-client-is-not-s3.md)).
