# Changelog

What changed between one tag and the next, not what changed between commits.
This file holds the release that has not been tagged yet;
[the releases page](https://github.com/nevindra/nilo/releases) holds the ones
that have, one page each. What was measured and what was got wrong on the way is
in [`docs/history.md`](./docs/history.md); what is coming is in
[`docs/roadmap.md`](./docs/roadmap.md), and what was refused or answered is in
[`docs/decided.md`](./docs/decided.md).

## Unreleased

### Breaking

- **`jobs.retryDead` returns `error.Scheduled` for a dead row of a scheduled kind**, and changes nothing. Reviving a dead tick ran the kind on two chains for good, because the successor was queued when the tick died. What to change: `Jobs.Error` gains `Scheduled`, so an exhaustive `switch` needs one more arm; a schedule that stopped is back through the re-seed, not through `retryDead`. A store of your own written against `job/contract.zig` takes the scheduled kinds as a fourth argument to `retryDead` and answers `error.Scheduled` for them (ADR 160).
- **An empty `.unique` is refused**: `error.EmptyUniqueKey` from `jobs.push` and from both stores, and a compile error when it is written `.unique = ""`. It deduplicated every push on `job.Table` and none on `job.Memory`, and an empty key is nearly always a missing value formatted into one. What to change: build the key from what identifies the row, or leave `.unique` out; `Jobs.Error` gains `EmptyUniqueKey`.
- **A store's `done` and `dead` take the time as a last argument**, `done(scope, id, attempts, now)` and `dead(scope, id, attempts, err, now)`, so `finished_at` follows the clock `drainAt` was given. What to change: only a store of your own written against `job/contract.zig`; `job.Enqueue` gains an optional `now`, which a store reads for `created_at` (ADR 160).
- **`Space.open` panics for a flat value no shard of the Store could hold**, naming the type, the limit and the Store's size, where the Space opened and every `put` was refused without a word, so `get` answered null. The limit is an entry (its 12-byte header, the key and the value) over a quarter of one shard's ring: a 20,000-byte struct on a 64 KiB store. Only a `V` that never worked is affected; what to change: open the Store with more `bytes` or fewer `shards`, or make the value smaller. `claimFlat` and `putFlatFor` also assert that a refusal is the key's doing (ADR 109).
- **`cache.OpenError` gains `SeedUnavailable`**, answered only when no `Options.seed` was given and the operating system had no entropy to give. A `switch` over the error set adds a prong.
- **`c.url` refuses a text value that is empty, `.` or `..` with `error.BadValue`**, which built `/u/../settings`, a URL a browser follows to `/settings`; percent-encoding cannot help, because a browser reads `%2E` as a dot. What to change: `url.into` gains `BadValue` in its error set, so a `switch` over it needs one more arm (ADR 100).
- **`Room.print` and `Room.json` return `error.WriteFailed` when their two formatting passes disagree**, where they panicked a safe build and sent uninitialised memory in `ReleaseFast`; the post is dropped. What to change: `Room.Error` gains `WriteFailed`, so an exhaustive `switch` needs one more arm (ADR 076).
- **A number in a JSON body is read by the same grammar as one in a query.** `5.0` and `1e2` for an integer field, `"1_0"`, `"+7"` and `"nan"` in a string token, and a value outside the field's type are a 400 naming the field, where std.json took some of them and panicked on a `u128` given `2e38`; a non-finite float is refused in a query and written to JSON as `null`. A client that sent any of these was relying on a defect (ADR 084, ADR 096).
- **A JSON body that repeats a key, an internally tagged union's discriminator included, is a 400**, where the union took the first of two (ADR 016).
- **A urlencoded form of more than 1,024 pairs is a 400**, which `form.max_pairs` names; a megabyte of `&` cost 33 MB of arena before (ADR 030).
- **An `Idempotency-Key` too long for the route's Space to hold is a 400 before the handler runs**, where it reached an `unreachable` (ADR 155).
- **`Ctx.send` returns `error.AlreadyAnswered` for a second answer**, where it asserted, which panicked a safe build and wrote two responses in `ReleaseFast`. What to change: a `switch` over its error set needs one more arm.
- **`c.peer()` returns `*const Peer`**, where it returned a `Peer` whose `address()` was a slice into a temporary. What to change: nothing at a call site that reads a field or calls a method; a variable typed `Peer` takes `.*`.
- **A `Body` read can fail with `error.BodyTruncated`**, a 400, when the connection ends while bytes are still owed, where `read`, `writeTo` and `discardRest` reported the clean end and a cut-short upload was stored as whole. What to change: an exhaustive `switch` over a `Body` error needs one more arm (ADR 083).
- **A middleware that returns without answering and without calling `next.run(c)` answers 500**, and the log names it (`middleware 2 of 3`), where it answered an empty 200 with the handler never run: a guard that forgot its 401 let the request through as a success. A handler returning nothing is still an empty 200. What to change: a middleware that stops the chain answers, with a fail function or `c.send` (ADR 008).
- **`c.stream`, `streamWith`, `events`, `eventsFrom`, `upgrade`, `upgradeWith` and `sendFile` return `error.AlreadyAnswered` for a request already answered**, as `send` does, where they asserted, which panicked a safe build and wrote a second response in `ReleaseFast`. What to change: an exhaustive `switch` over their errors needs one more arm.
- **A Space given to `Idempotent` needs `putIfAbsentFor(key, value, ttl_s)`** rather than `putIfAbsent`, so the in-flight marker gets a lifetime of its own. `cache.Space` has it; a hand-written Space adds the method (ADR 155).
- **The parser refuses what it used to pass on.** `Transfer-Encoding: gzip, chunked` is a 501, a target that does not begin with `/` (`admin:1/x`, `GET *`) is a 400, a `Host` that is not an authority (`evil.com/reset?x=`) is a 400, and a well-formed version nilo does not speak (`HTTP/2.0`) is a 505 where it was a 400. A client that sent any of these was relying on a defect (ADR 070, ADR 095).
- **A Postgres URL to a host that is not this machine, with no `sslmode`, requires TLS**, and a server that offers none refuses the connection at startup. It was plaintext. What to change: `?sslmode=disable` for a database you mean to reach unencrypted; `localhost`, `127.0.0.0/8`, `::1` and a unix socket are unchanged, and a Docker Compose service name such as `db` is not this machine ([ADR 241](./docs/adr/241-a-postgres-url-without-sslmode-is-encrypted-unless-it-stays-on-this-machine.md)).
- **`tcp_user_timeout` in a Postgres URL is refused**, because pg.zig cannot set it; `connect_timeout` is the bound it has (ADR 241).
- **`.across` with a negated operator does not compile.** `.not_icontains` over two columns kept a row one column matched; write one condition a column, joined the way you mean (ADR 172).
- **`.min` and `.max` over a `bool`, `Uuid`, `Bytes` or `Json` do not compile**, on either database, where Postgres refused them at run time.
- **A list column of `Timestamp`, `Date`, `Decimal`, `Bytes` or `Json` does not compile** where its Row is read, where pg.zig failed inside its own code.
- **`sql.Timestamp` and `sql.Date` are written to JSON between 0001-01-01 and 9999-12-31 or not at all**: outside that range the response is an error where it was `null` or text the parser refused, year 0 is refused as Postgres refuses it, and `Date.atMidnightUtc` answers `error.OutOfRange` (ADR 127).
- **A Dialect defines `introspect_all`, and a Wire `columnsOfMany` and `labelsOfMany`**, and `enum_values` takes its type names as an array: only a Dialect or Wire of your own changes.
- **On Postgres, a pool wait that runs out of `timeout_ms` is `error.TimedOut`**, where it was `Disconnected`, and `timeout_ms = 0` is no bound, as `wire.OpenOpts` always said; it failed the moment the pool was empty. A handler that branched on `Disconnected` for a full pool branches on `TimedOut` (ADR 107).
- **On SQLite, a version's `.sql` twin that rebuilds a table is stale**, because the twin now stops before `COMMIT` when `foreign_key_check` finds rows; `db check` names it, and `db generate` rewrites it (ADR 123).
- **On SQLite, `.gt`, `.gte`, `.lt`, `.lte`, `.order` (a run-time `sql.Ordering` key included), `.after`, and `sum`, `avg`, `min`, `max` over a `sql.Decimal` are Refusals.** The column is TEXT there, so `"100.00"` compared below `"9.99"` and a sum was added in floating point. Equality and `.in` are unchanged, and so is Postgres. What to change: store an integer of the smallest unit, or use Postgres (ADR 049).
- **An `.order` over a `Decimal`, `Interval` or `Inet` column, or an aggregate of one, sorts by the value on Postgres**, where it sorted the text the column is read as: `9.00` came before `100.5`, and a `db.feed` over one skipped and repeated rows. A plain select now answers such a column under the name `col#` (`"total"::text AS "total#"`); a shaped Row orders by the uncast expression. What to change: nothing, unless something reads a `…For` statement's columns by name (ADR 218).
- **The tiebreak a cut `.order` ends in runs the way its last named term runs**, so `.created_at = .desc` ends in `"id" DESC` where it ended in `"id" ASC`. A descending `db.feed`'s first page could order ties differently from the pages after it and repeat or lose rows at the boundary. A run-time `Ordering` keeps an ascending tiebreak, since `.after` refuses one (ADR 150).
- **A grouped Row with a parent, or with a field read `.through` a reference, groups by the referenced row's key as well as its columns**, so two customers named Acme are two rows where they were summed into one, and a page over a grouped Row ends in its group columns and those keys, where it had no tiebreak; a cursor over such a page carries one more term (ADR 218, ADR 150).
- **`db.insertOrIgnore` and `db.insertOrUpdate` refuse a conflict target the values written do not carry.** `ON CONFLICT ("id")` over values without `id` never conflicted, so every call inserted. What to change: write the target's columns, or name a target the values carry.
- **A list holding `null` given to `.in` or `.not_in` is a Refusal** (`&.{ 1, null }`, a `[]const ?T`). One null made `.not_in` select nothing and `.in` never matched a NULL row. What to change: take the null out of the list and add `.{ .tag = null }` under `.any` if NULL rows are wanted (ADR 040, ADR 052).
- **A `Timestamp` in JSON always carries six fractional digits**, `2026-08-16T09:30:00.700000Z`, where it was written to the second. A cursor handed back to `.after` lost its microseconds and skipped the rows later in that second. What to change: a client that matched the text exactly; any RFC 3339 reader takes both (ADR 127).
- **On Postgres, a migration step gives up after five seconds waiting for a table's lock**, with `error.Locked` and nothing kept, where it waited for as long as the transaction in its way stayed open, stalling every read and write to the table behind it. What to change: nothing for most versions; one that must wait longer sets `.lock_timeout_ms` on its `Version` (`0` waits for good). The number is not in the hash, so setting it on a version that already ran is not drift. The `.sql` twin sets it too (ADR 240).
- **Two schema mistakes are Refusals**: two tables giving an index the same `.name`, which planned and then failed the second `CREATE INDEX`, and a `.functions` entry whose name has capitals and is unquoted in its body, which Postgres keeps in lower case so nilo's `DROP FUNCTION` found nothing. What to change: give one index another name; write the function's name in lower case or in quotes (ADR 123).
- **On SQLite, only a version that drops a table runs with foreign keys off.** Every other version keeps them on, so a `DELETE` of a parent cascades as the schema says; it used to be refused at the COMMIT for the child it left. The `.sql` twin follows, so `db check` reports the twin of every SQLite version that drops no table stale until the next `db generate` writes it again (ADR 123).
- **A column added with `.default = .now` to a SQLite table that exists is a Problem in the plan**, and `addMissingColumns` answers `error.NeedsVersion` for one on a table with rows. SQLite refuses a default it works out per row on a table with rows, so the version failed at the deploy. What to change: add the field optional, fill it in a step, or write the rebuild the Problem spells out (ADR 123).
- **`migrate.Kind` has `.rename_index` and `.rename_constraint`, and `migrations.Error` has `SnapshotBehind`**, for a `switch` over either that is exhaustive. `generate` refuses a directory whose snapshot is older than its newest version file, which a run that stopped halfway leaves (ADR 123).
- **A Row or a raw read of a `u64`, a `usize`, an integer past 64 bits or a float other than `f32` and `f64` is a Refusal**, since neither database stores one; a list column holds `i16`, `i32`, `i64`, `f32` or `f64`. Each used to compile and fail at the first row, or inside pg.zig with its own message. Read a `u64` as `i64` (ADR 055).

- **A Wire's `Tx.commit` takes `(arena, problem)` and a Dialect's `offset` takes `(placeholder, limited)`**, for a Wire or Dialect written outside nilo. `commit` fills `problem` the way `run` does, since a deferred constraint is checked there; `offset` is told whether a `LIMIT` came first, since SQLite takes an `OFFSET` only after one.

- **A `sql.Timestamp` reads a Postgres `timestamptz` column and no longer a `timestamp` one.** A zoneless column moved `.now` by the session's zone: `now()` was stored as local wall time and read back as UTC, seven hours off under `Asia/Jakarta`, and `WHERE at < now()` compared it shifted the same way. `db.checking` and a raw statement's first-run check now refuse the column. What to change: `ALTER TABLE t ALTER COLUMN at TYPE timestamptz USING at AT TIME ZONE 'UTC'`, which keeps the values nilo wrote there; the refusal prints it with the names filled in (ADR 067).
- **On SQLite, a number is read only out of a number.** An integer or a bool field reading text or a REAL, and a float field reading text, is `error.QueryFailed` with a line naming the column, where it read 0, the REAL cut to an integer, or the year out of a `CURRENT_TIMESTAMP`. A bool is true for anything but 0, as `WHERE flag` says, where a 2 read false. What to change: a column holding the wrong class is written as its field's type, or read into a field that holds what it stores (ADR 067).
- **A `.sql` twin opens with a line that stops its shell at the first failed step**, `\set ON_ERROR_STOP on` for `psql` and `.bail on` for `sqlite3`. `sqlite3` used to carry on past a failed step and the `COMMIT` kept the steps that ran with the ledger row saying the whole version had, and `psql` rolled back and exited 0. The file is now a script for that shell rather than SQL a driver can send. What to change: run `db generate` once, since `db check` reports every existing twin stale until it has (ADR 123). ([reference](./docs/reference/sql.md#the-sql-twin), [guide](./docs/guide/sql/migrations.md#the-sql-twin-file))
- **An `update` or a `delete` whose `.like` or `.ilike` is only `%` is refused before it is sent**, as an empty `.not_in` list already was. Both bind the pattern as it is, so a search box's `%` matched every row with the column and a delete emptied the table. What to change: a call that meant every row says so with `db.raw` (ADR 149). ([guide](./docs/guide/sql/writing.md#update-and-delete-need-a-condition))
- **A negative `.limit` or `.offset` is refused before it is sent**, as `error.QueryFailed` with a line naming the field, on both databases. SQLite read `LIMIT -1` as no limit, so `?limit=-1` passed `@min(q.limit, 100)` and answered with the whole table; Postgres refused it itself. What to change: nothing, unless a SQLite call passed `-1` to mean every row, which is a `db.select` with no `.limit`.
- **A raw statement a test reaches may now fail it**, where a column's type is not the one the field reads or an outer join can leave it NULL in a field that is not optional (ADR 233). The message names the column and the fix. A Wire written outside this repository owes `describe(arena, sql, nulls)`, and answering null keeps it unchecked; a Dialect owes `reads`. ([reference](./docs/reference/sql.md#queries), [guide](./docs/guide/sql/raw.md#column-types-checked-the-first-time-it-runs))
- **An upsert's conflict target has to be the key or a declared `.unique`** on a table this program builds, and a unique that ignores case does not count. Both databases refused the others when the statement ran; now they do not compile. Declare the unique in the marker, or `.managed = false` for a table something else builds (ADR 151). ([reference](./docs/reference/sql.md#upserts), [guide](./docs/guide/sql/writing.md#upserts-insert-or-update))
- **`updateReturningOne` refuses a `.where` that could match more than one row.** It has to hold the key, or every column of a `.unique`, with `=`; other terms beside them are fine. It used to update every matching row and hand back the first. `updateReturning` is the call for a condition that means several (ADR 146). ([reference](./docs/reference/sql.md#rawone-updatereturningone-deletereturningone), [guide](./docs/guide/sql/writing.md#returning-the-changed-rows))
- **`generate --drop` names what it drops**: `--drop users.nickname,notes,extension:pgcrypto`. A bare `--drop` names nothing and writes nothing, and the refusal prints the command with the names filled in. `migrations.Options.allow_destructive` is gone, replaced by `.drop`, a list of the same names; `sql.cli.Request.allow_destructive` is `.drop` and `.drop_bare`. A field renamed without `.was` used to be dropped by the same flag as the column somebody meant to drop (ADR 123). ([reference](./docs/reference/sql.md#the-commands), [guide](./docs/guide/sql/migrations.md#dropping-data-needs-a-name))
- **A column type that does not widen is destructive, and has to be named with `--drop table.column`.** `int8` to `int4`, `float8` to `float4`, `numeric(10,2)` to `numeric(10,1)` and `timestamptz` to `timestamp` can refuse, round or reinterpret the rows already there; they were written like any other step. Widenings go through as before (ADR 123). ([reference](./docs/reference/sql.md#the-diff), [guide](./docs/guide/sql/migrations.md#dropping-data-needs-a-name))
- **`migrate.applyPending` refuses to apply anything when a version it already ran was edited**, `error.SchemaDrift`. It used to apply the versions after it on top. It also makes the ledger itself, so the `ensureLedger` call in front of it can go (ADR 123). ([reference](./docs/reference/sql.md#the-ledger-and-applying), [guide](./docs/guide/sql/migrations.md#applying-migrations))
- **On SQLite, a version runs with foreign keys off and checked once before its COMMIT**, through the new `wire.Begin.rebuilding`. The `DROP TABLE` of a table rebuild used to delete the old table's rows first and fire every `ON DELETE CASCADE` pointing at it, inside the version. A version that leaves a row pointing at nothing now answers `error.ForeignKeyViolated` and keeps nothing. A SQLite `.sql` twin carries the same pragmas, so `db check` reports every existing twin stale until the next `db generate` writes them again (ADR 123). ([reference](./docs/reference/sql.md#the-ledger-and-applying), [guide](./docs/guide/sql/migrations.md#applying-migrations))
- **`tx.commit()` on a transaction a failed statement aborted answers `error.QueryFailed` and rolls back**, on both databases. On Postgres it used to report success: the `COMMIT` came back tagged `ROLLBACK` with no error, so a handler that caught a statement's error without a savepoint and then committed answered 200 having kept nothing. SQLite, which keeps a transaction going after a failed statement, is held to the same rule, and every statement after the failure is refused until `sp.rollback()` on a savepoint taken before it. What to change: a statement whose failure a handler means to carry on past gets a savepoint around it (`var sp = try tx.savepoint();`, `sp.rollback()` in the `catch`), or becomes `insertOrIgnore` when the failure it expects is a duplicate (ADR 043, ADR 065). ([reference](./docs/reference/sql.md#errors), [guide](./docs/guide/sql/transactions.md#savepoints))
- **A serialization failure (`40001`) and a deadlock (`40P01`) are `error.RolledBack`**, new in `wire.Error`, where they were `QueryFailed`. It is the one error where running the whole transaction again is right, and a handler that lets it escape answers 503. What to change: a `switch` over `wire.Error` that is exhaustive gains an arm (ADR 117). ([reference](./docs/reference/sql.md#errors), [guide](./docs/guide/sql/transactions.md#retrying-a-rolled-back-transaction))
- **`error.Disconnected` answers 503 when a handler lets it escape**, where it answered 500. What to change: nothing, unless a test pinned the 500 (ADR 117). ([reference](./docs/reference/sql.md#errors), [guide](./docs/guide/sql/running.md#errors))
- **An `update` or a `delete` whose condition matches every row with the values it was handed is refused before it is sent**, as `error.QueryFailed` with a line naming the call. The two ways there are an empty `.not_in` list, `"id" <> ALL('{}')`, which is true of every row, and a pattern built from empty text, `.contains = ""`. A term that narrows beside either is sent as before. What to change: a call that meant every row says so with `db.raw` (ADR 149). ([reference](./docs/reference/sql.md#errors), [guide](./docs/guide/sql/writing.md#update-and-delete-need-a-condition))
- **`rawPage` and `rawPageOrdered` refuse an `OFFSET` nilo cannot set back to 0**: one written as a number other than 0, as arithmetic, or with a placeholder another clause also uses, values handed over as a named struct, and SQLite's `LIMIT a, b`. What to change: write `OFFSET $n` (`$n::int` is fine) and work the number out in Zig. It is what lets a page past its last row say its total (ADR 205). ([reference](./docs/reference/sql.md#queries), [guide](./docs/guide/sql/raw.md#a-paged-join-rawpage))
- **`Space.incr` and `Store.add` return `error.TooLarge` when the write is refused**, a key over 65,535 bytes or an entry over a quarter of a shard's ring, where they returned an uninitialised count: 0 in `ReleaseFast`, so `incr(email, 1) > 5` was a rate limit an oversized email walked through. What to change: `try` at each call (ADR 109).
- **An `s3.Bucket` call with an empty key is `error.Rejected`**, where `get("")` listed the bucket, `delete("")` was DeleteBucket, `put("")` was CreateBucket and `presign("")` signed a listing. `list` and a `presignPost` with `.prefix = true` still take `""` (ADR 059).
- **An `s3.Bucket` header value with a control byte is `error.Rejected`**: a byte under 0x20 other than tab, or 0x7f, in `content_type`, `cache_control`, `content_disposition` or `getIf`'s etag, which panicked a safe build in std's client and split the request in `ReleaseFast` (ADR 059).
- **A `session_token_max` above 2,048 does not compile**, where a token that long panicked `presign` (ADR 059).
- **A `job` store's `done`, `retry`, `dead` and `release` take the claim's `attempts` and answer `!bool`**, matching only a row still `running` under that claim, and a store has an eleventh method, `unkey`. A worker whose lease lapsed requeued, freed or killed the row a second worker held; now it does nothing and logs at `warn`. What to change: only a store of your own written against `job/contract.zig` (ADR 160).
- **A cron schedule whose day and month never meet does not compile** (`0 0 31 2 *`, `0 0 30 feb *`), where `next` looped for minutes and stalled the worker at seeding, and **a day field starting with `*`, `*/2` included, makes the day match both fields**, as Vixie cron does, where only a bare `*` did (ADR 161).
- **A cache entry lives at least its TTL and at most one second more.** Expiry counts whole seconds of a truncated clock, so an entry put at 5.99 s with `ttl_s = 1` was gone at 6.00, and an `incr` window could be a few milliseconds long, which let a client through a rate limit early. What to change: a test that waits exactly `ttl_s` for a miss waits `ttl_s + 1`. The clock still does not run while the machine is suspended (ADR 109).
- **`s3.open` refuses configuration that could never sign**: an empty key id or secret, an `expires_at` already past, a key id or session token too long, a key id or region holding `,`, `/`, a space or a control byte, and an endpoint authority over 255 bytes, as `error.BadCredentials`, `error.BadRegion` or `error.BadEndpoint`. Each opened and then answered 403 to every request, and the long endpoint panicked a safe build at the first `list` or `presign`. What to change: an exhaustive `switch` over `OpenError` gains `BadCredentials` (ADR 060).
- **`list` answers `error.Failed` for a page marked truncated with no usable continuation token**: missing, empty, or over 1,024 bytes. A missing one ended the caller's loop as though the bucket had been read to the end, which a backup or a cleanup cannot tell from success; an empty one came back as a 400 on the next page. What to change: nothing against a server that follows the protocol (ADR 058).
- **A row pushed with `jobs.pushIn` has no status until a worker takes it.** `pushIn` wrote `queued` into the `status` Space before the caller's transaction committed, so a rollback left a status for a row that never existed. What to change: a route that polls `status(id)` straight after `pushIn` reads `null` as not started yet (ADR 160).
- **`push(.within)` needs a window with `del` as well as `putIfAbsent`**, and a `cache.Space` has both. A push the store refused (`QueueFull`, a database error) held the window for its whole length with nothing queued, so every retry inside it answered `null`; the window is given back now. What to change: a hand-written window type adds `del` (ADR 160).

- **A WebSocket can sit in more than one `Room`**, and `error.AlreadySeated` is gone from `nilo.Room.Error`. Joining a second room used to be refused; it is now a seat in each, drained by the same `receive`, and `leave` gives up one room and keeps the rest. What to change: a `switch` on the error that names `error.AlreadySeated` drops that arm. `Socket.ticket()`, `inRoom()`, `seatedIn()` and `unseat()`, which were public for the Room's use, are replaced by `seating()` and `leaveRooms()`, and `room.Ticket.index` is a `u32` (ADR 035). ([reference](./docs/reference/streaming.md#several-rooms), [guide](./docs/guide/websocket.md#broadcasting-with-niloroom))
- **The session cookie is `__Host-session` wherever the prefix can hold** (`Secure`, `Path=/`, no `Domain`, the defaults), and that name is read before `session`. A sibling subdomain could plant a `session` cookie of its own under a path of this site, and the victim worked inside the attacker's account; a visitor with no prefixed cookie opened the planted one wherever it was sent, so `session` is now read only with `listen(.{ .session_plain_name = true })`. What to change: `app.guard(…, "session")` becomes `app.guard(…, nilo.session.host_cookie_name)`, and a test or a client that reads the cookie by name reads the new one. A program upgrading from 0.6.0 passes `.session_plain_name = true` for as long as its longest `max_age`, so nobody is signed out and each visitor's next `set` moves them. A session with a `domain`, another `path` or `secure = false` keeps the plain name and needs the same option, or its `set` fails with a message naming it (ADR 033). ([reference](./docs/reference/ctx.md#the-cookie-name), [guide](./docs/guide/sessions.md#the-__host--cookie-name))

### Added

- **`bucket.putMultipart(c, key, .{ .reader, .content_type })`**: S3's multipart upload as one call, for a reader of unknown length or an object too large for one PUT. Parts of `.part_bytes` (8 MiB default; under S3's 5 MiB floor is `error.Rejected` before a byte moves), a completion whose 200 is checked against its body because S3 can answer one with an error inside, an abort on the way out of any failure so parked parts are not left paid for, and S3's 10,000-part ceiling answered with the fix named rather than the server's refusal. A source that ends inside the first part becomes a plain `put` (one round trip, the content's own MD5 as the ETag); each part and the completion run under the source's optional `.timeout_ms` and the Store's `stall_ms`, the terms `putStream` sets, and `.cache_control`/`.content_disposition` are read off the source. Costs one `part_bytes` buffer, an ETag copy per part and the completion document in the Scope; holds one stream share for its whole life (ADR 058).

- **`cache.Options.seed`, and every hash in a Store is mixed with a secret**: `null`, the default, takes 8 bytes from the operating system once in `open` (`getrandom` on Linux, `arc4random_buf` on macOS), so keys an attacker chooses can no longer be precomputed into one shard and one bucket to evict a chosen entry or queue every request on one lock. A caller with a loop may pass one from `nilo.randomSecure`, and a test passes a fixed one so placement is deterministic; a fixed seed in production restores the old exposure. Nothing to change for a caller that passes nothing. It costs no extra hash pass and no extra cache line. On a target with neither source `open` returns `error.SeedUnavailable` unless `seed` is given, never a guessable seed (ADR 042, ADR 109).
- **`s3.Options.stall_ms`, `max_streams` and `fetch_timeout_ms`**, with a `timeout_ms` on a `Reading` and on a streamed put's source. `stall_ms` (30 s) is how long `stream` or `putStream` may move no bytes before `TimedOut`; `max_streams` (half of `max_in_flight`, at least one) is how many streaming calls may be open at once; `fetch_timeout_ms` (10 s, `0` for none) is how long a credential `fetch` may take. `open` refuses a `max_streams` over `max_in_flight` with `error.BadStreams`, which `OpenError` gains (ADR 060).

- **`.istarts_with` on SQLite uses a unique with `.ignoring_case`**, `SEARCH` where it was `SCAN`: 12 µs against 16.5 ms on 200,000 rows. The prefix is escaped in Zig and bound whole, one arena allocation per condition; the statement and the rows it matches are otherwise unchanged. Postgres is unchanged, since it already used the index (ADR 140).

([reference](./docs/reference/sql.md#dbfeed), [guide](./docs/guide/sql/reading.md#keyset-pagination-for-deep-pages))

### Changed

- **`s3` `stream` and `putStream` are no longer cut at the Store's `timeout_ms`**: they send no whole-call limit and stop on `stall_ms` of silence instead, and a call that wants a ceiling sets one (`var r: Files.Reading = .{ .timeout_ms = … }`, `.timeout_ms` on the put's source). They also share `max_streams` slots, so a program that held more than half of its `max_in_flight` permits in streams at once now waits for a slot: raise `max_streams` for it. `get`, `head`, `list`, `put` and `delete` keep the 30 s limit (ADR 060).
- **`app.compress` leaves a body over 1 MiB uncompressed**, `compress.Options.max_bytes`, because gzip holds the executor thread for the whole body: about 7 ms a megabyte on the machine measured, 130 ms for 20 MB. `0` lifts the limit (ADR 211, [`http.md`](bench/result/http.md)).
- **A `tryRoute` that is refused logs its one line at `warn`**, not `err`, since the caller asked for the error back; `route`, which stops the process, still says it at `err` (ADR 008).
- **A statement holding a `sql.given` is sent without the terms the call left out**, so SQLite uses the index again (29.4 ms to an index search on 500,000 rows) and Postgres keeps one named plan a combination of given values, up to three, where it parsed every call ([ADR 149](./docs/adr/149-a-filter-that-is-absent-is-not-a-filter-that-is-null.md), [sql.md §25](./bench/result/sql.md#25-a-guard-cut-out-of-the-text-per-call)).
- **`pgbouncer=true` or `pool_mode=transaction` in a Postgres URL turns prepared statements off**, and a `26000` from a pooler is prepared again once rather than failing every call (ADR 241).
- **The startup check asks the catalog once a schema, plus once for every enum**, where it asked once a Row and once an enum column: 26.7 ms to 7.7 ms for 50 tables on Postgres; `db status` and `db migrate` read the ledger once ([sql.md §24](./bench/result/sql.md#24-the-startup-check-and-the-ledger-ask-once)).
- **On SQLite, `createMissing` remakes a view or trigger whose text changed and sends no DDL when none did**, where a changed one was never updated (ADR 181).
- **A rebuilding version checks the foreign keys of the tables it dropped and the rows pointing at them**, on SQLite and in its `.sql` twin, where an old violation anywhere failed every rebuild (ADR 123).
- **`insertMany` and `updateMany` over an empty slice send nothing.**
- **`db.raw` refuses a gap in its placeholders**, `$1, $3` with three values, and holds SQLite's `?n` the same way, as ADR 204 said it did.
- **A Postgres statement that holds a `sql.given` is sent unnamed**, so each call is planned for its own values: once the kept plan went generic, a call with the filter read the whole table, 115 ms against 0.27 ms on 500,000 rows. It costs one Parse a call; a statement with nothing that can drop keeps its name. On SQLite such a statement still scans, and the reference says so ([ADR 149](./docs/adr/149-a-filter-that-is-absent-is-not-a-filter-that-is-null.md), [sql.md §22](./bench/result/sql.md#22-a-guard-and-the-plan-a-kept-statement-settles-on)).
- **`istarts_with` on Postgres is `lower(col) LIKE lower($1) || '%'`, and a case-folding unique is built over `lower(col) text_pattern_ops`**, so the prefix reads the unique as a range: 266 ms to 0.065 ms on 200,000 rows. What to change: a case-folding unique made before this keeps its old index and the prefix still scans until it is dropped and made again (ADR 140, [sql.md §23](./bench/result/sql.md#23-istarts_with-on-postgres-and-the-expression-it-reads)).
- **On SQLite, a required column with no default is a Problem at `db generate` and `db check`**, naming the rebuild, where it was a step that failed on the deploy against a table with rows (ADR 123).
- **`db check` fails on a version file the manifest lost, a manifest entry with no file, a `.name` that is not its file's, a duplicate number, and a snapshot ahead of or behind the newest version**, through `migrations.audit` (ADR 123).
- **An order a `.limit` or an `.offset` cuts ends in the table's key**, ascending, when it does not name the key already: on `db.page` and `db.one` always, and on `db.select` and `db.stream` with either field. Rows the order ties came back in a different order at each `OFFSET`, and a thousand rows paged by 25 over ten values showed 179 twice and 179 never. It costs the size of the tie group a page lands in where the index covered only the order column; an index ending in the key, `(status, id)`, takes it back ([ADR 150](./docs/adr/150-a-page-knows-what-it-left-out.md#a-page-ends-in-the-key), [sql.md §19](./bench/result/sql.md#19-the-key-a-cut-order-ends-in)). An order chosen by an `sql.Ordering` ends in the key the same way, after the terms the request chose, unless one of them already orders by it. What to change: nothing, unless a test pinned the statement's text. ([reference](./docs/reference/sql.md#options), [guide](./docs/guide/sql/reading.md))
- **A gRPC call runs on its connection's thread** rather than the next one round-robin, which sent nearly every call to another thread and its answer back: 2.7x the unary calls a second at 256 connections, and the worst call at 52 ms rather than 1.5 s (ADR 220).
- **zio is pinned at `0299e57` on its `main`**, for `spawnInto` and the fix below, and built with its tasks pinned to the thread they start on through zio's own build option (ADR 199). Nothing to change in an application. One that also depends on zio itself passes `.scheduling = .pinned` to its own `b.dependency("zio", …)` as well, or it builds a second, differently configured zio beside nilo's. A stripped binary is 6.9 KB larger (ADR 017).
- **A cached Postgres statement takes one round trip rather than two.** pg.zig is pinned at `lalinsky/pg.zig@2bc3405`, whose `master` carries two fixes from karlseguin's: a cached statement no longer sends a `Sync` of its own and waits before Bind and Execute, 2.1–3.1 µs off every query over a unix socket and about three times that through a Docker port; and `startup_parameters` now reach the server. Nothing to change in an application ([`sql.md` §16](bench/result/sql.md#16-the-round-trip-pgzig-wasted-taken-back)). ([reference](./docs/reference/sql.md#prepared-statements), [guide](./docs/guide/sql/running.md#prepared-statements))

### Fixed

- **A job whose run is waiting on the database when the server stops goes back to the queue.** nilo_sql answers a statement a cancellation cut off with `QueryFailed` (ADR 223), and the worker only handed a row back on `error.Canceled`: it wrote the run off as a failed attempt instead, in a store call the same cancellation stopped, and the row stayed `running` until its lease ran out, which is the longest `timeout_ms` of any kind. The worker now asks the fiber whether it was cancelled, and what it writes about a row after a run cannot be interrupted, so a run that finished just before the shutdown is `done` too. A worker cut off in its claim no longer logs `claim: QueryFailed` (ADR 243).
- **`job.Table` wrote `created_at` as the row's `run_at` and `finished_at` from the wall clock.** `created_at` is now the time of the push and `finished_at` the clock `drainAt` runs under, so a test that moves the clock sees the times it moved to. `job.Memory` keeps no finished row and is unchanged (ADR 160).
- **A streamed body is no longer sent on a pooled connection**, so the first `putStream` or `Exchange` with a `.stream` body after an idle gap cannot meet a connection the server closed, consume the reader and fail. It opens a connection of its own and closes it after: one handshake per streamed body, and calls with a slice or no body are unchanged. `stall_ms` now counts each chunk the source hands over as progress while a body goes out, which it did not, so an upload longer than `stall_ms` would have been `Stalled` however fast it moved (ADR 058, ADR 056).
- **A credential `fetch` that hangs no longer holds up every request.** The Store cancels it at `fetch_timeout_ms` and counts that as a failed fetch: the credentials in hand keep signing, and once they expire the requests get `error.CredentialsTimedOut` (a `Bucket` call answers `TimedOut`) instead of waiting for it. Cancellation lands at the function's next `Io` call, so a `fetch` should pass its `io` on to what it calls (ADR 060).
- **A WebSocket message that starts with an empty fragment and pauses no longer lands in a buffer already given back.** The quiet spell returned the message buffer to the executor's free list while `receive` still held it, and the next fragment was written into memory another connection could own. Unauthenticated, on any WebSocket route.
- **`useOn` covers a route whose pattern has a `:param` or `*` where its prefix has a word.** `useOn("/files/private", auth)` beside `GET /files/*` served `/files/private/x` without `auth`; such a route's chain is now resolved per request from the real path, with a percent-escaped segment read as it decodes (ADR 008).
- **A `Bound(T)` body whose `Patch(Enum)` field is not one of the choices answers 422**, where one request panicked the process.
- **A non-exhaustive enum holding a value no field names is written to JSON as its number**, where writing it panicked (ADR 096).
- **A stop no longer waits on keep-alive connections that are only waiting for their next request**, which it did for up to twice `idle_timeout_ms`; a WebSocket parked when the stop comes is sent its 1001. The listener closes as soon as the server stops accepting rather than at the end of the grace period, a connection-level error from `accept` is retried rather than stopping the server, and a listener that fails still drains the requests it took (ADR 194, ADR 046).
- **A WebSocket route that names a subprotocol negotiates it.** The answer is the first protocol in the client's `Sec-WebSocket-Protocol` that `Options.protocol` or the new `Options.protocols` lists, and none otherwise, so a plain `new WebSocket(url)` and a client offering two protocols both connect. A `Sec-WebSocket-Key` that is not 16 bytes of base64 is a 400, and a malformed close frame no longer reports `closedCleanly()` (ADR 046).
- **WebSocket frames and headers are read as RFC 6455 says.** A length in a wider form than it needs, or a 64-bit length with its top bit set, is a 1002; `Socket.ping` cuts its data to 125 bytes; `Connection` is read as a token list, so `Upgrade-Insecure` is not an upgrade; and a room post and a direct `socket.send` leave in the order they were made (ADR 046).
- **A gRPC call cancelled while its message was still arriving no longer holds back the calls beside it.** Its bytes stayed counted against the connection's budget, so once the budget was passed only the oldest call was given more window; they are given back at the reset (ADR 220).
- **A gRPC listener answers requests as RFC 9113 and the gRPC spec say.** `application/grpc-web` is a 415 rather than a native call; a duplicate, unknown or late pseudo-header and a missing `:scheme` reset the stream with `PROTOCOL_ERROR`; a request with both `:authority` and `host` is served, `:authority` winning; `grpc-timeout` counts from when the headers arrived; a malformed call no longer restarts the flood count and empty DATA to a call nothing is collecting is counted; and a `SETTINGS_INITIAL_WINDOW_SIZE` that would lift a send window past 2^31-1 is a `FLOW_CONTROL_ERROR` (ADR 220).
- **An HTTP/1.0 request carrying `Transfer-Encoding` is answered and the connection closed, and one empty line before the request line is skipped** rather than refused (RFC 9112, ADR 070).
- **`OPTIONS *` is answered as a server-wide OPTIONS and never matched to a root `/*`**, and the `Allow` on an OPTIONS 204 names OPTIONS (ADR 095).
- **A status line always carries its reason phrase.** `fail.status(502, …)` went out as `HTTP/1.1 502 `; one table now covers every registered status and the static answers are built from it (ADR 070).
- **A chunked body is committed a page at a time.** A chunk that announced eight megabytes and sent nothing held eight megabytes of arena; each chunk now takes a page first and the rest once it arrives (ADR 083).
- **The text log no longer writes a request path's control bytes as they came.** Control bytes and DEL are written as `\xNN` in the `.text` format, the request id too, so a path cannot steer a terminal or overwrite a line; `.json` already escaped them.
- **A `*` route matches a path deeper than sixteen segments.** `/files/*` and a root `/*` fallback were a 404 past sixteen segments; the rest of the path now goes to the `*`, for matching and for the 405 `Allow` set alike (ADR 012).
- **A body of any size no longer overflows the body deadline.** `armBodyRun` saturates, so `bodyStreamWith(.{ .max_bytes = maxInt(u64) })` gets the longest deadline rather than a panic or a wrapped, tiny one.
- **An IPv6 client with a long tail after `::` gets its own allowance key.** `2001:db8::1:2:3:4` and `2001:db8::1:2:5:6` shared one above a /64, because the overlapping tail was copied forward.
- **A request body the client cut short is a 400 that closes the connection**, where `Content-Length: 100` and ten bytes answered 500 and logged a warning; a gzip body that fails to inflate is refused again on a second `c.body()` rather than handed over still compressed (ADR 019, ADR 089).
- **A JSON body that fails to parse is no longer read again to its full depth.** Describing the failure parsed the body a second time as a `std.json.Value`, so a megabyte of `[` to a plain struct route took 174 MB of arena; the depth check now runs first, and the same body takes 1 MB (ADR 226).
- **A multipart body costs CPU in proportion to its size, not parts times size.** The search for a part's blank line walks once; 255 parts and a megabyte of padding took 4.8 s in Debug and take 2 ms.
- **A `Cached` answer that sets a cookie is sent and not kept**, with a `warn`, where the first visitor's `Set-Cookie` was replayed to everybody for the TTL; and a failure after the claim releases the marker rather than leaving every request to wait out the cap (ADR 188).
- **`c.stream` and `streamWith` under 204, 304 or a 1xx are a 500 naming the mistake**, where they wrote a framing header the head then dropped, so the next response started inside the stream.
- **A failure no longer carries the headers that described the answer it replaced.** A handler that set `Content-Encoding: gzip` and a year of `Cache-Control` and then failed sent a JSON 409 labelled gzip and cacheable for a year; `Content-Encoding`, `ETag`, `Last-Modified`, `Content-Range`, `Content-Disposition`, `Location`, `Expires` and a `Cache-Control` without `no-store` are dropped, and CORS, cookies and the application's own headers still go out (ADR 024).
- **An `Idempotent` replay carries every header the handler set through the `*Ctx`**, a session's `Set-Cookie` included, where only a `Response(T)`'s own were kept. The in-flight marker lasts two minutes whatever the Space's TTL, so a crash mid-handler no longer answers 409 for the whole TTL, and a request that fails before its handler (a body that does not parse, a `Bound` 422, an `Authorization` 401) releases its claim, so the corrected retry runs (ADR 155).
- **A `Cached` or `Idempotent` answer with a header `setHeader` refuses is not kept**, where every hit replayed its 500 until the TTL ran out (ADR 188, ADR 155).
- **`Versioned(T)` answers 304 only to a GET or a HEAD**; a `PUT` with a matching `If-None-Match` gets its ordinary answer, and the document lists the 304 for those two methods only (ADR 189).
- **A refused `tryRoute` registers nothing.** Under `without(m)` or `with(m)` a `DuplicateRoute` exempted the route already there from `m`, or attached `m` to it, and a `DuplicateName` left the route live and out of the document (ADR 008).
- **A route's `nilo.deadline(ms)` bounds the answer's writes when it is nearer than `write_timeout_ms`**, so a two-second route no longer waits thirty seconds on a client that reads nothing, and the write limit is armed again before every request on a connection (ADR 105).
- **`app.compress` leaves a 206, a 416, an answer with a `Content-Range` or one with `Cache-Control: no-transform` as the handler wrote it, and weakens a strong `ETag` on an answer it compresses** (ADR 211).
- **A gRPC connection counts a call's message against its budget until the answer is written**, the inflated and request-text copies included, and holds the oldest arriving call back while a started one still holds bytes, so a hundred calls to a slow route no longer hold a hundred messages; an answer is held once rather than twice; and a header block still unfinished when its call's time to arrive is up sends the connection away (ADR 220).
- **`FileBody` no longer leaks a descriptor when a header is refused**, such as a `Content-Disposition` with a CR in it.
- **A SIGTERM after `app.shutdown()` gets the grace period.** The handler read the flag `shutdown()` also sets, so the first signal exited at once; it has a flag of its own now, and ends the process with `_exit`, which is safe inside a signal handler.
- **`db.raw` runs statements its reader used to refuse**: a trailing comment or `;`, `IS DISTINCT FROM`, `a * b`, `ID` for `id`, `$$…$$` and `E'\''`, nested comments, `EXCEPT` and `INTERSECT`, `p.offset` and SQLite's backticks. One tokenizer reads the statement once, and a statement it cannot read is passed to the first-run check rather than refused (ADR 204).
- **`Composed` refuses `?n` in its text and a gap in its placeholders**, `sql.given` on `not_distinct_from` answers ADR 149's sentence, and SQLite's `LIKE` no longer rewrites a column whose name holds `ILIKE`.
- **A parent named like its table is refused for a table with a schema too.**
- **A `Timestamp` before 1970 is written to JSON**, where it was `null`.
- **On SQLite**: a `float8` read into an `f32` is refused when the value does not survive the narrowing; a value refused before binding no longer aborts the transaction; `db.exec` of a statement that is not DML answers 0; `db.rawExplain` no longer takes the writer, so a handler holding a `tx` does not wait on itself; a pool that fails to open is reported once, in SQLite's words.
- **A failed `Savepoint.release` leaves the savepoint to roll back to**, a transaction's savepoints live in the request arena rather than an allocation of their own, and a child statement that fails is told to the watcher.
- **`checkSchema` logs at `warn` when a mismatch is not fatal**, where `err` failed any test that reached it.
- **The startup check no longer refuses correct tables.** On SQLite it compares the column's affinity, so `VARCHAR(255)` under a `Str`, `DATE` under a `Date`, `UUID` under a `Uuid` and a column with no type pass; on Postgres a domain is read as the type under it, and `citext` is accepted where `text` is (ADR 055).
- **`.after` over a `Date`, `Decimal`, `Interval`, `Inet` or `Bytes` binds through its cast**, where a feed failed from its second page on Postgres.
- **On SQLite, the readiness probe runs on a reader**, so `/healthz` stays 200 while a long write holds the writer (ADR 107).
- **A fiber cancelled while it waits for a SQLite connection keeps its cancellation** and answers `Disconnected`, where it was told `TimedOut` and a background loop did not exit at shutdown (ADR 223).
- **A `password` or `sslpassword` given as a URL query parameter is masked in the log**, whatever its case or escaping.
- **A `Json(T)` column reads a document carrying a field `T` lacks**, where a rolling deploy that added a field made every old instance answer `QueryFailed` (ADR 067).
- **An index redefined over a column that is dropped goes before the column and comes back after it**, where the version failed on both databases (ADR 123).
- **Renaming an enum column with `.was` renames its check on Postgres**, where the next change to its words failed on a constraint that was not there (ADR 123).
- **`createMissing` and `addMissingColumns` take the advisory lock and the five-second `lock_timeout` `apply` takes, and read the table through their own transaction**, so replicas booting together do not race and a pool of one is enough (ADR 240).
- **An array column whose element type the field cannot hold, or an enum list with a label the enum lacks, is `error.QueryFailed`**, where pg.zig panicked and took the process down, empty arrays included.
- **A second `tx.commit()` after a refused one returns `error.QueryFailed`**, where it reported success for work that was never kept.
- **`Streamed.next()` after `close()` answers null, and a copy of the handle can no longer read or close a result its sibling closed**, where both read freed memory (ADR 093).
- **On SQLite, a second statement in one call is refused in every build**, where a release build ran the first and dropped the rest without a word.
- **On SQLite, children keyed by a `Bytes` column are found**, where every parent came back with an empty list.
- **`db.count` over a Row with a field `.through` a reference that cannot be null keeps the inner join**, so a page's total matches its rows.
- **`db status` and `db migrate` no longer panic on a ledger hash shorter than sixteen bytes.**
- **`sql.problem` and `sql.violated` answer null on the request after the one that failed**, where the next request on the same keep-alive connection that sent no statement read the earlier Problem out of memory its arena had handed back. The Scope's serial is compared now; `Ctx`, `Run` and `AnyScope` each gained a `serial()` that nilo reads through `core.serialOf` (ADR 117).
- **A Postgres URL may carry `options` and `client_encoding=UTF8`**, where both were refused and the server would not start. `options` rides in every connection's startup message, so `?options=-c%20statement_timeout%3D30s` bounds every statement of the pool and Neon's `options=endpoint%3D…` is read. An encoding other than UTF-8 is still refused, because every `Str` is UTF-8 (ADR 239).
- **A Postgres stream closed early gives its connection back in tens of milliseconds, whatever was left of its result.** It read the whole rest off the socket first: 178 to 313 ms for a stream closed after the first of 200,000 rows. Past 1 MiB of the rest the connection is now replaced, and an `info` line says so; inside a transaction the rest is still read whole (ADR 238).
- **A generated migration runs where it used to fail on Postgres's own error.** Two tables dropped in one change go child first. A check or a trigger over a dropped column goes before the column. A view over a column that is dropped, renamed or retyped, and a view reading that view, comes down before the change and goes back up after, and views are made in the order they read each other rather than the order listed. An index, unique or foreign key over a column `.was` renamed is renamed with it on Postgres, where the key was refused as new and the index rebuilt (ADR 123).
- **`createMissing` then `addMissingColumns` is the boot order again when a new field has a unique or an index.** `createMissing` sent the `CREATE INDEX` before the column existed: Postgres refused it, and SQLite indexed the constant string and refused the second row. The index now waits for `addMissingColumns` (ADR 123).
- **An enum whose tags only moved plans nothing**, where it dropped and remade its check; a tag holding `'` is written with the quote doubled; a text column becoming an enum is flagged as a backfill; version `10000_x.zig` is read back (ADR 123).
- **A Postgres number column reads into a field of another width**, range-checked: an `i32` over `int8`, a `u8` over `int2`, an `f64` over `float4`. The schema check accepted each and every read answered `QueryFailed`, and a `u16` or an `i8` did not compile inside pg.zig. A value past the field is `error.QueryFailed` naming the column. `db.raw`'s first-run check takes a column as wide as the field or narrower (ADR 233).
- **A Postgres connection the server closed or reset while it sat in the pool is replaced before it is used**, where it failed the next statement sent down it: after a restart or a failover, every idle connection cost one request a 5xx. One `poll` per acquire; a statement is never sent twice (ADR 237).
- **`tx.deadline(0)` times the next statement out**, where it sent `statement_timeout = 0`, which Postgres reads as no limit. A number past `maxInt(i32)` is sent as `maxInt(i32)` rather than aborting the transaction with Postgres's range error (ADR 043).
- **`.in` and `.not_in` over a `sql.Timestamp`, `sql.Date`, `sql.Decimal` or `sql.Bytes` column compile on Postgres and match on SQLite.** Each element is bound the way one value of the column is; a date or decimal list is cast through `text[]`. On SQLite a list of bytes compiled and matched nothing.
- **`.offset` with no `.limit` runs on SQLite**, written `LIMIT -1 OFFSET …`, where it was a syntax error there and a working statement on Postgres.
- **`sql.problem` answers for the call just made.** A call refused before it was sent (a condition that narrows nothing, a negative `.limit`, no pool, a raw statement its check refused) left the previous statement's problem in place, so `sql.violated` could name a unique the call never met. A failed step on a one-column read or a stream now reaches `sql.problem` and the watcher, and a COMMIT a deferred constraint refuses records which key it was (ADR 117).
- **A raw statement whose first run could not be described is described again on its next run.** A first run that met a table a migration had not made yet switched the check off for the life of the process (ADR 233).
- **`db.count`, `db.exists` and an empty page's total agree with the list when a required parent's row is missing.** The list's inner join left the row out and the count counted it; the count now joins every required parent (ADR 218).
- **A failed rollback, a savepoint that could not be rolled back to, and `migrate.expect`'s refusal log at `warn`**, where `err` failed any test that reached them. `migrate.expect` still returns `SchemaBehind`, which is what stops the process.

- **An `infinity` or `-infinity` in a Postgres `timestamptz` or `date` column is `error.QueryFailed`**, with a line that names it, where `'infinity'::timestamptz` overflowed inside pg.zig and took the process down and `'-infinity'` read as a moment 292,000 years ago. NULL is how nilo reads an open end (ADR 067).
- **A savepoint an outer rollback ended stays ended after a newer one is taken.** Its `defer` sent `ROLLBACK TO` a mark Postgres had already dropped, which aborted the transaction and failed its `commit` (ADR 048).
- **`migrate.addMissingColumns` adds a column with its foreign key, and its uniques and indexes after it.** An insert pointing at a parent that did not exist was taken for ever. A new column in a foreign key of several columns on SQLite is `error.NeedsVersion`, since SQLite writes one only with its table (ADR 123).
- **The cast check on a raw statement sees through `DISTINCT`, `DISTINCT ON (…)`, `ALL` and comments**, so `SELECT DISTINCT total` into a `Decimal` is refused like `SELECT total`, where it filled the field with Postgres's binary `numeric` (ADR 124).
- **A NaN bound on SQLite is `error.QueryFailed`** before it is sent, where SQLite stored it as NULL: `NotNullViolated` on a NOT NULL column, and `null` read back from a nullable one (ADR 067).
- **A `u64` or `usize` past `maxInt(i64)` bound on SQLite answers `error.QueryFailed`** where it panicked in Debug and ReleaseSafe and was undefined in ReleaseFast: zqlite binds an integer with `@intCast`, and `?offset=9223372036854775808` read into a `usize` took the server down. Postgres already answered.
- **A Postgres `text[]` read as `[]const ?Str` or `[]const ?[]const u8` keeps its text** after the statement. pg.zig copies an element only when it is exactly `[]const u8`, so each element pointed into the connection's read buffer and read whatever the next statements left there.
- **An aggregate's `.where` takes a value of the column's own enum**, so `.not_in = &finished` with `finished` a `[_]Category` reads as `.not_in = .{ .done, .cancelled }` does. - **A page past its last row answers its real total**, where it answered 0: `db.page` and `tx.page` send one `db.count` with the page's `.where` when a page that skipped rows comes back empty, and `rawPage` and `rawPageOrdered` ask the same statement again from its first row (ADR 150, ADR 205). - **An order term that says where NULLs go compiles on a shaped Row**, through a parent and on an aggregate; it failed inside `shape.zig` (ADR 218). ([reference](./docs/reference/sql.md#a-parent-children-a-group), [guide](./docs/guide/sql/shapes.md#joining-a-parent-row))
- **A statement whose prepared plan a migration made stale runs, rather than failing on every connection until the pool replaces it.** A column's type changed under a running server made Postgres refuse each kept plan with `0A000`. Outside a transaction the plan is deallocated and the statement sent again; inside one the answer is `error.RolledBack` and the next attempt prepares it fresh (ADR 051). - **A `COMMIT` is not cut off by a cancellation**, so its outcome is always known: it used to be able to answer `QueryFailed` for a transaction that had landed (ADR 223). ([guide](./docs/guide/sql/transactions.md#giving-a-statement-a-deadline))
- **A statement sent into an aborted Postgres transaction is answered `25P02` instead of destroying the connection**, and costs no reconnect (ADR 043). ([reference](./docs/reference/sql.md#errors), [guide](./docs/guide/sql/transactions.md#savepoints))

- **A cache TTL near `maxInt(u32)` saturates**, where it panicked a safe build and wrapped in `ReleaseFast` to an entry already expired.
- **An `incr` counter survives churn.** A counter is never read, so it stayed in the doorkeeper and restarted at zero each time unrelated writes lapped it; a second `incr` that finds it there now promotes it (ADR 109).
- **A failed S3 credential refresh fails nobody while the credentials in hand are still valid.** It failed every request for the whole 300-second margin; now the old key signs until `expires_at`, one fiber refreshes while the others sign, a failed fetch is tried again after 5 seconds, and credentials that live less than the margin are refreshed at half their life rather than on every request. `Source.fetch`'s strings only have to outlive the call: the Store copies them and frees nothing of the caller's (ADR 060).
- **A static file whose name has a space or a non-ASCII character is served at the URL a browser sends for it**, where `/caf%C3%A9.png` and `/My%20Doc.pdf` were a 404. A path that decodes to a `/`, a NUL, a backslash or a `.` or `..` segment, or holds a malformed escape, names no file; a name with a literal `%` is reached as `%25`. A path with no `%` in it is compared as it was (ADR 009). ([guide](./docs/guide/static-files.md))
- **A spilled or `.reload` static file swapped for a symlink after startup answers 404**, where the open followed the link out of the tree and served what it pointed at. Symlinks were already left out of the table at load; they are now named there in one `warn` line. `FileBody` from a handler still follows links (ADR 009).
- **A failure body is JSON whatever bytes its message holds.** `GET /items?page=%ff` against an integer `page` answered a body `res.json()` throws on, and an application's own failure shape got the message as an array of numbers. A byte that is not UTF-8 is written as U+FFFD, and a message cut at its length limit is cut between characters (ADR 024, ADR 096).
- **A failure a handler caught no longer decides the answer to a different error it returns later.** A handler that caught a `fail.notFound` and then returned `error.OutOfMemory` answered 404 with the old message, and the log said the same; what a fail function set now speaks only for `error.Failed` (ADR 004).
- **`listen()` refuses an app with an `Idempotent` route and no Space for it, naming the type**, where the server started and every request to the route answered 500 (ADR 005, ADR 155).
- **A cache miss on a full bucket reads the ring for nothing about once in 2,000 lookups, as documented, rather than once in 30.** The fingerprint read the hash bits the shard is chosen by, so only 256 of its 16,384 values ever occurred inside one shard; it reads bits no other consumer of the hash reads now, and a Store holds at most 65,536 shards so they stay apart (ADR 152).
- **A cache slot left untouched for 65,535 laps of the ring can no longer come back to life.** Its 16-bit pass number matched again, and the slot pointed into a newer entry whose value a client may have written, a header and a key included: a forged hit. Each region now clears its dead slots twice per wrap, under the lock a `put` already holds; slots stay eight bytes (ADR 152).
- **An S3 header value with a run of spaces or tabs in it is signed the way S3 reads it**, so `filename="a  b.pdf"` in `content_disposition` is no longer a 403 reported as `error.Rejected`, and an empty `content_type` is neither signed nor sent (ADR 060).
- **`s3.open` keeps its own copy of `.static` credentials and zeroes secrets it frees**: the copy, a refreshed credential set it replaces, and the derived signing key. It held the caller's slices until the server started, so a config buffer reused after `open` signed with whatever was written there (ADR 060).
- **`list` percent-decodes a key only when the answer says `<EncodingType>url</EncodingType>`**, where a literal `%41` in a key from a server that ignored the request's encoding came back as `A` (ADR 058).
- **A schedule that lost its next tick is queued again within a minute.** The next tick is pushed after the current one is marked done, so a crash between the two, a failed push or a `cancel` of the queued tick left the kind with no row until the process restarted. Every worker, and `drain`, now seeds again at most once a minute once the queue has been seeded; a kind that already has a tick inserts nothing. The failed push logs at `warn` (ADR 161).
- **The `status` Space says `running` while a row runs**, with its attempt, where it said `queued` for the whole run. It is written after the payload parses, so a row that dies on parsing never shows `running`. The Space belongs to one instance, which the guide now says (ADR 160).
- **A payload that cannot be parsed for want of memory is retried rather than dead**, with the kind's `retry` like a failed run; a payload this binary cannot read is still final (ADR 160).
- **`job.Memory`'s claim leaves a row queued when it cannot allocate**, where it marked the row `running` and spent an attempt first, so the row waited out its lease. It allocates before taking its lock, and so does `deadOnes` (ADR 160).
- **A worker started with `serveOn` cancels a run at its `timeout_ms`**, where nothing bounded it and the lapsed lease let a second worker run the row beside it (ADR 056).
- **A run that times out is retried and recorded as `TimedOut`**, even when it returns one of its own `final` errors or `Canceled`; the deadline was asked three times and answered once (ADR 179).
- **`Overlap.queue` queues the next tick while the current one runs**, where it behaved exactly like `.skip` (ADR 161).
- **`zig build test-s3` fails under `$CI` when the object store's variables are missing**, as `test-sql` does, where it passed with eleven live tests skipped; `-Ds3-required=false` opts out, and `test` runs the new `test-s3-suite` (ADR 239).
- **A float that is not finite is `null` on every path out of `json.write`**, where a type `covers` did not take (a tuple, a `std.json.Value`, a map, a type with its own `jsonStringify`, a value nested past eight) went through `std.json.Stringify` and wrote infinity as the bare word `inf` and NaN as `"nan"`, which is not JSON (ADR 096). Nothing to change. A `jsonStringify` that names `*std.json.Stringify` as its parameter keeps `std.json`'s spelling of the floats it writes itself; one that takes `anytype`, which is how every one in nilo and `std.json` is written, is covered.
- **A gzip gRPC message is inflated only within the room its connection's budget has left**, and its inflated copy is charged to the budget before it is allocated, where a hundred calls of 64 KiB of gzip that each inflated to `max_body` held about 200 MB on one connection (ADR 220). A call over the room is answered `UNAVAILABLE`, which an OTLP exporter retries with backoff, with a message saying the connection's budget is full; one alone on its connection has all of it. What to change: a client sending several large gzip messages side by side on one connection (an OpenTelemetry Collector with batches of a few MB and the default `num_consumers: 10`) now gets the excess refused: lower its `sending_queue.num_consumers` or raise `max_body`. The arithmetic is in the ADR.
