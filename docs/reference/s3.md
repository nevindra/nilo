# nilo_s3

**`nilo_s3` reads and writes objects in S3 and anything that speaks the same API, with each bucket declared as a type.**

**Guide:** [Object storage](../guide/s3.md) · **Design:** [Object storage](../design/s3.md)

## `nilo_s3`

Object storage for S3, MinIO, R2, Backblaze, and anything else that speaks the same API. It is a **Service**: it borrows the event loop and holds a destination ([ADR 061](../adr/061-a-fitting-borrows-the-loop.md)). It implements SigV4 and S3's semantics and nothing more; the HTTP underneath is `nilo_fetch` ([ADR 058](../adr/058-most-of-an-s3-client-is-not-s3.md), [ADR 063](../adr/063-an-object-store-is-a-service-that-dials.md)).

<!-- compiles -->
```zig
const s3 = @import("nilo_s3");

// A bucket is a type, and its name is a compiled-in default (ADR 059).
const Avatars = s3.Bucket("avatars", .{ .max_bytes = 2 << 20 });

fn avatar(avatars: *Avatars, c: *nilo.Ctx, key: nilo.Str) !void {
    const object = try avatars.get(c, key.view());
    return c.send(200, object.content_type.view(), object.bytes.view());
}
```

and at startup:

```zig
var store = try s3.open(gpa, .{
    .endpoint = "https://s3.ap-southeast-1.amazonaws.com",
    .region = "ap-southeast-1",
    .credentials = .{ .static = .{
        .access_key_id = settings.aws_key,
        .secret_access_key = settings.aws_secret,
    } },
});
defer store.deinit();

var avatars = try Avatars.open(&store);
defer avatars.deinit();
try app.provide(&avatars);
```

### `Store` and `Bucket`

**One Store, many Buckets.** The Store owns the connection pool, the credentials and the derived signing key. A Bucket owns a name and the options that go with it. Two buckets over one Store share one pool, and starting a Store twice does nothing the second time.

**A bucket opens under its declared name, or under one read at run time.** `Avatars.open(&store)` uses the name in the type. `Avatars.openAs(&store, cfg.avatars_bucket)` uses the one given, for a binary shared by every deployment, and answers `error.BadBucketName` for a name the bucket's style cannot carry: the rules the compiler applies to the declared name (3 to 63 characters; under `.virtual` lowercase letters, digits, dot and dash, not starting or ending with a dash or dot, not shaped like an IP address; under `.path` letters, digits, dot, dash and underscore). The name is copied into the bucket, so the config it came from need not outlive the call, and it is the name every log line and `presignPost` use. The type stays the identity: `Avatars.bucket` is the declared name and `avatars.name` the one in use. `Avatars.nameProblem(name)` returns the reason in words, or null, for a program that checks its configuration before opening. Both opens make one allocation and a refused name makes none.

### Bucket calls

| Call | |
|---|---|
| `bucket.get(c, key)` | `Object`: `bytes`, `content_type`, `etag`, `len`. One allocation holds all four |
| `bucket.getRange(c, key, .{ .from, .to })` | the same, for a slice. `to` is inclusive |
| `bucket.getIf(c, key, etag)` | `Conditional`: `.unmodified` or `.object`. A 304 is a success, so it is a union, not an error |
| `bucket.stream(c, key, &reading)` | fills a `Reading`: `len`, `content_type`, `etag`, then `pipe(w)` and `close()`, which gives back the connection, the permit and the stream slot. No whole-call limit unless `.{ .timeout_ms = … }` is set on the `Reading` before the call; `stall_ms` bounds silence ([ADR 060](../adr/060-a-signing-key-changes-once-a-day.md)) |
| `bucket.put(c, key, .{ .bytes, .content_type })` | also takes `cache_control` and `content_disposition` |
| `bucket.putStream(c, key, .{ .reader, .len, .content_type })` | sent with a length, never chunked, because S3 does not accept chunked uploads, and on a connection of its own that no pool held, so an idle gap cannot hand it one the server closed. An optional `.timeout_ms` on the source is a whole-call limit; `stall_ms` counts each chunk the source hands over as progress |
| `bucket.putMultipart(c, key, .{ .reader, .content_type })` | S3's multipart upload as one call, for a reader of unknown length: initiate, parts of `.part_bytes` (8 MiB unless the source says otherwise; under 5 MiB is `error.Rejected`, S3's own floor for any part but the last), then a completion whose 200 is checked against its body, because S3 can answer one with an error inside. A source that ends inside the first part becomes a plain `put`, one round trip and the content's own MD5 as the ETag. Each part and the completion take the source's optional `.timeout_ms` and the Store's `stall_ms`, the terms `putStream` sets; `.cache_control` and `.content_disposition` are read off the source if it has them. A failure after the initiate aborts the upload on the way out; 10,000 parts (S3's ceiling) is `error.Rejected` naming `.part_bytes` as the fix, a bound a reader of unknown length can only meet on the way. Costs one `part_bytes` buffer, an ETag copy per part and the completion document in the Scope, and holds one stream share for its whole life |
| `bucket.copy(c, from, to)` | copies an object to another key of the bucket inside the store: no byte passes through the caller. Up to S3's 5 GiB for one copy. A 200 with an error in its body (S3 can send one) is an error |
| `bucket.compose(c, to, parts)` | joins objects of the bucket, in order, into one object at `to`, inside the store: a multipart upload whose parts are copies (UploadPartCopy). S3's part rules hold: every source but the last at least 5 MiB, each at most 5 GiB, at most 10,000. A failure aborts the upload and leaves `to` as it was. Costs one ETag per part and the completion document in the Scope |
| `bucket.delete(c, key)` | |
| `bucket.head(c, key)` | `Meta`: `len`, `content_type`, `etag` |
| `bucket.list(c, .{ .prefix, .max_keys, .cursor })` | `Page`: `objects` (`Listed`: `key`, `size`, `etag`, `last_modified`) and `next`, the cursor for the following page, or null. One page, at most 1,000 objects; nothing follows the cursor for you, and a page marked truncated with no usable token (missing, empty or over 1,024 bytes) is `error.Failed`, not the last page ([ADR 058](../adr/058-most-of-an-s3-client-is-not-s3.md)) |
| `bucket.presign(c, key, seconds)` | `Presigned`: `url` and `expires_at`. Opens no socket |
| `bucket.presignPut(c, key, seconds)` | the same, for a PUT: a URL a process uploads one object to. The method is inside the signature, so this URL is a 403 as a GET and `presign`'s as a PUT. No size condition exists on a plain PUT, so the server that handed it out verifies what landed before recording it; a browser belongs on `presignPost`, whose policy carries the ceiling |
| `bucket.presignPost(c, key, .{ .seconds = 900 })` | `Posted`: `url`, `fields` and `expires_at`, for a browser uploading straight to the bucket. Opens no socket |

`c` is a Scope, the same as everywhere else.

**A call nilo cannot send honestly is `error.Rejected` before a byte moves.** An empty key is refused by every call but `list` and a `presignPost` with `.prefix = true`, because it addresses the bucket and not an object (`get("")` listed it, `delete("")` was DeleteBucket, `put("")` was CreateBucket). A header value with a control byte (under 0x20 other than tab, or 0x7f) in `content_type`, `cache_control`, `content_disposition` or `getIf`'s etag is refused too, because it would split the request ([ADR 059](../adr/059-a-bucket-is-a-type-and-a-key-is-not.md)). A run of spaces or tabs inside a header value is signed the way S3 reads it, so `filename="a  b.pdf"` signs.

### `bucket.presignPost`

**A presigned POST is a form, not a link.** `presign` gives somebody a URL to fetch; `presignPost` gives a browser everything it needs to upload without the bytes passing through your server. `url` is the bucket, not the key. The `fields` go into the form in the order they come back, with the file input **last**, because S3 ignores anything after the file part. The first field is `bucket`: Garage rejects the form without it, and AWS reads the bucket from the URL and ignores the field.

| `s3.Post` | Default | |
|---|---|---|
| `seconds` | required | clamped to `presign_max` and to what the credentials have left, the same three ways `presign` is |
| `content_type` | null | an `eq` condition on `$Content-Type`. Null lets the browser send any type |
| `max_bytes` | the bucket's `max_bytes` | **clamped to it, and defaults to it**, so this never hands out a form with no size limit |
| `prefix` | false | `key` is the start of a key instead of a whole key, so the browser picks the filename. The condition becomes `starts-with` |

```html
<form action="{url}" method="post" enctype="multipart/form-data">
  <!-- one hidden input per field, in order -->
  <input type="file" name="file">   <!-- last -->
</form>
```

The reason this lives in nilo and not in your application is one detail of SigV4: the policy is signed with the key ADR 060 derives once a day. A second implementation of that outside nilo means two places that must agree about a key rotation. They disagree at 00:00 UTC, and the symptom is uploads failing with a 403 that explains nothing.

### `s3.Options`

Given to `open`:

| Field | Default | |
|---|---|---|
| `endpoint` | required | `https://host[:port]`, no path. **The scheme decides whether payloads are hashed**: `UNSIGNED-PAYLOAD` over TLS, a real SHA-256 over plaintext |
| `public_endpoint` | null | the endpoint a **browser** reaches, when it differs from the one this process connects to. It is the host in every presigned URL and POST form, and **the signature is made for that host**, so rewriting the URL after signing gives a 403 ([ADR 177](../adr/177-a-presigned-url-names-the-host-the-browser-reaches.md)) |
| `region` | `us-east-1` | |
| `credentials` | required | `.static` or `.fetch` |
| `max_in_flight` | 32 | calls at once. An HTTPS connection holds 59,151 bytes, so this times that is the memory ceiling |
| `timeout_ms` | 30,000 | one call, end to end, for `get`, `head`, `list`, `put` and `delete`. **Not applied to `stream` and `putStream`** |
| `stall_ms` | 30,000 | how long a `stream` or `putStream` may move no bytes, in either direction, before it is `error.TimedOut`. `0` means no bound |
| `max_streams` | 0 | how many streaming calls may be open at once, out of `max_in_flight`. `0` is half of it (at least one); more than `max_in_flight` is `error.BadStreams` from `open`. Short calls always keep the rest |
| `fetch_timeout_ms` | 10,000 | how long `Source.fetch` may take before it is cancelled and counted as a failed fetch; `0` means no limit. Cancellation lands at the function's next `Io` call |
| `max_drain` | 64 KiB | how much of a rejected response body to read in order to keep the connection |
| `refresh_margin_s` | 300 | how long before expiry temporary credentials are replaced |

**`open` refuses configuration that could never sign**, each opening and then answering 403 to every request otherwise: `error.BadCredentials` for an empty key id or secret, an `expires_at` already past, a key id or session token too long or a key id holding `,`, `/`, a space or a control byte; `error.BadRegion` for a region holding the same bytes or too long for a credential scope; `error.BadEndpoint` for an endpoint that is not `scheme://host[:port]` or whose authority is over 255 bytes; `error.BadStreams` for `max_streams` over `max_in_flight` ([ADR 060](../adr/060-a-signing-key-changes-once-a-day.md)). `open` keeps its own copy of `.static` credentials and zeroes secrets it frees.

### Bucket options

The second argument to `Bucket`:

| Field | Default | |
|---|---|---|
| `max_bytes` | 8 MiB | the largest object a bounded `get` will hold, **checked against `content-length` before any byte is read** |
| `style` | `.virtual` | `.path` for MinIO and anything on a bare host |
| `sse` | null | `.aes256` or `.aws_kms` |
| `presign_max` | 3600 | the longest lifetime a presigned URL may have |
| `key_max` | 512 | the longest key. Known at compile time because it sizes a stack buffer, and stack is held per connection |
| `session_token_max` | 0 | room for a session token. **Zero is right for static credentials** and costs nothing; STS sources set 2048 and pay for it per connection. Above 2,048 does not compile |

### Temporary credentials

**Temporary credentials come from one function**, called lazily by the request that notices they are close to expiry. There is no background task:

```zig
.credentials = .{ .fetch = fetchFromIrsa },   // fn (gpa, io) !s3.Credentials
```

**A failed refresh fails nobody while the credentials in hand are still valid**: the old key signs until `expires_at`, one fiber refreshes while the others sign, and the next try is five seconds later. A fetch that hangs is cancelled at `fetch_timeout_ms` and counts as a failed one; once the credentials expire, a call answers `error.TimedOut` for a timeout (the log names the credential source), or the fetch's own failure ([ADR 060](../adr/060-a-signing-key-changes-once-a-day.md)).

### Errors

**There are seven errors, because a handler would do something different about each**: `NotFound` (the only one with a default status, 404), `TooLarge`, `Throttled`, `Unavailable`, `TimedOut`, `Rejected` and `Failed`. S3's own code and message are logged, not passed on to the client: sending `Rejected` to a client as a 403 would tell the caller they are not allowed, when in fact the *server's* credentials are wrong. A skewed clock is read from the response body and reported plainly.

### What it does not do

**No `COPY`, bucket lifecycle, or anything else whose success response is XML.** [ADR 059](../adr/059-a-bucket-is-a-type-and-a-key-is-not.md) is where that line is drawn and why. `list` and `putMultipart` are the two exceptions, each let in by a caller: a page with a cursor nothing here follows, and an upload protocol owned whole by one call ([ADR 058](../adr/058-most-of-an-s3-client-is-not-s3.md)).
