# The API description is read off the signatures, not written by hand

**Status:** accepted
**Topic:** [openapi](../design/openapi.md)

## Context

FastAPI's real contribution is not speed. It is that you write the function signature once and everything else is derived from it: validation, the messages, the OpenAPI document, and a page you can click through. nilo already had the hard half: the compile-time engine has read handler signatures since stage 3 to decide what to pass in, `fn getUser(db: *Db, id: u32) !User` is a contract the compiler enforces, and nothing had asked that contract to describe itself.

```zig
app.docs(.{ .title = "Orders", .version = "2.1.0" });
```

That is the whole of it. The document lands at `/openapi.json`, a page for reading it at `/docs`, and neither has to be kept in step with anything, because there is nothing to keep in step: the description and the code that serves the request are read from the same argument list on the same pass.

Three gaps showed up once real types started answering routes, all of them the same shape: something the signature settles and the document guesses at instead.

**A type that writes its own JSON was reflected as a struct.** `nilo_id`'s `Uuid` carries a `jsonStringify` and sends a 36-character string over the wire; the generated document described it as `{"type":"object","properties":{"bytes":{"type":"string"}}}`, because `openapi.zig` reflected the fields and nothing reconciled that with what `jsonStringify` actually wrote. It was the only wrong schema in a 29-schema document, and that made it dangerous: `Upload`, `Patch(T)` and every enum rendered correctly, so nobody checked the one field that lied. `nilo_sql`'s `Timestamp` and `AsText` (`Decimal`, `Interval`, `Inet`) write themselves the same way and were wrong the same way.

**Two names differed only by a lifetime, and a `union(enum)` return type got `{}` for no reason.** The `Str`-in / `Text`-out rule means a shape more than one level deep gets written twice, `Meta(Str)` and `Meta(Text)`, and both landed in `components/schemas` as byte-identical `Meta_Str` and `Meta_Text`, doubling a generated client's types for nothing a Zig lifetime means on the wire. Separately, a `union(enum)` as a body is rightly a compile error (nothing in the type says which arm arrived), but as a return type it compiles and serialises correctly, externally tagged, and the document said `{}` instead of describing a shape `std.json` was already committed to.

**There was no way to say a union is spelled with the discriminator beside its fields, only above them.** `std.json` writes a `union(enum)` one way, `{"metrics": {…}}`; most REST APIs tag the other way, `{"signal": "metrics", …}`, and saying that meant a hand-written `jsonStringify` and `jsonParse` per type, an estimated 300 lines of codec in one application across four such unions. It also cost real throughput: a response carrying any union sent the *whole* response through `std.json`'s byte-at-a-time escaping, because `covers()` did not recognise a union at all. Measured on a 374-byte payload, `std.json` ran 248–317 ns against a generated writer's 86–93 ns, roughly 2.8× to 3.2× (3.4× to 3.5× on 104 bytes; [`bench/result/http.md`](../../bench/result/http.md)), and internal tagging costs nothing extra against a struct with no union in it at all.

## Decision

### Comptime data, not generated code

The obvious shape is a writer function per route, generated by the same machinery as `typed.wrap` and stored beside the handler. It was rejected: that puts a copy of the JSON-emitting code in the binary for every route, and route counts are the one thing that grows in an app. So a route contributes an `Operation`, a plain value whose slices point at read-only memory, and one writer walks the list. Building it costs nothing at runtime because it *is* the compile output; the whole document is assembled once, in `resolveChains()`, into bytes that never change afterwards, then handed to `static.fromMemory` and served as a file ([ADR 009](./009-static-files-are-held-in-memory-or-opened.md)). The document gets an ETag, a repeat visit is a 304, and no new field appeared on `Ctx` and no new terminal handler on the request path.

### A type that writes its own JSON says what it writes

**A type whose fields are not its JSON is described by what it says, and a type that says nothing gets `{}` and a note.** `schemaOf` asks whether a type has a `jsonStringify` and stops reflecting when the answer is yes:

```zig
pub fn jsonStringify(self: Uuid, jw: anytype) !void { … }
pub const nilo_openapi = .{ .type = "string", .format = "uuid" };
```

`nilo_openapi` is plain data, and has to be: `nilo_id` imports nothing at all ([ADR 038](./038-a-module-sits-where-the-loop-puts-it.md)), so it cannot name a `Schema` to say this with. Two fields, `type` and an optional `format`, read field by field rather than coerced; a marker with no `type` is a Refusal in nilo's own words. `Uuid`, `Timestamp` and `AsText` each carry one line.

**Silence is answered honestly rather than guessed at.** A third-party type with a custom writer and no marker becomes a schema of `{}` (true, JSON Schema for "anything") with a description explaining that it writes its own body and has not said what it looks like, and how to fix that.

### Two named shapes that differ only by a lifetime are one component

The rule is narrow: it fires when both names are the same stem under a `_Str` / `_Text` suffix *and* the two schemas render the same all the way down, every field name, every field's requiredness, every field's type, recursively (`rendersTheSame`, distinct from the field-name-only `sameShape` that tells two *different* types apart). Anything else keeps its own name: `Page_Order` and `Page_User` share field names and are not the same shape, and nothing here merges them. The pair is written under the stem, so a client gets `Meta` rather than one of `Meta_Str` and `Meta_Text` standing in for both; a `$ref` to either name resolves to it.

**A `union(enum)` is a `oneOf` of one-key objects**, what `std.json` writes for an untagged encoding. An *untagged* union, one with no marker saying otherwise, stays `{}`: nothing in the type says which arm is live, so nothing can.

### A type says how its JSON is spelled

```zig
const Condition = union(enum) {
    pub const nilo_json = .{ .tag = "signal", .rename_all = .lowercase };
    pub const jsonParse = nilo.jsonParseFor(@This());

    metrics: MetricCondition,
    logs: LogCondition,
};
```

**`.tag` is the discriminator's key, `.rename_all` is how a variant or an enum tag is spelled on the wire, and both are read while compiling**, comptime strings in the same `writeAll` as the punctuation around them, which is why marking a type costs nothing measurable. The marker is plain data, the same rule as `nilo_openapi`: a type in a module that imports nothing still has to be able to write it, so every field is read by name rather than coerced.

**Unions get the generated writer whether or not they are marked.** An unmarked one is written externally tagged, byte for byte what `std.json` writes, which is where most of the saving lives: it arrives for every existing program with a union in a response, without anybody changing a line.

`.rename_all` here renames a union's variants and an enum's tags, not a plain struct's fields; that line moved after this decision, and a struct can now say its own `.rename_all` for its own fields ([ADR 148](./148-a-field-name-is-a-spelling-too.md)), each type's marker renaming only its own type.

**Writing is nilo's, reading is handed over.** `json.write` asks `covers`, which asks the marker, so writing needs no extra line. Reading does, because `std.json` is what chooses a parser for a type, asking `std.meta.hasFn(T, "jsonParse")`, and nothing can add a declaration to a type somebody else wrote; the type hands over a function nilo supplies, `nilo.jsonParseFor(@This())`. The variant is not known until the discriminator turns up, and it may turn up after fields that belong to it, so the reader depends on where it is. When the object opens with the discriminator, which is how every encoder here writes it, and every variant is a plain struct, the object is read once, straight into the variant (`readOpening`). When it opens any other way the reader makes two passes: one finds the discriminator (and refuses a second), the other reads the variant's fields with the discriminator skipped (`readAnywhere`). A union with a variant of another shape (its own `jsonParse`, a tuple) takes the original four-pass reading: `peekNextTokenType` puts the cursor on the value, `skipValue` finds its end, and the span is read again for the discriminator and then handed to `std.json` as the variant's own type. A stray `}` or `]` where the value should start is a syntax error before anything skips, because `skipValue` is `unreachable` on both. This costs no allocation because a body is read whole and bounded by `max_body`, so the bytes are already in memory; a streaming source (nilo never hands it one) falls back to a `std.json.Value`. Because `ignore_unknown_fields` has to be on to get the variant past the discriminator, the span's top-level keys are walked by hand and anything that is neither the tag nor a field of the variant is refused, so a typo inside a tagged variant is still a 400 naming the field. **A second discriminator is refused**, wherever it sits and whatever it says: the reader walks the whole object rather than stopping at the first, because `std.json` refuses a repeated key everywhere else and a front end that keeps the last one would see another variant than the one read here. It is a 400 naming the key (`json.parseLeaky` finds it on the way out), the variant's own fields are read by the same number grammar as any other body ([ADR 084](./084-a-number-in-a-request-is-not-a-zig-literal.md)), and the cost is one scan of the rest of a tagged object that used to be skipped. A key beside a variant with no payload is refused the same way, where it was dropped.

**The 400 says what was received and what would have been accepted**, in the second parse a refused body already pays (`describeTagged` in `ctx.zig`, no cost on a body that reads): an unknown variant quotes the tag it was given and lists the variants, an unknown key names itself and the variant it was in and lists what that variant takes, and a missing or non-text discriminator lists the variants. A key beside a variant that has no payload is refused the same way, where it used to be dropped in silence. What is wrong inside the variant is named by its path, `condition.query`, as in a struct.

**The document says which encoding.** A tagged union is `oneOf` with `discriminator`, each arm joined to its tag by `allOf` (an arm may already be a named component, and nothing can be merged into a `$ref`), each arm pinning its own value with a one-item `enum`. `rendersTheSame` compares the tag, so the two encodings are two shapes, not two renderings of one, and the lifetime merge above cannot put a client's one name on both.

### What it will not claim

A specification that lies is worse than none, so the places where a Zig signature does not settle the answer are written as unsettled:

- **A handler returning `Response(T)` gets `default`, not `200`.** The status is a field the handler fills in at runtime; a document claiming 200 for the route that answers 201 would send somebody debugging their client.
- **A type with no JSON shape gets `{}`**, true rather than a guess dressed up as a description.
- **A self-referential type is followed eight deep and then stops** (`max_depth`), because the alternative is a compiler that does not finish.
- **A `400` is listed only where nilo can actually produce one**: a route with a typed path param, a query struct, or a body.

What it does claim, it claims because the type said so: `:id` on a handler taking `u32` is an integer, a query field with a default is not required, an enum is the list of its names, `?T` is `anyOf [T, null]`.

### The one thing it gets wrong, and why it is left wrong

**An endpoint authenticated by a resolver is documented as needing nothing.** A handler that asks for `nilo.Authorization(…)` in its signature is documented with the matching `bearer` or `basic` scheme, and a route behind an `app.guard` with the cookie scheme ([ADR 153](./153-an-authorization-header-a-handler-can-ask-for.md)). What stays silent is a resolver: a handler taking a `CurrentUser` requires an `Authorization` header, and the document does not say so, because a resolver is an opaque function and the header it reads is a line of Zig inside it, not something in a type. Documenting it would mean either the resolved type declaring its own security scheme (a second thing to keep in step with the resolver, the drift this whole ADR exists to avoid) or reading the resolver's body, which is not something a compiler will do. It is a known hole, and for such a route the document describes the *shape* of a request accurately while staying silent on who may make one, which beats a made-up `securitySchemes` block that nothing enforces.

### The reader page pulls from a CDN

The document is self-contained; the page that renders it is one `<script>` from jsdelivr. Bundling a viewer would put a few hundred kilobytes of somebody else's JavaScript in this repository. This is stated plainly because a server with no outbound network is normal in production and somebody will hit it: the document itself never needs the network, and `ui_path = ""` turns the page off.

**The script is one version, held by its hash.** The page is served from the application's own origin, so what it loads runs beside the session cookie and can make requests that carry it. The tag names `@scalar/api-reference@1.72.0/dist/browser/standalone.js` with an `integrity` hash and `crossorigin="anonymous"`, so the browser runs that file and no other. Until a review read it, the tag named the package with no version and no hash, and whatever the package published next would have run in every nilo application's origin. Moving to a newer viewer is a change to `openapi.reader_script`, with the sha384 of the file (jsdelivr's `?structure=flat` listing confirms it by its sha256).

## What was rejected

**A writer function per route, generated code beside the handler.** A copy of the JSON-emitting code in the binary for every route, when route count is the one thing that grows in an app.

**Deriving a marked type's schema from its `jsonStringify` body.** The function is arbitrary Zig; there is no comptime reading of a function body, and a framework that guessed would be wrong in exactly the cases that matter. The same argument applies to deriving `.tag`/`.rename_all` from a hand-written `jsonStringify`.

**Refusing a custom writer with no marker.** Breaks every existing program with a `jsonStringify` on a response type, to fix a document those programs may not even generate. Visibly silent is the smaller hammer.

**A general JSON Schema builder** (`pattern`, `minimum`, `examples`). A second language for describing types beside the one nilo already has; two fields is what a custom writer needs to stop lying, and anything past that is a different feature.

**Merging any two schemas that render identically, not only the `_Str`/`_Text` pair.** Too strong: two unrelated types with the same field names and types today are one component under that rule, and stop being one the day somebody adds a field to either, so a client regenerated after an unrelated change finds a type has split in two. Tying it to the lifetime suffix means the merge is about the thing that is actually the same value.

**Naming the merged shape `Meta_Str` and pointing `Meta_Text` at it.** Cheaper, and it publishes the lifetime, the thing this decision is about there being no JSON for, as the name a client sees.

**Refusing a `union(enum)` in the return position.** Breaks working programs to fix a document, and the shape is derivable, so deriving it is strictly better.

**Taking the first discriminator, or the last, when an object has two.** Either one is a choice a front end in front of nilo may have made the other way, and two readers of one request that disagree about its variant is the disagreement [ADR 070](./070-a-request-nobody-else-would-answer-is-refused.md) refuses one layer down. Taking the first was the behaviour until the audit of `http/` at `39896d2`.

**A JSON parser of nilo's own**, so the tagging marker could be the only line. Puts unicode escapes, surrogate pairs and number edges in this repository, which `json.zig` already refuses to do for floats.

**serde's full case list.** `.snake_case` is already what a Zig field name is, so asking for it is a misunderstanding rather than a no-op; what is kept is the set unambiguous from snake_case (`.lowercase`, `.UPPERCASE`, `.SCREAMING_SNAKE_CASE`).

**A `serde`-shaped surface generally**, `content`, `flatten`, `skip`, `default`, `with`. Each is a different feature that has to arrive with its own caller.

## What it costs

Allocations per request and memory per idle connection are untouched by every part of this: nothing here runs while a request is in flight, and no new field appeared on `Ctx`.

Binary size is not: **+14 KB on the hello example, +34 KB on rest, whether or not `docs()` is called** (stripped `ReleaseFast`, measured against the commit before this landed: hello 1,030,792 → 1,044,840 bytes, rest 1,167,576 → 1,201,768; the difference between the two is route count). This breaks the "a module is either compiled in or absent" rule: `resolveChains()` reaches the writer through a runtime `null` check, not a compile-time one, so the linker cannot drop it. Accepted at 1.4% of a binary; making it genuinely absent needs a build option threaded through a `zig fetch` dependent, recorded in `docs/todo.md` as open.

**The first measurement of that cost was wrong by 88%, and the reason is worth keeping.** +43,360 bytes on hello did not square with 4.5 KB of `openapi.*` symbols; reading the binary found one extra instantiation of `std.sort.block`, 37 KB, pulled in because serving the document through `static.fromMemory` made the static layer's stable sort reachable in a program that loads no static files. URLs in a set are unique, so nothing can tie and stability buys nothing; swapping the call sites to `std.sort.pdq` gave back 29 KB, in every binary that serves files. The lesson: in Zig, the size of a feature is often the generic it made reachable, not the code written for it, and `nm --size-sort -S` answers that in a second where guessing does not.

The marker features cost nothing on any axis beyond that: `nilo_openapi` and `nilo_json` are comptime data, checked with `@hasDecl`/field reads at comptime, and `covers`/`schemaOf` reach them only through branches the linker drops for a program that never marks a type. The lifetime merge and the `union(enum)` `oneOf` are the same writer running once in `listen()`; the document gets smaller where the first fires and gains a `oneOf` where the second does. The tagging feature pays for itself: **2.8× to 3.2× on a 374-byte payload carrying a union, 3.4× to 3.5× on a 104-byte one**, for every response with a union in it whether or not the type is marked, because the generated writer now covers unions it previously handed to `std.json` whole.

Refusals hold every way of writing a marker wrong (an unknown word, a missing `type`, a `.rename_all` promising a rename the shape does not have); the one worth naming on its own is a tag whose name a variant already uses, the one mistake here that would corrupt the wire (the key written twice, a reader keeping whichever it likes) rather than fail outright.

## Consequences

- Every route appends one `Operation` to a list at registration, whether or not documentation is switched on: startup memory proportional to route count, and what keeps `docs()` order-independent, callable before or after the routes like `use` ([ADR 008](./008-middleware-is-an-onion-of-ctx-functions.md)).
- The description is only as good as the signature: a handler that takes a `*Ctx` and digs the body out by hand documents nothing, an accurate description of what it told anybody.
- Path params are named by the pattern and typed by whichever argument claimed them, so a `*Ctx` handler's params are documented as strings, what they are before anybody converts them.
- A catch-all is `{path}` in the document, because `*` is not a name OpenAPI accepts; the one place a name differs between what nilo calls it (`c.param("*")`) and what the document calls it.
- Routes win over both docs paths. The docs are searched *before* loaded directories, because a single-page app's `index.html` fallback answers for every path and would otherwise swallow `/openapi.json`, exactly the setup most likely to want it.

A struct's own field-renaming rules are [ADR 148](./148-a-field-name-is-a-spelling-too.md); a type that writes its own JSON around one known value, so a rename or a schema can still see through it, is [ADR 163](./163-a-document-is-its-value.md).
