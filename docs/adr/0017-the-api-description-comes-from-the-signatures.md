# The API description is read off the signatures, not written by hand

FastAPI's real contribution is not speed. It is that you write the function signature once and everything else is derived from it — validation, the messages, the OpenAPI document, and a page you can click through (ADR 0015).

zfast already had the hard half. The compile-time engine has read handler signatures since stage 3 to decide what to pass in; `fn getUser(db: *Db, id: u32) !User` is a contract the compiler enforces. Nothing had ever asked that contract to describe itself.

```zig
app.docs(.{ .title = "Orders", .version = "2.1.0" });
```

That is the whole of it. The document lands at `/openapi.json`, a page for reading it at `/docs`, and neither has to be kept in step with anything, because there is nothing to keep in step: the description and the code that serves the request are read from the same argument list on the same pass.

## Comptime data, not generated code

The obvious shape is a writer function per route, generated by the same machinery as `typed.wrap` and stored beside the handler. It was rejected: that puts a copy of the JSON-emitting code in the binary for every route, and route counts are the one thing that grows in an app.

So a route contributes an `Operation` — a plain value whose slices point at read-only memory — and one writer walks the list. Building it costs nothing at runtime because it *is* the compile output; the whole document is assembled once, in `resolveChains()`, into bytes that never change afterwards.

Those bytes are then handed to `static.fromMemory` and served as a file (ADR 0010). That decision is worth more than it looks: it means the document gets an ETag, a repeat visit is a 304, and no new field appeared on `Ctx` and no new terminal handler on the request path. The docs are a file, and zfast already knew how to serve files.

## What it will not claim

A specification that lies is worse than none, so the places where a Zig signature does not settle the answer are written as unsettled:

- **A handler returning `Response(T)` gets `default`, not `200`.** The status is a field the handler fills in at runtime; a document claiming 200 for the route that answers 201 would send somebody debugging their client.
- **A type with no JSON shape gets `{}`**, which in JSON Schema means "anything" — true, rather than a guess dressed up as a description.
- **A self-referential type is followed eight deep and then stops.** The alternative is a compiler that does not finish.
- **A `400` is listed only where zfast can actually produce one** — a route with a typed path param, a query struct, or a body. Not sprayed over every endpoint on the grounds that anything might fail.

What it does claim, it claims because the type said so: `:id` on a handler taking `u32` is an integer, a query field with a default is not required, an enum is the list of its names, `?T` is `anyOf [T, null]`.

## The reader page pulls from a CDN

The document is self-contained; the page that renders it is one `<script>` from jsdelivr. Bundling a viewer would put a few hundred kilobytes of somebody else's JavaScript in this repository, and writing one would be a second project.

This is stated plainly rather than hidden, because a server with no outbound network is normal in production, and somebody will hit it. The document itself never needs the network, and `ui_path = ""` turns the page off.

## What it costs, measured

Two of ADR 0018's three axes are untouched, and the third is not:

| | |
|---|---|
| Allocations per request | **unchanged** — nothing here runs while a request is in flight |
| Memory per idle connection | **unchanged** — no new field on `Ctx`, no per-connection state |
| Binary size | **+43 KB** on the hello example, **+61 KB** on rest — *whether or not `docs()` is called* |

That last row is the honest cost and it breaks the nginx rule ADR 0015 quoted approvingly ("a module is either compiled in or absent"). `resolveChains()` reaches `buildDocs`, which reaches the writer, so the linker cannot drop it — the switch is a runtime `null` check, not a compile-time one.

It is accepted for now on the grounds that 43 KB is about 4% of a 1 MB static binary, and that it buys the feature this whole stage is named after. Making it genuinely absent needs a build option that a `zig fetch` dependent has to thread through, which is a worse ergonomic problem than the one being solved. Recorded in `docs/plan.md` as open rather than settled.

## Consequences

- Every route now appends one `Operation` to a list at registration, whether or not documentation is switched on. That is startup memory proportional to route count, and it is what keeps `docs()` order-independent — it can be called before or after the routes, like `use` (ADR 0009).
- The description is only as good as the signature, which is a feature: a handler that takes a `*Ctx` and digs the body out by hand documents nothing, and that is an accurate description of what it told anybody.
- Path params are named by the pattern and typed by whichever argument claimed them, so a `*Ctx` handler's params are documented as strings — what they are before anybody converts them.
- A catch-all is `{path}` in the document, because `*` is not a name OpenAPI accepts. It is the one place a name differs between what zfast calls it (`c.param("*")`) and what the document calls it.
- Routes win over both docs paths, so `app.get("/docs", …)` of your own still gets its way. The docs are searched *before* loaded directories, though, because a single-page app with an `index.html` fallback answers for every path there is and would otherwise swallow `/openapi.json` — which is exactly the setup most likely to want it.
