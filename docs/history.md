# How nilo was built

Not what shipped, which is [`CHANGELOG.md`](../CHANGELOG.md), and not what is coming, which is [`todo.md`](./todo.md). This file is what was *learned*: the lessons that would change what somebody does next time, each with the case that taught it and a link to where the full account lives. The binding decisions are in [`adr/`](./adr/), the raw numbers in [`bench/result/`](../bench/result/), the vocabulary in [`CONTEXT.md`](../CONTEXT.md).

**How an entry is written.** One lesson, one paragraph: the lesson in bold, then the case in a sentence or two, then the link. It goes under the theme it teaches, not under the release or the round that found it, and a lesson learned a second time adds its case to the entry that is already here rather than opening a new one. No release narrative, no list of what a round fixed, no story an ADR already tells. If an entry would not change what somebody does, it does not belong here.

## Where it came from

Through v1 the model was **GoFiber**: the feel of Express on a fast engine, for Go and Node people giving Zig a try. From v2 the architecture comes from elsewhere and Fiber stays only as the tone ([ADR 014](./adr/014-what-nilo-borrows-and-from-whom.md)). The audience did not change; the claim did, to **"the signature is the whole contract"**: a handler you can read, test as a plain function and get documentation from, on a server whose memory you can put a number on.

**v1's rejections were worth as much as its acceptances.** Range requests, `sendfile`, streaming, groups and middleware hand-offs were deferred for want of a *decided shape*, not of work, and each landed later as an addition rather than a rewrite. A `recover` middleware was not a deferral: Zig cannot recover from a panic ([ADR 007](./adr/007-no-recover-middleware.md)). And "Router: path params, query params" sat in the v1 scope with half of it built until a handler wanted the other half ([ADR 011](./adr/011-the-query-string-is-a-struct-of-your-own.md)).

## What is measured

- **Primary:** requests per second **and p99** on a routed GET with a path param returning ~1 KB of JSON, keep-alive, no pipelining (`bench/main.zig`). p99 is counted so that winning on throughput while stalling the tail does not count.
- **Secondary:** memory per idle connection.

[ADR 017](./adr/017-the-trade-budget-has-four-axes.md) made the split a rule: throughput may slip 10% for DX, while allocations per request and memory per idle connection are hard invariants. **Allocations per request is 1**, the JSON body (it was 6, then 3). **Memory per idle connection is 4,669 bytes**: ~21 KB first, 16,961 on the real machine, 8,767 once a keep-alive connection stopped holding every buffer page it had touched, and 4,669 once the waiting moved to the shallowest frame ([ADR 062](./adr/062-where-a-connection-waits-is-what-it-costs.md)). Published figures are in [`bench/result/http.md`](../bench/result/http.md) and [`comparison.md`](./comparison.md).

## Measuring

**Build the before; do not quote it.** The primary metric read 1.31M req/s in a published table and 1.42M on the same machine months later, and a published 8,215 re-ran as 7,908. Build the parent with `git archive HEAD | tar -x` or a `git worktree`, same flags, same afternoon; stashing once gave 612 ns against 728 half an hour apart ([ADR 037](./adr/037-a-service-that-needs-the-loop-is-finished-when-the-loop-exists.md)). For a binary-size A/B the *after* has to be the change alone: an unrelated uncommitted change once put its own log string into the number.

**A microbenchmark row under about 20 ns apart is not a result until it has beaten a no-op.** Three optimisations together put a routed HTTP/1.1 `GET` 15 ns higher in `zig build profile` though none of them slowed that path; the tree before with an unused function of `nop`s added moved as far, and one binary run from two paths of different length differed by 10 ns until the path was made the same, because the path and the environment move the stack. Copy every binary to one path, run it with an empty environment, and put a padded build of the before beside it; a server run is what decides ([`http.md`](../bench/result/http.md#what-a-request-on-http2-costs-once-its-clocks-copies-and-passes-are-counted)). The same holds the other way: a lookup that is 7 ns in a loop of its own cost 35 to 41 in a request, so take a cost out by replacing the thing in place and timing the whole row against a build without it, not by adding loop rows ([`http.md`](../bench/result/http.md#a-message-is-told-from-json-by-sixteen-bytes)).

**Interleave, and a margin inside the spread is "unchanged".** A single 1,485,190 against a single 1,424,878 was published as a win; four interleaved pairs put it at +0.6% with the sign changing between pairs, and the claim was withdrawn ([ADR 062](./adr/062-where-a-connection-waits-is-what-it-costs.md)). `--watch` looked 2 s faster from two runs against a remembered number and lost all three interleaved rounds. Knowing the rule is no protection when the number is the one you wanted. A margin narrower than its own spread is quoted as a band (5–8%), never as one of its runs.

**Passes are not exchangeable, and agreement on sign is not a cost.** Pooling 900 blocks from three passes gave intervals that excluded zero while the sign moved between passes; a difference now needs the interval to exclude zero *and* every pass to agree ([`sql.md`](../bench/result/sql.md)). And a difference that is real can still be meaningless: a route doing strictly more work read less CPU than its control, because the control was bound by memory bandwidth and a stalled cycle counts as CPU ([`s3.md`](../bench/result/s3.md)). A client cannot cost negative CPU, and two candidates cannot disagree on the sign of one operation's cost; either means the subtraction measured the machine.

**Say what a number was measured through.** The same server did 197k req/s across a Docker published port, 359k over loopback and 458k over a unix socket, and every database figure of one cycle was taken through the slowest: the ratios survived and the absolutes were half. The other "throughs" that bit were Debug builds nobody meant: `-O ReleaseFast` given once applies to the root module only, `zig build bench-cache` does not imply ReleaseFast, and `-OReleaseFast` after `-Mroot` applies to nothing. **A number ten times off the one it replaces is a build mistake before it is a finding**; check the binary's size. A test binary is a build nobody meant too: test builds here skip LLVM (ADR 138), and a Postgres connect timed inside one read 115 to 360 ms, the ReleaseSafe binary slower than the Debug one, where the same connect on LLVM run alone is 16 to 27 ms ([`sql.md` §20](../bench/result/sql.md#20-what-a-stream-let-go-early-costs-to-give-back)). A cost that decides a constant is timed in the build that ships.

**A benchmark of a check must be able to see it fail.** Timing `parseHead(h) catch unreachable` in ReleaseFast told LLVM a parse never fails, and every new refusal in the parser exists only to return an error, so the optimizer deleted all of them: the stricter parser measured 34ns against the old one's 29, and three rounds of tuning chased that number before a harness that counted errors put it at 55 to 65. Tuned against the honest one it settled at 47ns, and 139ns against 64 on a browser's head, and the load test put the whole change at 1.5 to 4.5% of throughput, the axis ADR 017 actually budgets ([ADR 070](./adr/070-a-request-nobody-else-would-answer-is-refused.md), [the run](../bench/result/http.md#what-reading-every-byte-of-the-head-costs)). Count the errors, and take the decision from the end-to-end run.

**Give every tree its own build cache.** Six scratch trees made with `git archive`, built with one shared `--cache-dir`, produced six byte-identical binaries, all of them the first tree's, one of them from a tree whose patched file had grown by a line. Every file `git archive` writes carries the commit's timestamp, which is the likeliest reason and was not run down. A thread-count fix measured as doing nothing until `md5sum` showed there was nothing to measure ([ADR 230](./adr/230-a-cpu-quota-sets-the-thread-count.md)). Compare the checksums of the binaries of an A/B before the first run.

**Pin both sides, to physical cores.** A server on CPUs 0–7 and a load generator on 8–15 shared eight cores, because 8–15 are the SMT siblings; split by physical core the server got *faster* on half as many cores, 1.14M to 1.31M. Unpinned, gws looked 68% behind; pinned to the same cores the margin was 5–8%.

**A figure that has not moved can still be wrong by the allocator's size class, and a measured cause beats the plausible one.** An idle connection read 512 bytes over its recorded floor for two releases; the bisect found no frame deeper, and the cause was 264 bytes of `Options` in a connection's spawn arguments pushing zio's task from its 384-byte pool to the 1,024 class of the allocator. The same session found ADR 062 blaming the stack for 8,202 bytes that were a 4 KiB arena buffer kept by `arena_keep`: the experiment that should have said so (an 8 KiB buffer, one byte of difference) had been recorded as proof that depth, not size, was the cost. A reading that moves by one byte under a 56 KB change is a reading about something else, and the next step is to take each candidate out, not to name the one left. A page crossing that cannot be seen is held by a build step (`zig build park-check`), which read the `-Dhttp2` margin at 64 bytes the first time it ran.

**Take a per-connection figure out until marginal meets average, on both sides.** At 2,000 sockets two WebSocket rows read 60 bytes high; at 10,000 all four collapsed onto 5,183. Running gws to 10,000 as well moved its best row in its favour, and the side to check first is theirs. Use one fresh server per row, because RSS does not come back down. Growth that scales with connections rather than with requests is retention, not a leak, and it takes two runs to tell. A per-connection cost that rises and then falls is not one.

**A control is a measurement, and it has to do the same work.** `/warm/1m` allocated per request in nilo and once at startup in three other candidates, so the bytes verified identical while the subtraction measured different things. Fixed, the control found nilo's biggest gap, 2.2× on a megabyte, which was an `@memset` and a 16 KiB `arena_keep` faulting 257 pages a request rather than the write path the results file blamed ([ADR 075](./adr/075-a-response-larger-than-the-arena-keep-is-a-page-fault-per-page.md)). A control that is "the same work minus X" is checked for a plus as well as a minus. A number is only a measurement once something stands next to it: a WebSocket receive at 88 GB/s beside a send at 199.8 GB/s was impossible on its face, and fusing copy and unmask made it 244.5.

**Use the instrument that contains the change, and give "unchanged" its resolution.** wrk on two cores put a parser change anywhere from −5.3% to +0.3% while `zig build profile` put the changed row at 100 → 109 ns every round. wrk's per-request Lua callback made the client the bottleneck at 30k req/s, where a 50 ns cost, 7% of the real thing, could not have shown. "Unchanged" from an instrument that could not have seen the change is a weaker claim, and it says so beside the result.

**`VmRSS` does not count a page nobody wrote to.** A body reserved from `Content-Length` read 17,281 bytes either way in `VmRSS` and 1,852,080 against 316,080 in `VmData` ([ADR 083](./adr/083-a-body-is-taken-as-it-arrives.md)). `VmData` answers what a commit *asks for*; `VmRSS` what it uses. The same misreading put libdeflate's pool at +373 KB a thread, its allocation, when a small body writes +32 KB more than `std.flate`'s slot ([`http.md`](../bench/result/http.md#libdeflate-against-stdflate-on-a-quiet-zen-5-and-what-it-keeps-resident)). **The exception is a huge page**: under THP `always` one write into a large anonymous mapping makes 2 MB resident, so a probe counting pages needs `MADV_NOHUGEPAGE` first, and so does a pool that wants the untouched part to stay free.

**An instruction count is exact and can still follow the clock.** cachegrind gave the same count run after run, and `nilo_s3` still read 190 instructions a request higher in some runs, for both builds at once. The runs that did started in seconds :00 to :09: SigV4's `x-amz-date` pads a field under ten with a `0`, and the padding path costs more than the digit. Two rounds back to back agreed, because they started in the same few seconds, so the spread said nothing about it; it took a run every two seconds for three minutes, and `cg_diff` on an unstripped build, to name `splatByteAll`. A count is deterministic in its inputs, and the time of day is an input to anything that prints it ([ADR 242](./adr/242-a-release-is-measured-against-the-one-before-it.md)).

**A microbenchmark on a shared box needs its minimum and a second run.** Best of five put a UTF-8 check at 38 ns; best of 25, run three times, at 10. The pessimistic number would have blocked a correctness fix, and a pessimistic number never announces itself because its answer is "don't". A harness that takes one pass cannot know it is measuring the neighbours (three runs spread 1.8× at load average 5 on two cores), so it prints the range.

**Measure a per-operation saving twice: unloaded, and at the pool.** Prepared statements were +24% at one request in flight and 51–70% through a server, because a pool connection serves one query at a time and the time a query holds it is occupancy, not latency ([ADR 051](./adr/051-a-statement-that-is-a-constant-can-be-prepared-once.md)).

**A row that is faster than expected gets explained before it is kept.** Go's cache benchmark looked keys up with the very string objects it had stored, and Go compares pointers before bytes; a separate copy of the same text moved the gap 20%. The same afternoon produced a row measuring a cache an earlier row had emptied and a warm-up that filled the wrong values, all flattering. Give both libraries the same shape of memory too: a 64 MiB store for 50,000 keys was most of a single-threaded gap ([`cache.md`](../bench/result/cache.md)).

**A benchmark that cannot tell two designs apart reports that the worse one is fine.** Under uniformly random keys every eviction policy scores the optimum; `nilo_cache` scored 100% there and 78% on Zipf 0.99 ([ADR 109](./adr/109-a-cache-holds-its-bytes-under-a-lock-it-can-spin-on.md)). A two-core box cannot ask a concurrency question either: on eight cores the shard count was worth 64% and the lock everybody blamed 1.4%.

**A number taken under one load is not a property.** "zio is ~10% of CPU" was taken at saturation, the one place a wakeup is free; a nearly idle server paid 40 µs a request against 18 near saturation, from a second context switch ([ADR 199](./adr/199-a-connection-is-served-by-the-thread-it-was-dealt-to.md)). What fixed the idle side cost the saturated one, and the ADR records it as a trade, not a win.

**When a many-core reading will not reproduce on fewer cores, count what scales with cores.** 409K TLB shootdowns in eight seconds, one per three short-lived WebSockets, were free on eight cores and a stall on 64; the `TLB` row of `/proc/interrupts` named it where throughput here never moved ([ADR 216](./adr/216-a-message-that-arrived-whole-is-handed-over-where-it-lies.md)).

**A bottleneck on one fiber shows as idle CPU and a tail on the first request.** A p99 of 3 ms at backlog 128 and 100 ms at 4,096 is the backlog divided by ~43K connections a second, which is one accept fiber: queue depth ÷ rate = tail. One acceptor per executor took 660K to 1.97M ([ADR 200](./adr/200-every-executor-accepts.md)). A drop the kernel makes for the server is invisible from the server: a listen backlog of 128 put 623 of 1,000 burst connections on a one-second SYN retry, visible only as `ListenOverflows` in `/proc/net/netstat` ([ADR 198](./adr/198-a-backlog-is-sized-for-the-burst-not-the-load.md)).

**A reproduction takes the other side's inputs.** Every TLS number here used an ECDSA test key; the arena mounts RSA-2048, which cost 13.7 ms a handshake and was its whole 201 ms p99 ([`http.md`](../bench/result/http.md#what-an-rsa-certificate-costs-a-handshake)). Read how the load generator starts its clock: zrk anchors each connection after its own handshake, so the tail was the open connections queued behind handshakes ([ADR 217](./adr/217-a-handshakes-signature-is-computed-off-the-executor.md)). A rank on somebody else's box gets decomposed here until what is left is one named question ([`sql.md` §12](../bench/result/sql.md#12-the-arenas-query-at-one-connection)).

**The harness has to say what it is pointed at.** A sibling worktree's server held the port, so `mem.py` read the wrong process and wrk counted another server's 404s; later a benchmark row read 908k from a server left over from an earlier session. The servers now fail loudly, `mem.py` prints its pid, and the gRPC script refuses to run beside a stranger. Failing loudly is not enough when nobody reads it: another project's server on `nilo-hello`'s fixed 8787 made the new one exit at once, and gcannon measured the stranger at 150k where nilo does 2M. A script that starts a server checks that the process listening on the port is the one it started, not only that something answers there. The same holds for the two sides of a comparison: a binary-size check listed both output directories in one `ls`, which sorts its arguments, and a 624-byte cost read as a 624-byte saving until each side was built again under a name printed on its own line ([`http.md`](../bench/result/http.md#a-fallback-session-secret)). A harness nothing on `test` builds drifts the same way without anybody seeing it: `compare-sql/zigsql` pinned a different pg.zig from the root's, so its control was another driver, and it had stopped compiling since `.sql = true` became required; `bench-sql` had been ending in SEGV for five weeks, after its numbers printed ([`sql.md` §16](../bench/result/sql.md#16-the-round-trip-pgzig-wasted-taken-back)); and `zig build profile`, the tool every in-process number here comes from, had not compiled since ADR 248 gave `compress.zig` an import the profile's module was never handed. The answer is the same each time: the profile is compiled, not run, on every `test` now ([`http.md`](../bench/result/http.md#an-answer-handed-to-the-framing)). It was not applied to the next tool of the same kind: `zig build fuzz` stopped compiling when `framing.zig` began asking `nilo_build` whether gRPC is in, and was found broken only when the Huffman decoder went to two symbols a lookup and needed it; the fuzzer is compiled on `test` too.

**Confine a foreign runtime before loading it; the OOM killer is global.** Bun retaining 27 GB also killed MinIO, a Postgres container and the session driving the run. `systemd-run --user --scope -p MemoryMax=6G -p MemorySwapMax=0`, and `journalctl -k` first, not third. A comparison harness needs a "did not finish" before it needs another candidate.

**A figure belongs to a binary, a machine and an architecture.** `zig build run-hello` reads 4,810 bytes an idle connection and `bench/main.zig` 4,674; the roadmap's instruction for repaying a debt named the wrong one and would have reported a regression, so an instruction for reproducing a number is part of the number. "SQLite costs 524,840 bytes" became 523,352 because the framework around it grew: a difference between two binaries is not a property of what differs. ADR 138's x86 figures applied to aarch64 took a 16 GB laptop down three times ([ADR 138](./adr/138-a-test-does-not-need-the-optimiser.md)).

**A build figure is about an artifact, and the artifact has to run.** `--watch -fincremental` rebuilt an example in 0.12 s, was quoted as the answer, and the binary died at exec with `undefined symbol: main` ([`build.md`](../bench/result/build.md#what-a-restart-on-save-costs-per-save)).

**When a delta is inside the noise, multiply the thing measured rather than the runs.** One listener against two was inside its spread; one against five, divided by four, put an extra listener at 82 KB, a third over the 64 KB already written into its doc comment.

**Measure the program that does not use the feature.** `Dotenv` was 237,528 bytes before and after for a program that never names it; measuring only the program that does says nothing about what existing users pay ([`bench/RESULTS.md`](../bench/RESULTS.md)). And read it by symbol, not only by total: reading a message's `Content-Type` grew a program with no message 5,312 bytes, 4 KB of it a classing function written with `eqlIgnoreCase` whose every compare vectorised, and when that went into the head parser and then onto the `Ctx` instead, a byte sitting in padding the `Ctx` already had still cost `serveRequest` 81 bytes to initialise. `nm -S` over both binaries, with the generated suffixes taken off the names, said where each one was; the total only said that something was ([`http.md`](../bench/result/http.md#a-body-read-as-what-its-type-says)). A field a feature added to `Request` as a `bool` changed `serveRequest` by 217 bytes in a program without the feature, and a variant added to `Body`'s state enum moved a jump table in another; as a `void` and a flag beside the enum, both absent without the build flag, the two programs were the same bytes ([`http.md`](../bench/result/http.md#what-a-request-on-http2-costs-when-its-body-is-a-pipe)).

**A profiler measuring something other than the metric is worse than none.** For two versions it divided by the program's first, cold loop (1,343 ns against 643 warm) and serialised 25 bytes where the benchmark sends a kilobyte, hiding a 1,038 ns `std.json` that was more than the rest of the request. The pass before 0.1.0 then A/B'd every change on five request shapes at once, 1,684 → 605 ns, because a change that helps a 121-byte head can hurt a 556-byte one. What was measured and dropped counts as much: the fastest header filter tried also accepted a line with no colon. And a profiler that frees a list with the wrong allocator runs for months until it is pinned to one core, where `SmpAllocator` has one arena and the corrupted free list is allocated from.

**A tail latency has a floor set by the load, and the server's share is the spread around it.** A worst call of 1.4 s and 3.8 s at 256 and 1,024 connections stood on the record against tonic's 1.1 s, and when a client that logged every request was finally pointed at it the numbers did not reproduce (0.84 to 1.07 s, tonic 1.07 in the same harness). At 102,400 streams in flight the mean is 100 ms whatever the server is (Little's law); a maximum is mostly the first half second, when every stream is submitted at once; and what a server owns is the p99 over the median, which here was a run queue that spills its oldest half and not anything in nilo. A client that reports a mean and a maximum cannot say which of the three a number is, and a `ghz` run at a tenth of the server's rate measured the client. ([the run](../bench/result/http.md#where-a-grpc-calls-worst-latency-comes-from))

## Where the cost turned out to be

**A suspended fiber holds its stack at its high-water mark, so the arena is cheaper than the stack.** A handler returning a constant held 8,749 bytes a connection; one that only touched 8 KiB of stack held 17,932, database or not; 128 KiB held 140,787, one byte per byte touched, for the life of the connection. `var buf: [64 * 1024]u8` in a handler is 64 KiB times every connection that reached the route, and a frugal-looking streaming route cost 12,876 against 8,782 for pulling the whole megabyte into the arena ([ADR 062](./adr/062-where-a-connection-waits-is-what-it-costs.md)).

**Where a connection waits is what it costs.** Releasing idle stack changed nothing at first, because the connection handed its pages back and then slept 4 KB deeper in `readHead`: a release is measured at the frame the fiber sleeps in, and a page of margin is not a page of safety. Moving the wait to the shallowest frame took 8,767 to 4,669, and letting the connection loop run the WebSocket loop took 9,290 to 5,183 ([ADR 062](./adr/062-where-a-connection-waits-is-what-it-costs.md)). A change that adds no frame can still move the park across a page: a second caller of the handler cost a plain listener 4,102 bytes under `-Dtls` ([ADR 212](./adr/212-tls-is-an-option-a-build-asks-for.md)). Choosing HTTP/2 or HTTP/1.1 from a connection's first bytes cost +4,096 the same way: the sniff gave `waitForRequest` a second caller, so it stopped being inlined into the loop and the park sat one call frame deeper, under a page boundary it had 300 bytes of room below ([ADR 259](./adr/259-http2-is-a-framing-of-every-request.md)); and with the sniff itself out of line a connection that had said nothing parked in its frame and cost a page too. **Adding a caller to a function can move every connection's park**, so what is inlined on the connection's path is named inline, and the idle figure is read for the connection that has sent nothing as well as the one between requests.

**"Shrink the buffer" is the lever to check last.** Moving `std.http.Client`'s buffers off the stack was worth −66 bytes, and a 64 KiB streaming buffer rebuilt at 8 KiB moved one byte: a stack buffer no byte touches is never a resident page, and the cost is the depth of the call path. That −66 then became +4,096 once idle stacks were handed back and the arena was not; **a "no difference" result is the one nobody re-runs and the one most likely to have changed sign.**

**A format string costs whether or not it is printed.** Four `std.log.warn` sites on cold paths were most of `handleConnection`'s 4,184-byte frame, and `noinline` took the chain from 5,561 to 1,721. In the binary a call site is about 2 KB ([ADR 024](./adr/024-every-failure-answers-as-json.md)). On a per-connection path a `std.log` call is also one lock every connection queues on: a warning per reset WebSocket took 874K frames a second to 461K ([ADR 202](./adr/202-a-reset-between-frames-is-a-client-that-has-gone.md)).

**A generic you wake is linked whole.** `{d}` on an `f64` linked the shortest-round-trip float printer, more than half of metrics' 37,112 bytes (17,416 with integer division). `parseFloat` answering `q=0` in `Accept-Encoding` had cost every binary 25 KB. The `Date` formatter was guessed at 400 bytes and measured 6 KB, because the bill is for everything the first call links ([ADR 197](./adr/197-a-response-says-when-it-was-sent.md)). A six-line function that names a generic is measured like a feature. `std.json.Value`, parsed to read four string keys off a query plan, was +88 KB on a program whose one route is a `db.raw`: a hash map per object and a float parser for numbers nothing reads ([ADR 233](./adr/233-a-raw-statement-is-held-against-its-row-the-first-time-it-runs.md)).

**A call behind a runtime null check is linked, and a call through a pointer that only the opt-in call sets is not.** `app.trace` first added 12,032 bytes to `examples/hello`, which never traces: `if (self.tracer) |t| t.begin(…)` kept the id generator, the header walk, the ring and a URL parse. With the same calls made through pointers set inside `app.trace`, the cost to a program that does not trace fell to 432 bytes, the null checks. The linker only drops what nothing reaches, and a runtime check still reaches everything behind it. [ADR 247](./adr/247-a-request-is-a-span-and-the-trace-leaves-as-otlp.md), [`http.md`](../bench/result/http.md#what-tracing-and-security-headers-cost-a-program-that-does-not-use-them). The check that remains is not the floor either: Connect's choice on the failure path was 182 bytes while the error was handed through to the shape, every register below the call chosen again to keep it live, and 84 once the error went to the call that picks the shape instead ([ADR 257](./adr/257-a-connect-client-is-told-its-failure-in-connect-words.md), [`http.md`](../bench/result/http.md#a-connect-client-told-its-failure)).

**A stack frame is measured, not reasoned about.** `std.compress.flate.Compress.init` builds its 96 KB token buffer as a temporary: 99,048 bytes of stack for one call, where result-location semantics were expected to write it in place. `-femit-asm` and `grep 'sub.*rsp'` settled in a minute what the argument got wrong ([ADR 211](./adr/211-a-response-is-compressed-on-a-compressor-borrowed-from-a-pool.md)).

**Half of a release build is debug info; comptime is nearly free.** The frontend with every comptime handler is 0.5 s, LLVM takes it to 7.3 and debug info to 14.7; a specialised handler costs ~59 ms a route. Rust's release profile leaves debug info out and Zig's does not, so "nilo 15.0 s against axum 4.8" compared a build doing the work with one skipping it. Compare CPU against wall before any theory about a slow build: 110 s of CPU in 30.6 s of wall on sixteen cores meant one compilation ran alone, and it was 94% LLVM Emit in a ReleaseSafe test build ([ADR 138](./adr/138-a-test-does-not-need-the-optimiser.md), [`build.md`](../bench/result/build.md)).

**The round trip is the cost, not the query.** A Postgres round trip is 24 µs and the query inside it 2.3, and the server's CPU went from 6.13 µs a request to 21.8 with a query, nearly all syscalls. 215,000 req/s with a query in every request was the first measurement that pg.zig parks a fiber rather than blocking a thread, three years after the design argument. pg.zig spent two round trips per prepared query where pgx spent one, and that extra trip was the whole of its single-row gap to tokio-postgres; taking it out moved pg.zig from 24–63% behind to fastest on seven of eleven shapes ([`sql.md` §16](../bench/result/sql.md#16-the-round-trip-pgzig-wasted-taken-back)). A co-located Postgres is reached over its unix socket: `postgres://user:pass@%2Fvar%2Frun%2Fpostgresql%2F.s.PGSQL.5432/app`, the full socket path, percent-encoded.

**A fixed saving is worth most where the percentage looks best.** A prepared statement saves ~12 µs either way, 30% of a key lookup and 14% of a sorted page; a service's mix is mostly cheap queries, which is why it is on by default. The pool is a curve too, and its p99 turns (best at 32 connections) before its throughput does.

**An atomic load is one the compiler may not fold, hoist or vectorise.** A lock-free cache read was 13% slower on one thread until the bucket scan used `unordered` loads and the cursor was passed rather than read twice ([ADR 152](./adr/152-a-lookup-asks-the-cursor-afterwards-instead-of-taking-a-lock.md)). A reader-writer lock was +11% on eight threads and −11% on one: two atomic read-modify-writes are a large share of a 30 ns lookup, and one thread pays them for nothing.

**Price the cache against the cheap fix before building it.** A 19 MB argon2 buffer faulted 4,864 pages, 2.2 ms a hash; `MADV_HUGEPAGE` made it ten faults, and a warm re-used mapping was no faster, so a 152 MiB buffer pool would have bought nothing ([ADR 044](./adr/044-a-password-hash-is-gated-because-forgetting-is-silent.md)). `getrandom` measured 56 ns through the vDSO, which killed a per-thread CSPRNG with its fork hazard ([ADR 042](./adr/042-entropy-belongs-to-the-loop.md)).

**An allocation's size is not what it costs.** Growth past the retained arena block is an `mmap` and `munmap` per step: 16 KiB steps cost 35% of a 64 KiB body and doubling saved almost none ([ADR 083](./adr/083-a-body-is-taken-as-it-arrives.md)). A separate allocation costs the next power of two (320 measured 512), and a masked ring rounds a 12 MiB budget down to 8. A slot is paid for whether or not anything is in it: halving it and doubling the ways took the cache from 125.8 bytes an entry to 63.3.

**A configured maximum is not a cost.** SQLite's default `cache_size` of 2,000 KiB went into an ADR as per-connection memory; a connection holds 28 KiB opened and grows towards the ceiling only as it touches pages, and on key lookups the ceiling saved nothing.

**A shared pool sized for somebody else's use case is an accident waiting.** `nilo.blocking`'s default of `cpu_count * 2` suits disk waits; argon2id is bound by memory bandwidth, peaks at 16 concurrent and falls at 32, and ungated sign-ins would have queued every session cookie behind them. At 13 ms a hash it also sits under the blocking detector's floor, so forgetting the hop was silent, which is why the Gate exists ([ADR 044](./adr/044-a-password-hash-is-gated-because-forgetting-is-silent.md)).

**A fast path with a fallback has two numbers.** `covers` sends the *whole* value to `std.json` when one type in it is not nilo's to write, so a single union cost a response 2.8–3.2× ([ADR 016](./adr/016-the-api-description-comes-from-the-signatures.md)) and `sql.Uuid` did it to every response of a port with 145 uuid columns ([ADR 148](./adr/148-a-field-name-is-a-spelling-too.md)). Ask what fraction of real values a comptime check refuses, not only whether it is correct.

**A rule that costs a syscall per response may be standing in for a guarantee.** Flushing on every `send` gave a pipelining client sixteen `send(2)`s for sixteen requests. What was wanted was *a response is on the wire before the connection next waits*, and moving that into the Engine gave 4× and 10× on the pipelined shapes with the others unchanged ([ADR 201](./adr/201-a-response-is-flushed-before-the-connection-waits.md)).

**Making the router scan cleverer lost twice to making it read less.** One request was 585 ns of nilo's own work, and a 25-route app spent ~9% of it matching. A packed parallel array of the fields a rejection reads was +7% on one route set and −10% on another, and was reverted; a real hash of the first segment cost more at one route than the `mem.eql` it saved, and one route is what most apps have. Four bytes of the first segment compared as one `u32` took 44% off a 100-route app for 2 ns at one route, moving ADR 017's 10% crossing from ~30 routes to ~40. **And the synthetic tables measured the case the filter was built for.** Every `/thingN` route starts with a different word; the first real application to report put 276 routes under one `/api`, where that key throws out nothing, and matched at 125 ns, 35% of a request. A tree searched in ADR 012's order took it to 27 ns, and returning the 300-byte `Match` through the caller's pointer instead of by value was a third of that saving and every request's, one route included ([ADR 012](./adr/012-the-most-specific-route-wins-and-duplicates-are-refused.md), [`http.md`](../bench/result/http.md#matching-on-a-real-table-of-276-routes-under-one-prefix)).

**A block recycled while a send still names it corrupts the response.** A per-thread block cache read as worth 10,229 → 14,365 req/s cannot be built as described: an `io_uring` completion holds the pointer, not a copy, and the arena has no idea a write is outstanding. The motivating number came from a 32 MB L3 this box does not have ([`decided.md`](./decided.md)).

**The two optimisations a decoder was expected to need moved nothing.** Closing a generic protobuf decoder's 13% gap to a hand-written one, a slab for the repeated slices (1,039 allocator calls to 38) and a short-string UTF-8 check (4 times faster in isolation) changed the end-to-end number by 0.2 ns a row; a table that finds a field from its key byte, and a reader that keeps its position in registers, took the decode from 105 to 80. Both stayed for what they hold on other axes, and the list of what to try had been written before any of it was timed. What is left is a second pass, 15 ns a record, which a stage timing found and the first guess (the allocator) had hidden ([`bench/result/proto.md`](../bench/result/proto.md)).

**A unary gRPC call's cost was the scheduler, not HTTP/2.** 3.12M calls a second inline against 0.77M with a fiber per call, of which the fiber itself is 0.23 µs; the rest is zio dealing each spawn to another executor ([ADR 220](./adr/220-grpc-is-served-over-h2c-behind-a-flag.md)).

**Before paying for new state, look for a Debug-only counter that already tracks it.** `sql.problem` could not tell two requests on one keep-alive connection apart in a release build and read the earlier request's Problem out of freed memory; the fix on the table was a new serial on every Scope, and the count already existed as `Lifetime.gen`, kept only for the `Str` trap. Letting it run in every build cost +24 B of binary and nothing measurable per connection ([ADR 117](./adr/117-a-statement-that-failed-says-what-the-database-said.md), [bench](../bench/result/http.md#what-a-request-serial-in-every-build-costs)).

**A protocol's per-request cost was a dozen small things, none of them its codec.** The suspects for HTTP/2 costing 2.5 times HTTP/1.1 were HPACK and the fiber spawn, and the breakdown cleared both: the rest was clock reads, copies and passes over the same bytes. Count each read, copy and pass of the path before choosing the large mechanism, and sample the real server as well as the in-process profile, which cannot see an Engine. A stamp saved by reading the clock less often must be tested behind a slow upload, where it goes stale ([`bench/result/http.md`](../bench/result/http.md#what-a-request-on-http2-costs-once-its-clocks-copies-and-passes-are-counted)).

**A constant standing in for a measured thing deletes whatever it feeds.** A message read as JSON was slower than a plain struct and the slow read of the head was blamed; a run with the read replaced by a constant "closed" the gap, but the compiler had folded the choice of spelling away with it. A string the optimiser cannot see through showed that about two thirds of the gap remained after the read was made 3.5 times faster. Take a cost out with a value the optimiser cannot see through, and expect more than one cost under a number named after one (`bench/result/http.md`, "A header is looked for by the lines that can hold it").

**Count the writes before blaming the cipher, and a number that is far from its sibling is a copy or a syscall.** Two figures on a TLS listener were 35% and 2.6 times off their other protocol, and with no tracer on the host the code gave the causes: the record library flushes to the socket after every record it seals, so a frame's 9-byte head was a record and a write of its own; a file read through a 4 KiB write buffer was a `pread`, a record and a write for each 4 KiB; and HTTP/2 copied a megabyte into the arena that HTTP/1.1 writes from where it lies. Each change was measured alone (spilled 0.58 to 2.4 GB/s, held over HTTP/2 1.7 to 3.1), and the faster form that left records unsent behind an empty-looking writer was refused, because callers flush only `if (end != 0)`. The same afternoon a stream's weight that moved between 6 and 12 KB with the speed of the client was not the allocator's: it was how many fibers were alive together, each leaving a pooled stack with its 15 KiB resident ([`http.md`](../bench/result/http.md#what-a-tls-write-is-sealed-in), [`http.md`](../bench/result/http.md#the-spread-of-a-handed-over-stream-is-the-engines-stack-pool)).

## Tests that could not fail

**A check that has only been seen to pass and a check that cannot fail look the same** ([ADR 032](./adr/032-a-guard-is-not-a-guard-until-it-has-been-seen-to-fail.md)). `zig build test` printed a red block every run while every run passed, and underneath it a log function in `http/test_root.zig` had never run, because the root of a test build is the compiler's runner and it declares `std_options` itself; a cached run step then executed the binary once in six runs. A lock-free soak's 542 million verified hits said nothing until deleting one cursor read produced 14,564 wrong answers. **Break the thing on purpose and require the failure**; that has caught a guard, a fix, and a test passing through the branch it was written to avoid. An `expectError` passes for any path that raises the error: the live tests of `db.raw`'s first-run check passed with the check switched off, because a `LEFT JOIN` over an empty table fails at the row with the same `error.QueryFailed` the check returns. The data now finds a row every time, so only the check can refuse it ([ADR 233](./adr/233-a-raw-statement-is-held-against-its-row-the-first-time-it-runs.md)). A file its module imports for its functions runs none of its tests: `rawcheck.zig`'s 28 had never run, because `sql.zig`'s `test { … }` did not name it and nothing else does; the first one written against it passed a filter that matched nothing ([ADR 124](./adr/124-a-raw-statement-cannot-cast-what-it-did-not-write.md)).

**A fixture made of easy cases tests the easy cases.** `sql.Timestamp`, `Uuid` and `Json(T)` all had unit tests and none could be read from a database, because the live fixture was `bigint`, `text` and `integer`; the fix added those three and not the enum column the roadmap already called fatal. `sql.Bytes` was tested on SQLite only and failed the first Postgres `bytea` sign-in: a type two files name by contract is two tests ([ADR 141](./adr/141-bytes-are-a-type-not-a-second-protocol.md)). A redundant `NOT NULL` walked round a rowid bug ([ADR 050](./adr/050-a-view-or-a-rowid-alias-is-not-a-nullable-column.md)), every date was after 1970, every migration step was one line. The HPACK list-bomb test used only static-table references, which are never copied, so a guard that counted a field after copying it passed, and one byte referencing a 4 KB table entry cost 4 KB of arena ([ADR 220](./adr/220-grpc-is-served-over-h2c-behind-a-flag.md)). A stand-in is a fixture too: `wire.Fake` answered one value per type, so a stream that forgot to step past an optional parent's presence column read the parent's name out of it and every test passed. Answering per column, the same mutation fails. **A known gap and an untested path are the same fact, and only one of them fails a build.** It happened again in one audit: every `Decimal` ordered in a test had the same number of digits, so a text sort and a numeric one agreed, and every grouped Row's parents had different names, so grouping by the name and grouping by the key agreed; the fixtures that caught both are `9.00` against `10.00` and two customers named Ani ([ADR 218](./adr/218-a-row-may-carry-its-parent-its-children-or-a-sum.md)).

**A fixture dated relative to today tests today.** The SQLite example seeded three invoices thirty days apart and asserted three months in its report; on the 30th of September two of them landed in August and the suite went red with no change to the code. A step of 31 days cannot share a month, because no month is longer.

**A method on a generic struct is analysed only where it is called.** `db.one`, `tx.raw` and `.in` had compiled exactly never while looking finished, and SQLite's whole write half was never compiled by `zig build test` ([ADR 067](./adr/067-a-value-is-whatever-the-database-stores.md)). For a type generic over a seam, the coverage figure is how many seams the tests instantiate. A documentation block that only declares types proves it parses and nothing more, for the same reason.

**A test of the string is not a test of the statement.** `sql.given` had four comptime tests asserting its SQL and Postgres refused every one, because a parameter is typed at its first use; `rename_all` was tested on three fields and ran out of branches at ten ([ADR 149](./adr/149-a-filter-that-is-absent-is-not-a-filter-that-is-null.md)). The `.sql` twin of a migration had four green text tests and an `INSERT` with an unclosed column list, found by handing it to a database ([ADR 123](./adr/123-a-migration-is-a-diff-against-a-snapshot.md)). A generated file nothing compiles is a file whose shape is unchecked ([ADR 123](./adr/123-a-migration-is-a-diff-against-a-snapshot.md)).

**Both optimize modes are the gate, and they are two processes.** A `Response` header slice built from a runtime value lived in the handler's frame: 175 tests passed in Debug and the README's flagship example segfaulted in release ([ADR 018](./adr/018-a-response-owns-its-headers.md)). An assertion behind `if (traps_enabled)` is no assertion in ReleaseSafe ([ADR 093](./adr/093-a-guard-against-double-release-is-not-a-debug-trap.md)), and a test's ReleaseFast arm was the one arm the suite never builds. `test-s3` runs both modes at once against one server, so two binaries raced on one key: a test that passes alone and fails under `zig build` has said which kind of bug it is.

**A test can pass through a mechanism other than the one it names.** A redirect test got its 200 from the stale-connection retry re-sending the original URL, and only an assertion on `head.redirected` saw it. A test one layer under the bug stays green while nobody can reach the fix: `snapshot.parse` asserted a diagnostic every caller passed `null` for ([ADR 181](./adr/181-the-marker-has-two-kinds-of-word.md)). Test on the path a person takes. `fetch-check` built its dependent against nilo by path, which sees the whole working copy, so when `embedDir` started reading `examples/embedded/dist` at configure time, a directory `.paths` does not ship, the check stayed green while every real dependent failed before its first step; it now builds against a staged copy of exactly what `.paths` ships.

**A lifetime test that hands the code an arena tests nothing about lifetimes.** `std.json` over a slice returns strings that point into the input unless told `.alloc_always`, so `verify` handed callers claims inside a scratch arena it had freed, and every test passed an arena. Free the answer string by string on `std.testing.allocator`. The `Str` staleness trap was likewise tested on one keep-alive connection, the one case that could not miss, while two `curl` calls read stale bytes silently.

**A differential test only finds what its two halves disagree about.** The reference parser was written from the same reading of `Transfer-Encoding` as the fast one and passed four framing bugs and `chunked, identity` ([ADR 070](./adr/070-a-request-nobody-else-would-answer-is-refused.md)). The first thing a differential catches is its oracle, and a corpus has to be seen to decode: every entry once replayed as empty input and the suite was green while testing air. A new refusal upstream of a corpus can retire the whole corpus while it stays green, so the corpus is part of the change. A fuzzer's generator is a test subject as well: random SETTINGS values sent every connection away and 0 of 2,000 answered a call. A fake written from the client's reading of a spec is the same pair: `canned.zig` only trimmed a SigV4 header value as the client did, so a tab inside `cache_control` was signed and accepted by both while S3 folds it and answers 403; the fake now folds the way S3 does ([ADR 060](./adr/060-a-signing-key-changes-once-a-day.md)).

**A concurrency test that does not oversubscribe tests only the interleavings the scheduler picked.** A writer lapped inside its own `memcpy` gave 7 wrong answers in 1.9M with more threads than cores and 0 in 34.9M with one each ([ADR 109](./adr/109-a-cache-holds-its-bytes-under-a-lock-it-can-spin-on.md)). A race narrow enough that the obvious hammer cannot reach it gets certified absent; hold the window open on purpose. A flaky test is a coin: make it deterministic and read the error name before believing "racy under load" ([ADR 058](./adr/058-most-of-an-s3-client-is-not-s3.md)). A flaky failure bisected once produces a clean-looking table and a wrong theory; re-run the clean side.

**A proof about ordering carries its architecture.** ADR 152's lock-free read was sound on x86, which does not reorder two stores, and handed back another key's bytes on aarch64 in five runs of nine; audit the direction each `seq_cst` does *not* pin ([ADR 152](./adr/152-a-lookup-asks-the-cursor-afterwards-instead-of-taking-a-lock.md)). A machine you have not run on is a set of constants you have not tested: 16 KiB pages on Apple silicon made a scratch-buffer test assert nothing.

**A behaviour whose only signal is a log cannot be tested here.** Zig's test runner fails a run on any `std.log.err`, whatever `std.testing.log_level` says. So in nilo `err` means the server is refusing to start and everything on the request path is `warn`; when a test needs the failing branch, split the decision from the sentence (`migrate.standing` returns a verdict and `expect` announces it) or assert on the input the other system was given (`SHOW transaction_read_only`). A diagnostic that cannot be provoked gets deleted rather than fixed. A suite whose database was down skipped 95 tests, failed none, and exited 1 behind 190 `err` lines ([ADR 145](./adr/145-a-suite-whose-database-is-down-is-not-a-suite-that-failed.md)).

**A behaviour whose only evidence is an absence survives every test that has a database.** `connect_on_init` had never worked ([ADR 115](./adr/115-a-boot-dials-the-connection-its-work-needs.md)); the schema check never ran on the defaults ([ADR 115](./adr/115-a-boot-dials-the-connection-its-work-needs.md)); a `switch` arm that turned an error into `QueryFailed` deleted the only word that said why ([ADR 117](./adr/117-a-statement-that-failed-says-what-the-database-said.md)). An option whose default disables a feature somewhere else is invisible from both files. A defect whose only symptom is a number nobody prints, a reconnect after every failed transaction, was pinned by reading the driver's own counter ([ADR 043](./adr/043-a-deadline-needs-a-connection-you-hold.md)).

**A check that works against the clients you have is not a check.** The `Bearer` scheme was matched case-sensitively in nilo's own example and guide ([ADR 153](./adr/153-an-authorization-header-a-handler-can-ask-for.md)), and `clientIp()` read only the first `X-Forwarded-For` field, fine behind nginx and forgeable behind HAProxy ([ADR 102](./adr/102-a-proxy-is-trusted-by-which-one-it-is.md)). Both were found by reading somebody else's code, because the peer in the tests was always the same one.

**A workaround needs a test for the reason it exists, bound to it.** `nilo.testing.show` asserts that it renders *and* that `{any}` prints `"wati"` as bytes; without the second half, the day std changes the workaround outlives its reason with every test green. Two halves 580 lines apart are a pair that decays into one, so they share a test or name each other. And a test holds the property with a local type, not with an instance like `Uuid` that stays green while the property breaks for everything else.

**Check that a check runs.** `zig build refusals` ran 56 of 105 checks while its name promised all of them, and a row added to one of eight tables while another step runs is a check that never executed. The build step matches `.says` with `endsWith`, so a prefix of the message never matches. A `<!-- compiles -->` mark on a page the step did not list looked checked, and two more were copied from one of those the evening the gap was discussed: **a broken instance of a convention is indistinguishable from a working one when read, and reading is how conventions spread**, so the step now finds the pages itself.

**Build a throwaway dependent before calling a module done.** Eighteen green migration tests; a ten-line project importing `nilo_sql` found three bugs in five minutes (a missing `makeDir`, an array where a slice was meant, multi-line SQL printed flush left). A test calls a function with the convenient argument and a dependent uses it. The first stranger's application found that every guide recipe worked only on one database or in one order ([ADR 180](./adr/180-work-that-needs-the-services-runs-on-their-loop.md), [ADR 204](./adr/204-a-raw-placeholder-is-spelled-for-the-dialect.md)); a first boot is the one boot nobody's test runs twice.

**A harness borrowed from outside finds what the local one is shaped not to see.** Autobahn passed the WebSocket framing, 294 OK and 0 failed, and left the server spinning five cores: six connections then a SIGTERM hung three runs in four, because a completion the loop still held was written into a frame that had been handed on ([ADR 077](./adr/077-a-completion-the-loop-holds-outlives-the-frame-that-submitted-it.md)). No in-memory test could have reached it.

**A dependency bump is not verified by the suite that passes after it.** The pg.zig fix for a double unlock moved its reconnector onto nilo's loop and the panic came back from zio instead; `test-all` was green while two throwaway programs, one refusing to start and one booting with the database down, panicked on both pins ([ADR 121](./adr/121-a-service-is-stopped-before-the-loop-is.md), [ADR 122](./adr/122-the-panic-under-the-panic.md)).

**Half a detector's job is not firing.** Three of the watchdog's seven tests prove it stays quiet; one that cries wolf gets switched off, and then its absence looks exactly like its silence.

**When a guard is hard to reach, reaching it is the design problem.** An expiry only a wall clock can pass will only ever be seen to pass; `openAt(T, text, key, now)` turns "wait a day" into three numbers ([ADR 033](./adr/033-a-session-is-sealed-into-the-cookie.md)). The deadline vtable did the same for "armed once however many reads", a counting assertion instead of a real wait ([ADR 022](./adr/022-a-deadline-belongs-to-an-operation-not-to-a-request.md)).

**A test that looks after the run cannot see what was true during it.** `Overlap.queue` had a test, and it counted rows once the tick had finished, which is the same number `.skip` gives; the promise was about the queue *while* the tick runs, and only a read from inside `run` showed it was never kept. A cron `next` guarded by a count of turns hung for minutes on `0 0 31 2 *`, because each turn cost more than the last: a bound has to be in the unit the cost grows in, here years of calendar ([ADR 161](./adr/161-a-schedule-is-a-type-that-makes-the-caller-choose.md)).

**An entry point that only a running server answers has no test until a test can run a server.** `nilo.io()` in an `app.spawn` fiber was exercised by a spike's scratch project and curl, and the tests reached the same code through `Wired`, which answers a `Threaded`. The missing piece was not a test but a helper: `testing.Live` starts `listen` as an `io.concurrent` task on port 0, so the next live test is a dozen lines instead of the thread, the flag and the port loop each file had written for itself ([ADR 244](./adr/244-a-handler-is-given-the-loop-it-runs-on.md)). A writer that must wake while idle has no `get` with a deadline to use, and the shape that works is the queue plus an event reset before the drain.

**A stall that needs a second message right behind the first is invisible to a test that sends them one after the other, and to a code read.** A WebSocket over TLS was carried in the todo list as "read from the code, not run": `Wake.wait` polls the socket, and tls.zig decrypts one record a call, so a second record already read with the first would be waited for on a socket the kernel had emptied. Nothing sent two records fast enough until HTTP/2 over TLS did, and `bench/mem.py --tls --h2` stopped on one connection in a thousand; the HTTP/2 test written beside it passed on its first run and failed when the suite was loaded. Only putting both records in one socket write (the client's `output` pointed at a buffer for two flushes) made the failure the same every time, and then removing the fix made it fail every time ([`bench/result/http.md`](../bench/result/http.md#what-offering-h2-to-a-browser-costs)).

## A suite that hangs, and a build that looks stuck

**Take the CPU time before believing a build is slow.** `ps -o etime,cputime -C zig` first, `ps --ppid <pid>` for the child's own CPU, `/proc/*/task/*/wchan` for the thread parked in `accept`, `gdb -p` for its stack: twenty seconds once the build is suspected rather than waited on. A documented slow path, the refusals, is the best hiding place a hang has. The readings that all look like "slow":

| what you see | what it is |
|---|---|
| `etime` high, `cputime` near zero | a deadlock, or something waiting on you (`--time-report` stands up a web server) |
| both high, `free` near zero | an OOM kill |
| no process, no `Build Summary`, no log | the machine was taken (macOS): read `vm.swapusage` and physical footprint, not `ps` RSS |
| an empty output file | `2>&1 \| tail` holding the log until the pipe closes |
| green | possibly about a tree edited since the step read it: stop editing, then run, then commit |
| eighty live tests failing at once | one cause, most often the machine (a full disk failed every fixture): read the first failure's message before the count |

**A wait needs a bound, and the giving-up path has to set something.** `fetch/deadline.zig` gave up a port scan by returning without setting the flag the test waited on, and its third deadlock was an `accept` six lines below the second, unbounded by `done`. A suite that never finishes reports nothing, which is strictly worse than the failure that caused it, and **work that lands behind a hang is unreviewed**: three broken tests shipped behind one.

**`io.async` may run its function on the calling thread.** `std.Io.Threaded` allows `cpu_count - 1` tasks and runs the rest inline, so on two cores a test's listener sat in `accept` on the very thread about to connect to it. A listener a test connects to is started with `io.concurrent` ([ADR 056](./adr/056-the-way-out-was-open-the-clock-was-not.md)). Before changing anything the call sites were counted: fifteen default `Threaded`s standing on a latent hazard is a paragraph, not a change to two modules.

**A test tuned against a kernel default has no margin.** A body of 128 KiB was exactly `tcp_rmem`'s default and hung depending on autotuning. Size for the ratio the test is about, and make the worst case a wrong tally with a line number rather than a hang. The machine's speed is the same kind of default: on the loaded macOS runner a 60 ms sleep was measured at 135 ms, so fetch's trickle tests, whose gaps sat within a few hundred milliseconds of their silence bound, failed there and nowhere else until they got a one-second bound. **Nothing a timing test sets up may run inside the clock it measures**: the route-deadline test filled its 96 MB answer inside the handler, a loaded Mac took longer than the 200 ms deadline to do it, and a write that begins after its deadline goes out under the ordinary thirty-second limit ([ADR 105](./adr/105-a-route-can-say-how-long-it-has.md)), so the test waited out the thing it was written to prove gone. It failed three macOS runs of eight and was filed as an Engine fault ([#9](https://github.com/nevindra/nilo/issues/9)).

**A loop that is never idle never reaches a cancellation point** (`io.checkCancel` at the top of a worker loop), and **a read that issues another statement issues it after the first has let go**, or one request holds two pool connections.

**A cancel is one signal, and a catch that turns it into its own error spends it.** cid's server stayed up after SIGTERM with every thread idle, now and then: its background worker was mid-job when the stop came, the cancel landed in an S3 call that cid reported as a storage error, the job carried on, and the worker's next `nilo.sleep`, the wait that was meant to end it, slept as if nothing had happened while `listen()` waited for it. Fifteen seconds and `/proc/*/task/*/wchan` showed sixteen idle executors and no log line from the worker's exit, which is what pointed at it. A spawned fiber's `sleep` now refuses while the server is going ([ADR 028](./adr/028-a-spawned-fiber-belongs-to-the-server.md#a-swallowed-cancel-does-not-keep-the-server)); any other wait after a swallowed cancel still needs `recancel`.

**A benchmark is a machine state.** Ten thousand keep-alive connections left the ephemeral range in TIME_WAIT, which is what finally made a rare failure path in a test ordinary. Fixed port windows in two files overlapped and ran out from the sixth run; binding port 0 and reading the address back, which std had done all along, ended the port walks. `reuse_address` is refused because it sets `SO_REUSEPORT`, and two test binaries silently sharing a port is worse than one failing to bind.

## Claims that decay

**A number with no run behind it decays into a claim, and a premise decays the same way and costs more, because a wrong premise gets planned against.** `connect_on_init` was documented in three files and had never worked ([ADR 115](./adr/115-a-boot-dials-the-connection-its-work-needs.md)); "8,767 bytes, flat" described a handler nobody deploys and was republished in six files after its first correction ([ADR 062](./adr/062-where-a-connection-waits-is-what-it-costs.md)); three modules sat "blocked" on a seam open since ADR 037 on the strength of a manifest nobody opened; `nilo_fetch`'s 16,495 bytes were retired by our own commit two days later and the entry stood for a month. **A number is a claim about a commit, and the next commit can retire it**: re-run the ranked lever before quoting the ranking. A number in a code comment decays the same way: the 600 ns clock gap `bulkhead.zig` recorded had stopped existing in Zig 0.16 ([ADR 041](./adr/041-core-knows-what-time-it-is.md)). So does one nobody counted: the cache's fingerprint was documented as fourteen bits and a wasted probe in 2,048, and read the hash bits the shard is chosen by, so 256 values occurred in a shard and the rate was one in thirty; three readers of one hash have to read disjoint bits by construction ([ADR 152](./adr/152-a-lookup-asks-the-cursor-afterwards-instead-of-taking-a-lock.md)). A plan read under one setting decays into a claim about every setting: `starts_with` was on the roadmap as losing its index "once the statement goes generic" on Postgres, read off a forced generic plan, and asked eight times Postgres never chose one; the database that did scan was SQLite ([sql.md §21](../bench/result/sql.md#21-where-a-prefix-pattern-is-built)). A premise about who runs what decays into a claim about what exists: `nilo-dev` pruned every cache directory holding its binary's name because nobody builds that binary beside its dev loop, and yesterday's build for another target needed nobody running it to be named by its own manifest, so it failed with `FileNotFound` on every run after; what is safe to delete is read off the cache's model, one manifest per configuration, not argued from habits ([ADR 190](./adr/190-a-restart-on-save-watches-the-binary-not-the-sources.md)).

**"Blocked on somebody else" gets one more hour, and "blocked on a design" two.** Broadcast waited on a zio API that was public in the pinned version (`CompletionQueue`); the stack fix on `Coroutine.getCurrent()`, public one file over; writing an upload to disk on `Dir.createFile`, in zio all along ([ADR 097](./adr/097-a-file-is-written-by-the-engine.md)); a bound port on `getsockname`, which `std.Io.Threaded` already called; RS256 on RSA "not being in std", because a survey grepped filenames and `std.crypto.Certificate.rsa` lives in `Certificate.zig`; a signer hook in tls.zig, whose fork nilo already publishes ([ADR 217](./adr/217-a-handshakes-signature-is-computed-off-the-executor.md)); and a fork of pg.zig kept "until lalinsky/pg.zig#13 merges" after both commits were on lalinsky's `master` under the same hashes, with the pull request still open: the row named the pull request and not the commits, and the commits are what the pin needed ([`sql.md` §16](../bench/result/sql.md#16-the-round-trip-pgzig-wasted-taken-back)). **A blocker names the thing needed, not the request for it.** Nothing downstream ever re-tests a blocker, and an entry that reasons carefully from an unchecked premise reads as the most finished item on the page. The canonical account is the last section of [ADR 062](./adr/062-where-a-connection-waits-is-what-it-costs.md). "The layer below cannot fix it" is not "nobody can" either: `std.testing` cannot render a custom type and `nilo.testing`, one layer up, already could ([ADR 137](./adr/137-a-failed-assertion-that-can-be-read.md)). "Waiting for a caller" is the same blocker with nobody to re-test: decoding a gRPC call's header block, 28% of the call, measured and linked, sat under that heading asking for somebody who had noticed, and a framework fast enough that nobody writes in about 250 ns never sends one. A list sorted by what an entry waits for hides what it costs, so the todo list is now sorted by the cost ([ADR 255](./adr/255-the-todo-list-is-ranked-by-evidence-and-the-roadmap-is-written-from-it.md)).

**A requirement written as one mechanism reads as a blocker; written as what it has to catch, it reads as a choice.** A body deadline "zio's `Timeout` cannot express" became a deadline per read run ([ADR 022](./adr/022-a-deadline-belongs-to-an-operation-not-to-a-request.md)); `contains` "needing an allocation per condition" became an `ESCAPE` inside the statement ([ADR 140](./adr/140-the-database-escapes-the-pattern-it-is-going-to-match.md)); bytes "needing a second protocol" became one more type ([ADR 141](./adr/141-bytes-are-a-type-not-a-second-protocol.md)); "a runtime sort is two statements" became comptime fragments chosen by index ([ADR 165](./adr/165-an-order-chosen-at-run-time-from-a-closed-set.md)); `.references` "needing the target's type in scope" became a lookup in the one list of Rows every tool already walks ([ADR 181](./adr/181-the-marker-has-two-kinds-of-word.md)); gzipped request bodies waited on a pool of compressor windows when a decompressor's window is the destination buffer. A rule written as its example is read as its example: "a `memcpy` and nothing else" kept an integer add out of a lock for a cycle ([ADR 109](./adr/109-a-cache-holds-its-bytes-under-a-lock-it-can-spin-on.md)).

**"Not worth copying" is a claim about a caller, and the first real caller can falsify it.** `json.zig` left floats to `std.json` because how it chooses between `12.5` and `1.25e1` was not worth reimplementing, and for a year nobody had a program that cared. The first large program ported to nilo (photon, from Rust) compared a recorded response byte for byte and differed at byte 19, `1` for `1.0`, and 14 of 26 edge floats differed, one of which `std.json` writes as 320 characters. The fix was smaller than the objection: shortest digits already come from `std`, the rest is layout, and the result is faster and links less than `print("{}")` did ([ADR 096](./adr/096-a-byte-that-is-not-text-is-not-a-string.md), [`bench/result/http.md`](../bench/result/http.md)).

**A roadmap entry that names a mechanism should say whether the mechanism was tried.** Rate limiting's "fixed table sized at `listen()`" was impossible, since a middleware has no startup hook, and a table sized while compiling replaced it ([ADR 092](./adr/092-an-allowance-is-a-table-sized-while-compiling.md)); "honour `timeout_ms` in `take`" named a timed wait `std.Io.Condition` does not have ([ADR 107](./adr/107-a-wait-for-a-connection-has-a-bound.md)); CSRF sat open as "every framework ends up with a token in the session, a hidden field and a compare", a mechanism a sealed session and a server with no templates could not carry, while browsers had been writing `Sec-Fetch-Site` for two years and the check needed no token at all ([ADR 224](./adr/224-a-request-that-changes-something-says-where-it-came-from.md)); the single-page fallback's `fetch` and deep link were written down as "indistinguishable at this layer" for a release, and `Sec-Fetch-Mode` told them apart, so a mistyped API path answered `index.html` with a 200 until a port to Zig found it ([ADR 087](./adr/087-a-fallback-answers-a-navigation-not-a-missing-asset.md)). **A design blocked on what the compiler does is blocked on nothing**: what `@typeName` prints for a sibling file, whether a library can read the program's optimize mode ([ADR 069](./adr/069-a-library-can-tell-what-mode-the-program-was-built-in.md)), how `@setEvalBranchQuota` reaches its caller, each a ten-line program.

**An entry that guesses at its own answer stops anybody taking the number.** "May well be nothing" sat under *Waiting on: a number* for a cycle; the service registry measured 1.2 ns an entry, a threshold (13.4% of a request at 32 services), which neither half of the guess had room for. An entry states a number or states that nobody has taken one. An entry that calls a saving "free" has named the one thing to check first: `result_state_size` also sizes pg.zig's parameter-OID array.

**An explanation that fits the number is not evidence, and a mechanism that explains a result is the most expensive thing to be given before you have one.** quick_cache's lead was explained as values kept in its table and was a shared lock and fewer writes, found by opening `shard.rs` ([`cache.md`](../bench/result/cache.md)). Two theories for 16 KB per connection both arrived with arithmetic that worked, and **a number that matches a constant you recognise is the most convincing wrong answer available**. A coherent extra-round-trip theory died when the packet counts came back identical. And a reading that applies the right rule can still be about nothing: a logger buffer that looked inlined built byte-identical both ways.

**The documentation was believed and the thing it documents was not opened.** Two sessions gated a merge by running seven steps by hand because `CLAUDE.md` did not say `test-all` depends on them; `build.zig` did. A mechanism asserted ("the module is behind `-Dsql`") is worse than a conclusion asserted, because it reads as the checking already done. A count is a claim with an expiry date and a merge is when it expires: cite what a line says, not where it sits.

**The unit that needs evidence is the clause, not the sentence.** "Boots with the database down, connects when it comes up, serves 134,967 requests a second, and shuts down clean" had three measured clauses and a fourth written in the same breath and never run. A consequence is a claim too: "registering `/a/:` twice leaves an unreachable route" was false, because two functions nobody opened refuse it, and the reachable bug was a `*` not counted as a capture.

**A pin is a checksum against the thing it names, or it is a sentence.** `zig fetch …?ref=v0.5.0`, the README's own line, put the tree of `main` in the lockfile, because Zig 0.16's fetcher does not peel an annotated tag; the install lines now carry `#<commit>`. A sentence about what a tool watches is a claim until a save is made under it (`bench/devloop.py`), and an instruction in a release note is a claim with no run behind it ([ADR 181](./adr/181-the-marker-has-two-kinds-of-word.md)).

**A refusal compresses into a slogan, and the slogan is what gets quoted.** "`nilo_config` does not parse a file" was argued entirely on dependencies that never reached a fifty-line `.env` scanner; the line moved to "does not open a file" ([ADR 039](./adr/039-a-setting-is-a-field-and-every-bad-one-is-named-at-once.md)). "Nothing about them can be checked while compiling" pushed 126 defaults and 29 `IN` lists into SQL strings nothing checks, leaving the schema less checked than the vocabulary would have ([ADR 181](./adr/181-the-marker-has-two-kinds-of-word.md)). "One table" was drawn against a builder nobody proposed, and 167 of 272 raw statements fit a Row that declares its join or its sum ([ADR 218](./adr/218-a-row-may-carry-its-parent-its-children-or-a-sum.md)). A rejection holds for the question it answered: "one request deadline is the wrong budget" was true, and the unbounded routes were the ones nobody looked at ([ADR 105](./adr/105-a-route-can-say-how-long-it-has.md)). Re-read the argument, and what callers write past the line, before defending it.

**A bound on a wait is per read unless the arming says otherwise, and a claim of a whole bound is checked at the call that arms it, not at the constant.** Three waits on a stranger were documented as bounded and armed a per-read limit: the linger after a refused request ("one second", eighteen hours at a byte every 900 ms), the drain of a body nobody read, and a WebSocket part way through a frame. ADR 022 had learned the lesson for the head and the buffered body, and each new wait was written after it without it ([ADR 195](./adr/195-a-refused-request-is-hung-up-on-with-a-fin.md), [ADR 022](./adr/022-a-deadline-belongs-to-an-operation-not-to-a-request.md), [ADR 021](./adr/021-a-websocket-is-a-handler-that-does-not-return.md)).

**A decision can be recorded, moved and lost in the move.** ADR 058's one retry for a pooled connection the peer had closed was swallowed by ADR 061's "no retries", which was about somebody else's service; the amendment belongs in the move. A decision deferred to a named future caller is decided by the rules in force when the caller arrives, not when the note was written ([ADR 039](./adr/039-a-setting-is-a-field-and-every-bad-one-is-named-at-once.md)), and it can sometimes be split along the property that deferred it ([ADR 057](./adr/057-percent-is-needed-by-two-layers.md)). A rule changed for one reader is lost by its siblings the same way: `trusted_proxies` replaced the hop count for `clientIp()`, and `host()` and `scheme()`, which ADR 090 had put under the same rule, went on reading the count alone, so naming the proxies as the guide said left `scheme()` at `"http"` behind TLS. Three readers of one trust now call one function ([ADR 102](./adr/102-a-proxy-is-trusted-by-which-one-it-is.md)).

**The proxy is the sentence people quote.** Core was described as "no IO at all" while its rule was "needs no event loop", and a clock sits between the two; the day they disagreed was the only day anybody would notice which was load-bearing. A cost that belongs to a design is not a property of the feature: TLS was refused for "five times the memory" of an idle connection and measured 9,307 bytes against 5,191, because its buffers are handed back at idle like the cleartext pair ([ADR 212](./adr/212-tls-is-an-option-a-build-asks-for.md)).

**A lease is a lock that lapses for its holder as well, so whatever the holder writes afterwards needs a fence.** `nilo_job` reclaimed a slow row by its lease and let the slow worker finish it by `id`, which requeued the row the second worker held; `nilo_s3`'s design page promised that a failed credential refresh failed only its own request while the code failed every request for five minutes. Both were sentences nobody had run, found by an audit that read each module against its own page ([ADR 160](./adr/160-a-queue-is-a-table-in-the-database-you-already-have.md), [ADR 060](./adr/060-a-signing-key-changes-once-a-day.md)).

**An estimate of what one more allocation costs was too kind, and an arm nothing used cost a build 18%.** Before holding every answer was measured, a copy of a 16 KiB to 1 MiB body was guessed at "a few microseconds"; at 64 KiB it was 400 µs of p99, because each copy grew the arena past what it keeps and went to the page allocator every request ([`bench/result/http.md`](../bench/result/http.md#holding-every-answer-until-the-chain-unwinds)). The same stage then made a routed HTTP/1.1 GET 18% slower in a `-Dgrpc` build, through code it never runs: the gRPC arm's collecting functions inlined into the dispatch every answer passes through. Every row the profile breaks out was level, so the cost was in its remainder, and only switching the arm off in a scratch build found it; `noinline` on the two functions took it back ([ADR 254](./adr/254-an-answer-can-carry-trailers.md)). The next stage paid it again the other way round: the request's core made `inline` so a gRPC call could have an entry of its own compiled twice, every function it calls gained a second call site, and the compiler stopped inlining them into the HTTP/1.1 path, +6% on the same GET and 9,920 bytes for a call 1% faster; one entry branching on how the request arrived took both back ([ADR 253](./adr/253-an-answer-is-handed-to-the-framing-that-carried-its-request.md)). Measure the build with the flag as well as the one without, and read the remainder, not only the rows; and a second copy of hot code is a second call site for everything under it.

## Reading somebody else's code

**Read a dependency's manifest before its README, and its source before its field names.** pg.zig takes a `std.Io` and names no zio, which is what lets the live tests run on `std.Io.Threaded` ([ADR 037](./adr/037-a-service-that-needs-the-loop-is-finished-when-the-loop-exists.md)). A field that exists is not a feature that works: pg.zig's `QueryOpts.timeout` is commented out, `startup_parameters` is never written to the startup message, `Pool.initUri` drops `connect_on_init_count`, and zqlite's `columnCount` is `sqlite3_data_count`, zero until the first step. Each cost one `grep`.

**A C library's freestanding mode can replace your program's `memcpy`.** libdeflate under `-DFREESTANDING` defines `memcpy`, `memset`, `memmove` and `memcmp` in `lib/utils.c` as weak byte loops, for a target with no libc. Linked into a nilo build, which has none, its 288-byte `memcpy` won over compiler_rt's for every caller in the program, Zig's own included, and nothing failed: the output was right and the cost would have been spread across every copy nilo makes. It showed only in `nm -S` of the binary. The fix was to leave the file out and write its four other symbols in Zig ([ADR 248](./adr/248-gzip-is-libdeflate-when-a-build-asks-for-it.md)); the check is the size of `memcpy` in a build with the library against one without.

**A protocol can say "failed" in a field the driver does not read, and then the failure reads as success.** Postgres answers a `COMMIT` on an aborted transaction with the command tag `ROLLBACK` and no error, and pg.zig reads the error and not the tag, so a handler that caught a statement's error without a savepoint and then committed was told its work was kept ([ADR 043](./adr/043-a-deadline-needs-a-connection-you-hold.md)). The same review found the second database agreeing with the code for the wrong reason: SQLite keeps such a transaction going, so the suite run against it passed the handler Postgres would have rolled back ([ADR 065](./adr/065-one-writer-is-not-a-setting-it-is-the-database.md)). Ask what the other side sends on the path nobody tests, not only whether it sends an error.

**An assert in a dependency is a panic in the safe modes and nothing in ReleaseFast, and ordinary data reaches it.** Any Postgres array may hold a NULL and an `integer[]` column stores two dimensions without complaint ([ADR 045](./adr/045-an-array-is-a-slice-and-a-slice-is-one-deep.md)). An assert is also a rule the dependency made up and the wire does not have: `std.http.Client` refuses a DELETE with a body ([ADR 174](./adr/174-the-body-decides-not-the-method.md)). Where a dependency has two encoders for one shape, distrust the one used less: pg.zig's `jsonb[]` wrote a NULL one byte short. The same holds for a check a dependency keeps for Debug: zqlite refuses a second statement in one string only there, so a release build ran the first and dropped the rest without a word, and pg.zig's array iterator unwraps an enum label and an element type with `.?` and `std.debug.panic`, so a label the enum lacked took the process down; both are checked on nilo's side of the call now, in every mode ([ADR 055](./adr/055-the-second-dialect-is-the-test-of-the-seam.md), [ADR 049](./adr/049-a-column-type-can-come-from-outside-this-module.md)).

**A bare name in a Postgres `ORDER BY` means an output column before it means a table's.** A `Decimal` is read as `"total"::text AS "total"`, so `ORDER BY "total"` sorted the text and answered `9.00, 100.5, 10.00`; nothing refused it and every test passed. The select list now aliases a cast column `"total#"` so the name reaches the table's column ([ADR 049](./adr/049-a-column-type-can-come-from-outside-this-module.md)). A rename in the select list is a change to what every later clause of the statement means.

**A promise in a doc comment is about the interface; the cost is in whoever implements it.** `std.Io.concurrent` under zio starts a *fiber*, so a blocking C call inside one still holds an executor thread, which is why `sqlite.Options.threading` has no default ([ADR 064](./adr/064-a-file-has-no-socket-to-wait-on.md)).

**A dependency's tests are part of its documentation, and its changelog is a list of failures the old pin had.** The last test in zio's `completion_queue.zig` calls the `cancel()` nilo's `Wake` never made ([ADR 077](./adr/077-a-completion-the-loop-holds-outlives-the-frame-that-submitted-it.md)). zio v0.18 retried `ConnectionAborted` inside `accept`, and under v0.17 one client giving up in the backlog had ended `listen()`: read the callee's error set against what a `return err` turns into a shutdown, which then found `ProcessFdQuotaExceeded` doing the same ([ADR 194](./adr/194-an-accept-loop-that-is-out-of-descriptors-waits.md)). A workaround that kept its reproduction was removed in an afternoon.

**Compare against the thing at your own altitude, and expect mostly "already have it".** tokio yielded nothing; axum, tower and actix-web yielded four one-field changes ([ADR 156](./adr/156-a-route-can-say-how-much-body-it-takes.md) onward), a missing `Date` header, a needless `Connection: keep-alive` ([ADR 197](./adr/197-a-response-says-when-it-was-sent.md)) and a listen backlog of 128. A peer on the same loop, dusty, found two bugs the suite could not. The leftover four are the finding.

**Write the worked example in the other framework's syntax before proposing.** A validation design consistent with three ADRs had two gaps that appeared in ten minutes once the sign-up struct sat beside what a zod user writes ([ADR 193](./adr/193-text-with-a-shape-is-a-type-and-a-rule-about-the-struct-is-a-function-on-it.md)). A design checked only against the repository's own rules is checked for consistency, not for use.

**Isolate a leak in the dependency before believing it is yours.** `std.zon.parse.fromSliceAlloc` leaks on a failing parse when `diag` is null, reproducible in four lines of std. A stack trace stops one frame early the same way: the panic under the pg.zig panic was zio's.

**A conformance suite's first number is one cause, not sixty-seven.** h2spec failed 67 of 146 against the first HTTP/2 server that served ordinary routes, and nearly all of it was one thing: it never sends the dynamic table size update RFC 7541 §4.2 asks of a client after a server's table of 0, so the first block was a compression error. Widening the table on a scratch copy, not in the tree, made the suite's own blocks decode and showed the failures that were real (a stream depending on itself, a `WINDOW_UPDATE` on a stream not open, a window one bit short of 2^31-1, a `GOAWAY` that dropped frames already read). Group the failures by the first frame that went wrong before reading any of them, and keep the experiment out of the tree ([`bench/result/http.md`](../bench/result/http.md#what-any-request-on-http2-costs)).

## Where a rule has to live

**Validate where every caller goes through, not where this caller does.** The cookie check and the request-id check both named response splitting in their comments, while `putHeader` underneath them checked only header names, and a `Set-Cookie` written through `Response.headers` never met the cookie check ([ADR 029](./adr/029-a-header-is-checked-once-and-two-of-them-repeat.md)). There were five paths, and the one that would have forgotten arrived a year after the first. The lesson came round again in 0.6.0: the content type is chosen through `send` rather than set, so it was the one value that never met `putHeader`'s check, and a cookie's path and domain were written beside a value that was checked, unchecked themselves.

**A rule about an API is a rule about all of its callers, and the ones to check are in other files.** "A second `setHeader` is somebody changing their mind" is true of one function and false of a stack: CORS's `Vary: Origin` was overwritten by a gzipped file's `Vary: Accept-Encoding` ([ADR 029](./adr/029-a-header-is-checked-once-and-two-of-them-repeat.md)). `app.use("/api")` also covered `/apiary`, while `static.zig` had compared whole segments since it was written.

**The repository knew it in one file and not in the next.** The signed zero-pad that printed `+1945` was a comment in `sql/cli.zig`; `.alloc_always` was in `http/testing.zig`; the `std_options` trap was in `test_root.zig`'s header; "`warn`, not `err`" was in two comments and missed at the third call. A finding parked in the file where it was found is paid for again by the next person, and a rule in comments rather than a build step is applied wherever somebody happened to remember it. When a check refuses one way of corrupting the wire, read its comment and ask what else the sentence is true of ([ADR 072](./adr/072-two-renamed-names-that-collide-are-refused.md)). `csrf.with` refused the origin `null` while compiling; the run-time list `csrf.reading` reads, and `cors.with` beside it, took it.

**A fix scoped to the caller that found it is the bug with one caller subtracted.** The boot dial was fixed for the schema check and not for the hook that runs next ([ADR 115](./adr/115-a-boot-dials-the-connection-its-work-needs.md)); `revive` was written for `COMMIT` and `ROLLBACK` and not for `ROLLBACK TO SAVEPOINT`, the one statement that exists to run after a failure ([ADR 048](./adr/048-contention-is-what-a-transaction-is-for.md)); a rule written for "the key" did not survive a composite key. ADR 223 held off the cancellation in `release`, `drain` and a transaction's `ROLLBACK`, and not in the `ROLLBACK` that cleans up after a raw statement's first-run check, so a shutdown landing there was dropped and the job ran to the end ([ADR 223](./adr/223-a-statement-cut-off-by-a-cancellation-hands-it-back.md)). A closure argument, "every leaf has a negation" ([ADR 052](./adr/052-a-set-operation-over-one-table-is-a-condition.md)), is a claim about a set that keeps growing and needs a test that walks the set. `db migrate` refused a version edited after it ran, and `applyPending`, the same runner called from a program's own boot, applied the versions after it on top ([ADR 123](./adr/123-a-migration-is-a-diff-against-a-snapshot.md)).

**Advice the tool prints is a code path, and it needs a test that runs it.** The diff's Problem for a SQLite column change spelled out the four-statement rebuild, and nothing ever ran those four statements against a table something pointed at. With foreign keys on, the `DROP TABLE` in the middle deletes the old table's rows first and fires every `ON DELETE CASCADE`, so following the advice emptied the child tables inside the version's own transaction ([ADR 123](./adr/123-a-migration-is-a-diff-against-a-snapshot.md)). The same review found the backfill hint telling an added required column to take a data step in front of it, which cannot fill a column that does not exist yet.

**A "must never" in a comment is kept only by whoever reads that comment.** `fallback_slot` said nothing may set it on an executor thread, `bulkhead.blocking` said the same, and `serveRequest`, one file over, set it on every request and left it set across the request's suspensions, so spawned work wrote into other requests; ADR 028's safety argument was true of the two places that knew. Reading the design pages against the code found it, and `setFallbackSlot` now refuses in Debug ([ADR 028](./adr/028-a-spawned-fiber-belongs-to-the-server.md)). The same reading found ADR 201's flush before a read held at the layer `Link` wraps and not at the TLS cleartext layer above it, where a keep-alive POST waited 75 s for its answer: **a guarantee installed by wrapping one reader covers that reader** ([ADR 201](./adr/201-a-response-is-flushed-before-the-connection-waits.md)).

**Where a comptime check runs decides whose error message a person sees.** Every registration method runs its own check so the reference trace starts at the user's line, not two frames inside `app.zig` ([ADR 026](./adr/026-the-rule-about-error-messages-is-held-by-a-build-step.md)); a check called one line too early gave Zig's "no field named 'to'" instead of nilo's sentence. A refusal that depends on the optimize mode is worse than none (`Str` is 40 bytes in Debug and 16 in release). A comptime budget belongs to whoever spends it: a quota raised in a callee raises the caller's whole evaluation and a smaller one never lowers it, so it is sized off the input, and generously ([ADR 126](./adr/126-a-check-pays-for-its-own-branches.md), [ADR 169](./adr/169-a-statement-pays-for-the-width-of-its-row.md)). **Every comptime loop over user fields or their names needs one, in every module**: `nilo_config` had none, and a Config of ten fields with 34-character names stopped with an error from inside `read.zig`; the test that proves a quota is a generated type big enough to fail without it, declared apart from the test so the test's own quota does not pay for it. **The audit of the other modules counted loops against quotas first and confirmed nothing, which is why it was not enough**: `job/job.zig` (14 loops, no quota) did fail, at twelve kinds with 40-character names, while `sql/db.zig` (23 loops, no quota) and `s3/sign.zig` (5, over nilo's own header list) never did, and the sites that did fail were ones a count would not rank, a name lookup in `sql/row.zig` that compared every name a byte at a time (the square of a Row's width, in every loop over it) and a flat `200_000` in `sql/shape.zig` that twenty aggregates spent. Compile the type through the public API at three to five times what a program reaches, and let the error say where.

**Put the rule in a build step, and write the error for the person reading it.** The build step supplies the `nilo: ` prefix, so a check that dies inside std can only be fixed or deleted, never recorded as passing; writing the first cases found two messages with no prefix in the file that documents the rule ([ADR 026](./adr/026-the-rule-about-error-messages-is-held-by-a-build-step.md)). A message that ends in a compiler rendering detail breaks when the rendering changes, and a message that sends the reader to a table to discover it was false is worse than none.

**Layering has holes a scan of `@import` cannot see.** A marker on a type is an import nothing can see: moving `sql.Uuid` down a layer would have moved a database's opinion with it ([ADR 038](./adr/038-a-module-sits-where-the-loop-puts-it.md)). A check that reads source has to survive source about source (doc comments quoting `@import`). Two modules built from one root file are two types, held by a `core.Str == nilo.Str` test. And an import named only from a `test` block is never analysed outside a test build, which is what made the layering affordable.

## Designing from the caller

**A rule keyed on a request header is tried against what `curl` and `fetch` send when nobody sets it.** A message route first refused any `Content-Type` but JSON's and protobuf's with a 415, and its comment said `curl -d` kept working; `curl -d` says `application/x-www-form-urlencoded` and a `fetch` of a string `text/plain`, so the two clients somebody tries a route with first were the two it refused, where a plain struct's route reads both as JSON. A message now reads as protobuf only under a protobuf label ([ADR 256](./adr/256-a-body-is-read-as-what-its-type-says.md)).

**Anything the framework emits comes back as input.** `/users/{id}`, printed by nilo's own OpenAPI document, was pasted in as 203 routes matching literal braces ([ADR 118](./adr/118-a-pattern-written-the-way-the-document-prints-it.md)). A wrong entry in a generated document is worse than a missing one; a failure stated in a function body cannot reach the document, so it belongs in the return type ([ADR 023](./adr/023-a-failure-mode-belongs-in-the-return-type.md)); and an artifact other people build against cannot need the thing running, which the OpenAPI file did, database included ([ADR 135](./adr/135-the-document-is-a-build-artefact.md)).

**A workaround that documents its reason stops looking like a workaround.** A checkbox field typed `Str` "because a ticked one arrives as `on`" was a complete bug report that read as a design note ([ADR 071](./adr/071-a-checkbox-is-a-bool-in-a-form-and-nowhere-else.md)). Ask why a field is not the type it obviously is. A workaround already written is a reason never to ask again, so report what nilo cannot spell before writing the patch for it.

**A feature that widens a type has to delete the sentence that said it may not**, and the place to look is above the new one, because a reader meets the restriction first, believes it, and writes the workaround. A declaration is findable from where somebody stands when they need it, not from where it belongs.

**Read a page end to end and ask whether it agrees with itself.** "Stay signed in for thirty days" and "a copied cookie still opens" were each true and described two different systems ([ADR 033](./adr/033-a-session-is-sealed-into-the-cookie.md)). A page's examples drift from each other before any one of them is wrong; compiling them against one world makes the drift a build failure ([ADR 068](./adr/068-the-guide-is-the-source-of-its-own-snippets.md)). The guide also holds the hardest real statements in the repository, so a new comptime check ships with `zig build snippets`, not after it: the first thing one catches is your own code.

**An escape hatch that costs nothing teaches nothing, and a narrow check makes the problem look solved.** A port wrote the untyped call five times in three modules while a typed one existed; a compile check caught one, and would have stopped anybody looking for the other four ([ADR 136](./adr/136-an-escape-hatch-that-costs-nothing-teaches-nothing.md)). A decision that makes a wrong shape cheaper is a cost of that decision. Check a fix against the instance reported, not the category it was filed under: an `expectEqual` helper could not have helped the `expectError` that was reported ([ADR 137](./adr/137-a-failed-assertion-that-can-be-read.md)).

**A feature list is not coverage; write the ordinary job.** Every piece of a list endpoint existed and the endpoint was still `db.raw`, because the pieces did not compose where a product assembles them ([ADR 149](./adr/149-a-filter-that-is-absent-is-not-a-filter-that-is-null.md)). A gap that looks like a missing feature is worth ten minutes as a missing call ([ADR 116](./adr/116-a-raw-parameter-is-converted-the-way-a-rows-is.md)). A sweep for what the framework makes you write finds what never stops a build, and is not a smaller finding for that. Two near misses in a row mean the shape is wrong, not that the third attempt needs to be bigger ([ADR 143](./adr/143-a-key-that-can-be-printed-and-a-key-that-can-be-made.md)).

**A shape tested with one service is not a shape.** `app.start` then `listen()` was tested with a `Db` alone, recommended in three guides, and hung the first program that ran a job worker beside the pool ([ADR 180](./adr/180-work-that-needs-the-services-runs-on-their-loop.md)). A feature only seen to compile is not seen to run: `spawn` shipped with no line of any program able to start one ([ADR 028](./adr/028-a-spawned-fiber-belongs-to-the-server.md)), and `http/live.zig` stands a real server up because of it.

**A design nobody attacked is as wide as its unexamined sentences.** The Allowance met all four axes and fell three ways to one outside review: a fail-open meant for strangers applied to your own traffic, `X-Forwarded-For` is not canonical the way the kernel is, and the index was a guessable twelve bits. The axes say a feature is affordable, not right, and ten minutes of asking somebody for the attack beat a day of building ([ADR 092](./adr/092-an-allowance-is-a-table-sized-while-compiling.md)). A claim that both paths cost the same has a hidden parameter (argon2's decoy ran at `Cost.default`), and `unreachable` on a callee's error is a promise about every precondition, not the ones that came to mind.

**Build the uncertain part standalone before designing around it.** `nilo_id` found that entropy and the wall clock had become IO in Zig 0.16 ([ADR 038](./adr/038-a-module-sits-where-the-loop-puts-it.md)); a spike put 65 lines of policy against 3,537 of `std.http.Client` before a fourth layer was argued, and that ADR carries its own weakest number ([ADR 061](./adr/061-a-fitting-borrows-the-loop.md)); `spike/cache_ring/` found a writer race and a mutex that takes an `Io` before a module existed. Spike the part whose answer is unknown, not the parts that merely have to be written.

**Most of what is said to need a second service does not.** A queue shared by several servers is `FOR UPDATE SKIP LOCKED` on the database they already share, a unique index is the leader election, and the order's own transaction is the outbox ([ADR 160](./adr/160-a-queue-is-a-table-in-the-database-you-already-have.md)). A win on the axis with numbers loses to a correctness failure with no symptom: replica routing and a query cache were refused although the cache was the largest single win available.

**Answer a header as asked, at the place that makes the answer free.** `100 Continue` sent where nilo commits to reading lets a 413 go out before 20 MB is uploaded, where sending it at the parse would not; the cheap version and the right version were the same size ([ADR 073](./adr/073-a-header-is-answered-as-asked-or-refused.md)). A weak ETag would have made every `If-Range` resume start again from zero. A cookie value carrying `;` is refused rather than escaped, because the grammar has no escaping to defend with.

**The name is cheap for us and not for them.** A rename touched 1,581 occurrences here for free, and it breaks every `pub const nilo_…` marker in users' structs, so names are settled before there are users. For the same reason a snapshot field rename costs a mirror struct until 1.0 while an added field is free.

**An option that reads nicer than a call can cost every program the module.** `.expect` on `Db.Opts` linked 17,296 bytes whether set or not, and `db.expecting(version)` moved the same binaries by 16 and 48. A fixed array in a function that already allocates is a ceiling that buys nothing ([ADR 170](./adr/170-a-document-names-every-shape-it-has.md)), and a value beside a borrow is a trap with a passing assertion in it ([ADR 171](./adr/171-an-answer-knows-which-request-it-was.md)). The same came back as a union variant: the connection loop's handover called an event stream's `run` directly, which linked the stream and the Room behind it into every server whether it streamed or not, 6,720 bytes on `hello`; carried as a pointer that only `eventsFrom` sets, the change cost 656 ([ADR 227](./adr/227-an-event-stream-fed-by-rooms-waits-where-a-connection-waits.md)).

**A metric can force an exemption the feature never needed.** The watchdog excused streams and WebSockets because it summed handler time over a connection, which has no bound on one that stays open; measuring the longest unparked stretch made the exemption disappear ([ADR 013](./adr/013-handlers-must-not-block-the-thread.md)).

**Handing something back to a queue you are still asking is not letting go of it.** A released row of an unknown kind was the most urgent due row again at once and was claimed 88,210 times, with `/health` timing out behind it. An enum column sorts by its name, so a priority is the integer behind the enum; and an equality column may precede a range column in a composite index while a second sort column may not (988 buffers and 7.9 ms against 7 and 0.065, [`job.md`](../bench/result/job.md)).

**Documentation written for a reader who starts at the top loses both readers who actually arrive.** A person scans the headings and an agent pulls the outline and greps, and at `d14780e` both hit the same walls: headings that were conclusions ("The value comes back as it was sent") rather than topics, 76% of prose hard-wrapped so a phrase split across lines was invisible to grep, a guide that linked the design pages 0 times, and a hand-kept list of reference headings already missing four. The fix was a shape every page shares, a map, and a build step, not better sentences ([ADR 236](./adr/236-a-doc-page-says-what-it-is-and-where-its-other-layers-are.md)).

**A refusal the client retries is not a delay, it is a cliff.** A gRPC call whose gzip copy did not fit the connection's budget was answered `UNAVAILABLE` so an OTLP exporter would retry rather than drop, and the ADR called the cost "a delay rather than a loss". Measured against a real Collector, each retry waited out a backoff of 5 seconds and up while the server sat idle, and at 16 MiB its queue grew by 329 batches in 30 seconds; holding the call until room came back took the same load with nothing queued. The prediction of how many batches a budget refuses was arithmetic from an assumed batch size until somebody ran the client ([ADR 220](./adr/220-grpc-is-served-over-h2c-behind-a-flag.md#what-the-budget-does-to-an-opentelemetry-collector), [`http.md`](../bench/result/http.md#what-waiting-for-room-buys-an-opentelemetry-collector)).

**A refusal that stands in for a missing safety net is paid by every caller, so price the net before keeping the refusal.** A bare `:memory:` was refused because a pool on it was several databases and because a reader in memory could write; every test then picked a shared-cache name by hand, and two that reused one shared rows (a downstream suite carried one name per test). A name private to the pool and `PRAGMA query_only` on each reader removed both reasons, each a line in `open`, and the refusal went with them ([ADR 065](./adr/065-one-writer-is-not-a-setting-it-is-the-database.md#tests-memory-is-one-database-for-the-pool-and-nobody-elses)).

## Zig and std traps

Each of these cost somebody an hour, usually in the wrong file. A version named in an item is where it was found; the rest held on 0.16 and 0.17 both.

- The test runner fails a run on any `std.log.err` whatever `log_level` says, and `std_options` in a tested file is never read, because the root of a test build is the runner.
- `std.testing.tmpDir(.{})` cannot be iterated, and iterating it panics with `BADF` inside `std.Io.Threaded`, which reads as an Engine bug. Pass `.{ .iterate = true }`, or take `nilo.testing.tmpDir()`, which always does and also hands back the path std leaves to be read off its source (ADR 250).
- `std.Io.Threaded` allows `cpu_count - 1` concurrent tasks; `io.async` past that runs inline on the caller.
- `std.Io.Mutex.lock` takes an `Io`, so a module with no event loop can only `tryLock` and spin; `std.Io.Condition` had no timed wait until 0.17 added `waitTimeout`; `std.crypto.random` and `milliTimestamp` are gone behind an `Io`.
- A cancellation crossing `std.Io.Reader` arrives as `error.ReadFailed`, its cause in a field; ask the bound whether it fired, which also spends the pending cancellation. zio delivers a cancel once, so a `catch {}` around a read or a flush spends it and the next wait parks fresh: a stop waited on every idle keep-alive connection for twice `idle_timeout_ms`, through `waitForRequest` swallowing one and `Link.settle` another. zio never clears that field either, so it answers for the operations since the limit was last armed only once the arming clears it (`waitForRequest` in [`http/serve.zig`](../http/serve.zig), `Clocks` in [`http/engine/zio.zig`](../http/engine/zio.zig)).
- On 0.16 `std.Io.net.UnixAddress.ConnectError` has no `ConnectionRefused`, so the refusal a probe is looking for is `error.Unexpected` and a stack trace printed before the error returns; 0.17 added it.
- `std.json` over a slice returns strings into the input unless `.allocate = .alloc_always`, and dispatches parsing on `hasFn(T, "jsonParse")`, which nothing can add to somebody else's type.
- `std.http.receiveHead` frames a 204 as read-to-EOF although its comment says otherwise ([ADR 176](./adr/176-an-answer-with-no-body-ends-at-its-head.md)); `Request.deinit` drains only from `.received_head`; a HEAD's `content-length` is a claim about a body that is not there.
- `std.compress.flate.Decompress` asks for room before every block, the empty final block of a flush-then-close writer included; `Compress.init` uses 99 KB of stack.
- `std.zon` fills a missing field from its default; `fromSliceAlloc` with a null `diag` leaks on a failing parse.
- `std.log.default_level` is `.info` in all three release modes; `std.debug.runtime_safety` tells ReleaseSafe from ReleaseFast.
- `std.Io.Limit` is `usize`-backed, so a 32-bit build clamps a file over 4 GB.
- `Dir.readFileAlloc` on a file in `/proc` returns nothing, because it reads to the size `stat` reports and `/proc` reports 0; `File.readerStreaming` reads it to its end. The test it broke failed with a mapping not found, which reads as the code under test being wrong.
- A generic is memoised on the type it returns, so a comptime parameter the body never mentions makes no new type. A struct declared inside a generic function is one type for every instantiation that captures the same values, so a `var` in it that names none of them is one for the whole program: the first-run flag of `db.raw` was, and only the first raw statement to run was ever checked ([ADR 233](./adr/233-a-raw-statement-is-held-against-its-row-the-first-time-it-runs.md)).
- `&.{ "a", "b" }` is a pointer to an anonymous tuple struct, not to an array; `&.{ … }` holding runtime values lives in the function's frame.
- `{d:0>4}` on a signed integer writes the sign.
- `@setEvalBranchQuota` in a callee raises the caller's whole evaluation, and a smaller value later never lowers it.
- `@typeName` spells a type from its own module's root, so an application's `room.Room` reads exactly like nilo's.
- A global in `build.zig` is one variable for every instance of the package in a build runner, because the runner compiles the file once: a dependent asking for nilo in Debug and in `ReleaseSafe` runs `build` twice into the same globals, and a fixed-size memo there overflowed on the second. Key such state by the `*std.Build` and grow it from `b.allocator`; `zig build two-modes` configures that dependent.
- `b.lazyDependency` is a request, not a conditional ([ADR 066](./adr/066-a-lazy-dependency-is-a-request.md)); measuring what a dependent downloads means clearing both `zig-pkg/` and the global cache's `p/`.
- A build step that succeeds is cached and one that fails is not, which is why the refusals are re-analysed every run and the snippets are nearly free.
- A string literal is writable under the x86_64 self-hosted backend and read-only under LLVM, so a test that hands `std.Io.Reader.fixed` a literal and the code under test writes into the buffer passes in Linux Debug and bus-errors on a Mac. The first macOS CI run found three, all a WebSocket unmasking in place; forcing `testBackend` to LLVM for Debug reproduces it on Linux.
- `zig build test --fuzz` does not compile on 0.16; the fetcher does not peel an annotated tag, on 0.17 as on 0.16; on aarch64 the default backend is LLVM in both modes.
- On 0.17 `@hasDecl` answers only for `pub` declarations, and a `nilo_*` hook or a Wire's declaration written without `pub`, which 0.16 refused with "not marked pub", is skipped without a word. Every probe in nilo was audited at the port; a user's is the one nothing can catch.
- On 0.17 `std.heap.ArenaAllocator` grows its last block in place when the allocator under it can, so a test that counts allocations through `std.testing.allocator` moves with that allocator's bucket layout (4 or 6 trips for one connection). Count through a `FixedBufferAllocator`, or an allocator that never grows a block in place, as `sql/db.zig`'s `Pages` does.
- On 0.17 `build.zig` cannot define a step with a function of its own, so a check that reads the tree is a program `build.zig` runs (`checks/`); and a file or environment variable read while configuring is outside the cached configuration's key unless declared with `b.dependOn…` or `poisonCache()`, which is how a changed `DATABASE_URL` would have been ignored.
- A dependency's "builds with Zig 0.17" is a claim about the file it changed. lalinsky's pg.zig `7b4609c` said it of its tls.zig, and the driver, its metrics.zig and its xsync each failed on 0.17; zio's newest tag, v0.19.1, shipped helpers "for Zig 0.16/0.17" and still failed on 0.17's `Io`, which only `main` implemented. Compile the dependency, not its commit message.
- `std.simd.suggestVectorLength` is the register width, not the unroll factor a loop wants (128 measured 30% faster than the suggested 64).
- SQLite: a URI's `mode=` beats the flags given to `sqlite3_open_v2`; `journal_mode = WAL` in memory answers `memory` instead of failing; `$2` before `$1` is numbered by first appearance.
- Postgres: an unquoted identifier folds to lower case; a parameter is typed at its first use, so `$1 IS NULL` first cannot be typed; a `LIMIT $n` bound as a parameter is planned on every call.
